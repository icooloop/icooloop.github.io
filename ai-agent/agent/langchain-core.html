LangChain Core：消息、Runnable 与 LCEL ​

上一页用原生 Python 拆开了 Agent 的 Observe-Decide-Act 循环。本页开始使用 LangChain，但暂时不创建 Agent。我们先掌握框架中更基础、也更可复用的一层：数据对象与 Runnable 运行协议。

学完本页，你应该能够：

  • 区分 Message、Document、PromptValue 和模型输出；
  • 用 RunnableSequence、RunnableParallel、RunnablePassthrough、RunnableLambda 与 RunnableBranch 组合处理过程；
  • 正确选择 invoke、ainvoke、batch、abatch、stream 与 astream；
  • 用 RunnableConfig 传递回调、标签、元数据与并发限制；
  • 识别静态类型、Schema 展示与运行时校验之间的边界；
  • 使用 Fake Model 在没有 API Key、没有网络的环境中测试链。

本页配套源码是 examples/agent-development/langchain_core_pipeline.py。正文会写出关键实现和一份完整程序；源码文件只是方便运行，不替代教学内容。

四种角色承担不同职责：

  • SystemMessage：应用规则、角色与长期约束；
  • HumanMessage：用户输入；
  • AIMessage：模型回复，也可能包含 tool_calls；

3.2 content 不应被假定永远是字符串 ​

纯文本示例中，message.content 通常是 str；多模态或供应商标准化内容中，它也可能由多个内容块组成。业务代码若只支持文本，应在边界明确拒绝其他形态，而不是直接执行：

python
# 脆弱：content 不是 str 时会失败。
text = message.content.strip()
1
2

可以先建立自己的窄边界：

python
from langchain_core.messages import BaseMessage


def require_text(message: BaseMessage) -> str:
    if not isinstance(message.content, str):
        raise TypeError("this pipeline accepts text messages only")
    text = message.content.strip()
    if not text:
        raise ValueError("message text must not be blank")
    return text

3.3 消息还有哪些字段 ​

消息除了 content，还可能携带：

  • id：供应商或应用分配的消息 ID；
  • name：可选名称；
  • additional_kwargs：供应商特有的附加信息；
  • response_metadata：停止原因、模型标识等响应元数据；
  • usage_metadata：输入、输出及总 Token 用量；
  • tool_calls：标准化后的工具调用。

这些元数据适合观察和计费，但不要把供应商特有字段当成跨模型稳定协议。跨模型业务逻辑应依赖 LangChain 已标准化的字段，或在自己的适配层统一格式。

7. Runnable：统一的运行协议 ​

Runnable 可以近似理解为带有统一执行方法的“可组合函数”：

text
Runnable[Input, Output]
1

核心方法包括：

单个/多个同步异步流式
单个输入invokeainvokestream / astream
多个输入batchabatch通常由调用方组织

Prompt、Model、Output Parser 本身就是 Runnable；普通 Python 函数可以用 RunnableLambda 接入这个协议。

python
from langchain_core.runnables import RunnableLambda

normalize = RunnableLambda(lambda text: " ".join(text.split()))
print(normalize.invoke("  hello   world  "))

不要因为函数被包装成 Runnable，就认为它自动获得了超时、重试、运行时类型校验或真正的流式能力。Runnable 统一的是调用和组合协议；具体能力仍取决于组件实现与外层配置。

9. RunnableParallel：同一个输入产生多个字段 ​

    characters=RunnableLambda(lambda text: len(text)),
    has_number=RunnableLambda(lambda text: any(ch.isdigit() for ch in text)),
)

11. RunnableLambda：接入小而明确的 Python 逻辑 ​

适合放进 RunnableLambda 的逻辑包括：

  • 输入校验；
  • 规范化字符串；
  • 格式化 Document；
  • 计算派生字段；
  • 将一个内部数据结构映射为另一个。
python
def normalize_question(data: dict[str, object]) -> str:
    question = data["question"]
    if not isinstance(question, str) or not question.strip():
        raise ValueError("question must be a non-blank string")
    return " ".join(question.split())


normalize_runnable = RunnableLambda(normalize_question)

不要把一个完整业务服务全塞进巨大 Lambda。复杂逻辑先写成有名称、可单测的普通函数，再用 RunnableLambda(function) 接入。

还要注意流式边界：普通 RunnableLambda 通常要等输入完整到达并完成函数调用，才产生输出。如果把一个“收齐全文再解析”的 Lambda 放在模型之后，模型前面的 Token 流可能在这里被缓冲。

12. RunnableBranch：有限且可测试的路由 ​

RunnableBranch 按顺序测试条件，执行第一个命中的分支；最后一个参数是默认分支：

python
from langchain_core.runnables import RunnableBranch


def is_order_question(data: dict[str, object]) -> bool:
    question = str(data["question"]).lower()
    return "order" in question or any(ch.isdigit() for ch in question)


router = RunnableBranch(
    (
        is_order_question,
        RunnableLambda(lambda data: {"route": "order", "input": data}),
    ),
    RunnableLambda(lambda data: {"route": "knowledge", "input": data}),
)

print(router.invoke({"question": "Where is order A1024?"})["route"])
print(router.invoke({"question": "How long is refund review?"})["route"])

from typing import Any
from uuid import UUID

from langchain_core.callbacks import BaseCallbackHandler


class ErrorRecorder(BaseCallbackHandler):
    def __init__(self) -> None:
        self.errors: list[dict[str, str]] = []

    def on_chain_error(
        self,
        error: BaseException,
        *,
        run_id: UUID,
        parent_run_id: UUID | None = None,
        **kwargs: Any,
    ) -> None:
        self.errors.append(

                "run_id": str(run_id),
                "parent_run_id": str(parent_run_id) if parent_run_id else "",
                "error_type": type(error).__name__,
            }
        )


recorder = ErrorRecorder()

try:
    RunnableLambda(lambda _: 1 / 0).invoke(
        None,
        config={
            "callbacks": [recorder],
            "tags": ["tutorial", "expected-failure"],
            "metadata": {"case": "division-by-zero"},
        },
    )
except ZeroDivisionError:
    pass

print(recorder.errors[0]["error_type"])

17. 完整离线程序 ​

下面的程序完整展示：Document、输入校验、Passthrough、Parallel、Prompt、Fake Model、Parser、Branch、RunnableConfig 与异步调用。它不需要 API Key。

将代码保存为 core_offline_demo.py，或直接对照项目中的 examples/agent-development/langchain_core_pipeline.py：

python
from __future__ import annotations

import asyncio
from typing import Any, Literal, TypedDict

from langchain_core.documents import Document
from langchain_core.language_models.fake_chat_models import FakeListChatModel
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.prompt_values import ChatPromptValue
from langchain_core.runnables import (
    RunnableBranch,
    RunnableConfig,
    RunnableLambda,
    RunnableParallel,
    RunnablePassthrough,
)


class PipelineInput(TypedDict):
    question: str
    documents: list[Document]


class RouteResult(TypedDict):
    route: Literal["order", "knowledge"]
    answer: str


def validate_input(data: PipelineInput) -> PipelineInput:
    question = data.get("question")
    documents = data.get("documents")

    if not isinstance(question, str) or not question.strip():
        raise ValueError("question must be a non-blank string")
    if not isinstance(documents, list):
        raise TypeError("documents must be a list")

    for index, document in enumerate(documents):
        if not isinstance(document, Document):
            raise TypeError(f"documents[{index}] must be a Document")
        source = document.metadata.get("source")
        if not isinstance(source, str) or not source.strip():
            raise ValueError(f"documents[{index}] requires source metadata")

    return data


def normalize_question(data: PipelineInput) -> str:
    return " ".join(data["question"].split())


def format_context(data: PipelineInput) -> str:
    if not data["documents"]:
        return "[no authorized evidence]"
    return "\n".join(
        f"[{doc.metadata['source']}] {doc.page_content}"
        for doc in data["documents"]
    )


def report_config(data: PipelineInput, config: RunnableConfig) -> PipelineInput:
    metadata = config.get("metadata", {})
    print(f"pipeline_version={metadata.get('pipeline_version', 'unknown')}")
    return data


validate = RunnableLambda(validate_input)
observe_config = RunnableLambda(report_config)

prepared_input = RunnablePassthrough.assign(
    normalized_question=RunnableLambda(normalize_question),
    formatted_context=RunnableLambda(format_context),
)

prompt_input = RunnableParallel(
    question=RunnableLambda(lambda data: data["normalized_question"]),
    context=RunnableLambda(lambda data: data["formatted_context"]),
    document_count=RunnableLambda(lambda data: len(data["documents"])),
)

prompt = ChatPromptTemplate.from_messages(
    [
        (
            "system",
            "Answer only from the supplied authorized context. "
            "If evidence is missing, say that you cannot confirm.",
        ),
        (
            "human",
            "Question: {question}\n"
            "Authorized documents: {document_count}\n\n"
            "Context:\n{context}",
        ),
    ]
)

# Fake Model 返回固定答案，用来验证链，而不是模拟真实推理质量。
fake_model = FakeListChatModel(
    responses=["Refund review normally takes three business days."]
)

knowledge_chain = (
    prepared_input
    | prompt_input
    | prompt
    | fake_model
    | StrOutputParser()
)


def is_order_question(data: PipelineInput) -> bool:
    normalized = normalize_question(data).lower()
    return "order" in normalized or any(char.isdigit() for char in normalized)


order_route = RunnableLambda(
    lambda data: RouteResult(
        route="order",
        answer=f"Send '{normalize_question(data)}' to the order service.",
    )
)

knowledge_route = knowledge_chain | RunnableLambda(
    lambda answer: RouteResult(route="knowledge", answer=answer)
)

pipeline = (
    validate
    | observe_config
    | RunnableBranch(
        (is_order_question, order_route),
        knowledge_route,
    )
).with_types(input_type=PipelineInput, output_type=RouteResult)


def sample_input() -> PipelineInput:
    return {
        "question": "  How long does refund review take?  ",
        "documents": [
            Document(
                page_content="Refund review normally takes three business days.",
                metadata={"source": "refund-policy#review"},
            )
        ],
    }


async def main() -> None:
    config: RunnableConfig = {
        "run_name": "offline-core-demo",
        "tags": ["tutorial", "offline"],
        "metadata": {"pipeline_version": "v1"},
    }

    knowledge = await pipeline.ainvoke(sample_input(), config=config)
    print(knowledge)

    order = sample_input()
    order["question"] = "Where is order A1024?"
    print(pipeline.invoke(order, config=config))

    # Prompt-only 链用于检查模型真正看到的消息。
    prompt_preview = (
        validate | prepared_input | prompt_input | prompt
    ).with_types(output_type=ChatPromptValue)
    value = prompt_preview.invoke(sample_input())
    for message in value.to_messages():
        print(f"{message.type}: {message.content}")


if __name__ == "__main__":
    asyncio.run(main())

20. 常见失败路径 ​

20.1 导入真实模型失败 ​

text
ModuleNotFoundError: No module named 'langchain_xxx'
1

原因通常是只安装了 langchain-core。Core 定义模型协议，但真实供应商客户端位于独立集成包。根据项目锁定文件安装对应包，不要凭旧教程猜包名和版本。

20.2 Prompt 缺少变量 ​

text
KeyError: Input to ChatPromptTemplate is missing variables ...
1

检查 Prompt 声明的变量集合和上一步输出字典的键。不要用 .get(..., "") 隐藏关键上下文缺失。

20.3 相邻 Runnable 的形状不匹配 ​

text
TypeError: string indices must be integers
1

常见原因是上一步输出字符串，下一步却按字典读取 data["question"]。把每一步的 Input -> Output 写出来并单独 invoke()。

20.4 误以为 with_types() 会拒绝坏输入 ​

它主要声明类型和 Schema，不替代运行时校验。对 HTTP 请求、模型输出、Document metadata 等不可信数据使用 Pydantic或显式校验 Runnable。

20.5 stream() 只有一个块 ​

这不一定是故障。Prompt、普通 Lambda 和某些模型本来就只产生完整对象；序列中的非流式组件也可能缓冲。用最小链分别测试每一段的块类型与块数。

20.6 Batch 压垮下游 ​

.batch() 和 .abatch() 可能并发执行。未设置 max_concurrency 时，大批输入可能触发限流或耗尽连接。根据真实下游容量限制并发，并为可重试错误设置有限退避。

20.7 回调泄漏敏感内容 ​

直接记录完整输入、Prompt、Document 和模型响应可能泄漏个人信息或商业数据。默认只记录 ID、类型、耗时、版本和脱敏指标；正文采样必须有明确权限与保留策略。

21. 练习 ​

练习 1：增加无证据分支 ​

在完整程序中加入条件：documents 为空时不调用模型，直接返回：

text
I cannot confirm from authorized evidence.
1

测试 Fake Model 没有被调用。提示：可以给 Fake Model 设置只够正常路径使用的响应数量，或用自定义回调计数。

练习 2：并行生成 Prompt 字段 ​

给 prompt_input 增加：

  • sources：逗号连接的来源；
  • latest_update：元数据中的最新日期；
  • has_evidence：是否有文档。

为零份、一份和多份 Document 写测试。

练习 3：路由重叠 ​

新增“退款订单”分支，并设计输入：

text
Can order A1024 be refunded?
1

明确它应该命中哪个分支，调整条件顺序，并用测试锁定这个决定。

练习 4：六种执行方式 ​

对一个固定 Fake Model 链分别调用 invoke、ainvoke、batch、abatch、stream 和 astream，记录：

  • 返回类型；
  • 结果顺序；
  • 流的块数和每块类型；
  • 一条输入失败时的行为。

练习 5：配置与回调 ​

实现一个 Callback，记录每次链运行的错误类型和耗时。要求：

  • 通过 RunnableConfig 注入；
  • 日志包含 run_id 和 pipeline_version；
  • 日志不包含问题全文或 Document 正文；
  • 回调失败不能改变业务答案。

练习 6：真正的运行时边界 ​

用 Pydantic 改写完整程序的 validate_input，拒绝：

  • 多余字段；
  • 空白问题；
  • 非 Document 元素；
  • 缺少 source 的 Document。

证明 with_types() 和运行时校验承担不同职责。
