LangChain 工具系统 ​

Tool Calling 不是“模型执行了一个 Python 函数”。模型只能生成一份调用建议；应用负责校验参数、检查权限、决定是否需要人工审批、执行代码，再把结果作为 ToolMessage 交回模型。

一个完整回合是：

text
应用向模型提供工具 Schema
  -> 模型返回 AIMessage.tool_calls
  -> 应用做名称、参数、权限与审批检查
  -> 应用执行工具
  -> 应用返回匹配 tool_call_id 的 ToolMessage
  -> 模型根据工具结果生成最终 AIMessage

本章将完成：

  • 使用 @tool 和 StructuredTool 定义工具；
  • 使用 Pydantic 2.13.4 建立严格参数 Schema；
  • 理解 bind_tools() 只把工具定义绑定给模型，并不执行工具；
  • 正确处理 AIMessage.tool_calls 和 ToolMessage.tool_call_id；
  • 实现离线、可测试的完整 Tool Calling 回合；
  • 安全处理并行工具、动态工具集和未知工具；
  • 使用 InjectedToolArg、ToolRuntime 和 Store 隐藏可信运行时数据；
  • 设计错误、超时、幂等、权限和人工审批边界。

2. 工具的四份契约 ​

一个生产工具至少有四份契约：

契约回答的问题由谁执行
描述契约什么时候应该调用？模型读取，开发者维护
参数契约可以提交哪些字段和类型？Pydantic / JSON Schema
权限契约当前主体是否允许执行？应用与领域服务
结果契约成功、失败和 artifact 如何返回？工具执行器

JSON Schema 只解决参数结构，不会自动解决授权。例如 order_id 格式正确，不代表当前用户有权查看该订单。

3. 第一个 @tool ​

项目的 examples/agent-development/tools.py 使用了下面的完整模式：

python
from __future__ import annotations

from langchain_core.tools import tool
from pydantic import BaseModel, ConfigDict, Field


class OrderArguments(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    order_id: str = Field(
        pattern=r"^A\d{4}$",
        description="Order identifier such as A1024.",
    )


@tool(args_schema=OrderArguments)
def get_order(order_id: str) -> dict[str, str]:
    """Read one order status. This tool has no side effects."""
    orders = {
        "A1024": "shipped",
        "A2048": "processing",
    }
    return {
        "order_id": order_id,
        "status": orders.get(order_id, "not_found"),
    }


print(get_order.name)
print(get_order.description)
print(get_order.args)
print(get_order.invoke({"order_id": "A1024"}))

@tool 把普通函数转换为 BaseTool。函数名默认成为工具名，docstring 默认成为工具描述，类型注解或显式 args_schema 成为参数 Schema。

工具描述应该说明：

  • 它读取还是修改数据；
  • 什么时候应该使用；
  • 不应该用来做什么；
  • 重要前置条件；
  • 结果的主要含义。

不要在描述中写数据库密码、内部访问令牌或租户密钥。描述会发送给模型。

对重要工具，显式 Pydantic Schema 更可靠：

python
from pydantic import BaseModel, ConfigDict, Field, model_validator


class SearchArguments(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    query: str = Field(min_length=2, max_length=120)
    limit: int = Field(default=3, ge=1, le=10)
    category: str | None = Field(default=None, max_length=40)

    @model_validator(mode="after")
    def reject_blank_category(self) -> "SearchArguments":
        if self.category is not None and not self.category.strip():
            raise ValueError("category must be non-blank when provided")
        return self


@tool(args_schema=SearchArguments)
def search_authorized_kb(
    query: str,
    limit: int = 3,
    category: str | None = None,
) -> list[dict[str, str]]:
    """Search documents already authorized for the current request."""
    suffix = "all" if category is None else category
    return [
        {
            "source": f"policy-{index}",
            "text": f"{query}:{suffix}",
        }
        for index in range(limit)
    ]

5. StructuredTool ​

当工具需要分别提供同步与异步实现、动态创建或显式控制 metadata 时，可以使用 StructuredTool.from_function()：

python
import asyncio

from langchain_core.tools import StructuredTool


def search_sync(query: str, limit: int = 3) -> list[str]:
    return [query] * limit


async def search_async(query: str, limit: int = 3) -> list[str]:
    await asyncio.sleep(0)
    return [query] * limit


search_tool = StructuredTool.from_function(
    func=search_sync,
    coroutine=search_async,
    name="search_kb",
    description="Search the authorized knowledge base.",
)

print(search_tool.invoke({"query": "refund", "limit": 2}))
print(
    asyncio.run(
        search_tool.ainvoke({"query": "refund", "limit": 2})
    )
)

6. 工具结果：content 与 artifact ​

默认 response_format="content"，返回值会成为 ToolMessage.content。如果模型只需要简短摘要，而应用还要保留完整结构或二进制引用，可以返回 (content, artifact)：

python
from langchain_core.tools import tool


@tool(response_format="content_and_artifact")
def retrieve_policy(query: str) -> tuple[str, dict[str, object]]:
    """Retrieve authorized policy evidence for a focused query."""
    documents = [
        {
            "source": "refund-policy#review",
            "text": "Refund review normally takes three business days.",
        }
    ]
    content = "Found 1 authorized policy excerpt."
    artifact = {"query": query, "documents": documents}
    return content, artifact


call = {
    "type": "tool_call",
    "id": "call_policy_1",
    "name": "retrieve_policy",
    "args": {"query": "refund review time"},
}

message = retrieve_policy.invoke(call)

print(message.content)
print(message.tool_call_id)
print(message.artifact["documents"][0]["source"])

直接使用普通参数字典调用时，content_and_artifact 工具只返回 content；以包含 id 的 ToolCall 调用时，LangChain 才能构造带 artifact 的 ToolMessage。

7. bind_tools() 只绑定，不执行 ​

模型绑定工具：

python
# model 必须是实现 bind_tools() 的具体 Chat Model 集成。
model_with_tools = model.bind_tools([get_order, search_authorized_kb])
ai_message = model_with_tools.invoke("查询订单 A1024 的状态。")
1
2
3

这一操作通常把工具的名称、描述和 JSON Schema 转换成供应商请求参数。它不会：

  • 执行工具；
  • 自动批准副作用；
  • 证明参数合法；
  • 证明当前用户有权限；
  • 自动把结果发送回模型。

BaseChatModel.bind_tools() 是抽象能力。FakeListChatModel 和 FakeMessagesListChatModel 不实现它，直接调用会抛出 NotImplementedError。本章后面会使用一个很小的 ScriptedToolModel：它离线返回预设 AIMessage，并在 bind_tools() 中保存转换后的 Schema，从而测试完整应用控制流。

真实模型的 tool_choice、强制调用、禁止调用和并行调用参数属于供应商集成的版本相关能力。不要假定相同字符串在所有模型上具有相同含义。

执行前必须检查：

  1. 工具名是否在本轮允许集合；
  2. 调用 ID 是否存在且本轮唯一；

invalid_tool_calls 表示集成层无法规范化的调用，不能把它们当作普通文本忽略。应记录安全的错误摘要，决定反馈模型、有限重试或转人工。

10. 完整离线 Tool Calling 回合 ​

下面是可直接运行的完整程序。它包含严格 Schema、bind_tools()、标准 tool call、工具分发、ToolMessage 回传和最终模型回复，不需要真实供应商。

python
from __future__ import annotations

from collections.abc import Sequence
from typing import Any

from langchain_core.language_models.chat_models import BaseChatModel
from langchain_core.messages import (
    AIMessage,
    BaseMessage,
    HumanMessage,
    SystemMessage,
    ToolMessage,
)
from langchain_core.outputs import ChatGeneration, ChatResult
from langchain_core.tools import BaseTool, tool
from langchain_core.utils.function_calling import convert_to_openai_tool
from pydantic import BaseModel, ConfigDict, Field


class OrderArguments(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    order_id: str = Field(pattern=r"^A\d{4}$")


@tool(args_schema=OrderArguments)
def get_order(order_id: str) -> dict[str, str]:
    """Read one order status. This tool has no side effects."""
    orders = {"A1024": "shipped", "A2048": "processing"}
    return {
        "order_id": order_id,
        "status": orders.get(order_id, "not_found"),
    }


class ScriptedToolModel(BaseChatModel):
    """Deterministic offline model with a real bind_tools contract."""

    responses: list[AIMessage]
    index: int = 0
    bound_tool_schemas: list[dict[str, Any]] = Field(default_factory=list)

    @property
    def _llm_type(self) -> str:
        return "scripted-tool-model"

    def _generate(
        self,
        messages: list[BaseMessage],
        stop: list[str] | None = None,
        run_manager: Any = None,
        **kwargs: Any,
    ) -> ChatResult:
        if self.index >= len(self.responses):
            raise RuntimeError("scripted model has no response left")
        response = self.responses[self.index]
        self.index += 1
        return ChatResult(
            generations=[ChatGeneration(message=response)]
        )

    def bind_tools(
        self,
        tools: Sequence[dict[str, Any] | type | BaseTool],
        *,
        tool_choice: str | None = None,
        **kwargs: Any,
    ) -> "ScriptedToolModel":
        self.bound_tool_schemas = [
            convert_to_openai_tool(item) for item in tools
        ]
        return self


def execute_tool_calls(
    message: AIMessage,
    allowed_tools: dict[str, BaseTool],
) -> list[ToolMessage]:
    results: list[ToolMessage] = []
    seen_ids: set[str] = set()

    for call in message.tool_calls:
        call_id = call["id"]
        name = call["name"]

        if not call_id or call_id in seen_ids:
            raise ValueError("tool call ids must be present and unique")
        seen_ids.add(call_id)

        selected = allowed_tools.get(name)
        if selected is None:
            results.append(
                ToolMessage(
                    content=f"Unknown or unauthorized tool: {name}",
                    name=name,
                    tool_call_id=call_id,
                    status="error",
                )
            )
            continue

        result = selected.invoke(call)
        if not isinstance(result, ToolMessage):
            raise TypeError("a ToolCall invocation must return ToolMessage")
        results.append(result)

    return results


model = ScriptedToolModel(
    responses=[
        AIMessage(
            content="",
            tool_calls=[
                {
                    "name": "get_order",
                    "args": {"order_id": "A1024"},
                    "id": "call_order_1",
                    "type": "tool_call",
                }
            ],
        ),
        AIMessage(content="订单 A1024 已发货。"),
    ]
)

tools = [get_order]
tools_by_name = {item.name: item for item in tools}
model_with_tools = model.bind_tools(tools)

messages: list[BaseMessage] = [
    SystemMessage(content="查询订单后再回答，不得猜测状态。"),
    HumanMessage(content="订单 A1024 现在怎么样？"),
]

# 第一次模型调用：提出工具调用。
assistant_request = model_with_tools.invoke(messages)
messages.append(assistant_request)

# 应用执行工具，并把匹配 ID 的 ToolMessage 追加到历史。
tool_messages = execute_tool_calls(assistant_request, tools_by_name)
messages.extend(tool_messages)

# 第二次模型调用：根据工具结果形成最终回复。
final_answer = model_with_tools.invoke(messages)
messages.append(final_answer)

assert model.bound_tool_schemas[0]["function"]["name"] == "get_order"
assert tool_messages[0].tool_call_id == "call_order_1"
assert tool_messages[0].status == "success"
assert final_answer.content == "订单 A1024 已发货。"

for message in messages:
    print(message.type, message.content)

11. 并行工具调用 ​

一次 AIMessage 可以包含多个 tool calls。互不依赖、无副作用的读取工具可以并行：

python
import asyncio

from langchain_core.tools import BaseTool


async def execute_parallel_reads(
    message: AIMessage,
    allowed_tools: dict[str, BaseTool],
) -> list[ToolMessage]:
    calls = message.tool_calls

    if len({call["id"] for call in calls}) != len(calls):
        raise ValueError("duplicate tool call id")

    selected: list[tuple[BaseTool, dict[str, Any]]] = []
    for call in calls:
        tool_item = allowed_tools.get(call["name"])
        if tool_item is None:
            raise PermissionError(
                f"tool is not allowed: {call['name']}"
            )
        selected.append((tool_item, call))

    raw_results = await asyncio.gather(
        *(tool_item.ainvoke(call) for tool_item, call in selected),
        return_exceptions=True,
    )

    messages: list[ToolMessage] = []
    for (_, call), result in zip(selected, raw_results, strict=True):
        if isinstance(result, Exception):
            messages.append(
                ToolMessage(
                    content=f"Tool failed: {type(result).__name__}",
                    name=call["name"],
                    tool_call_id=call["id"],
                    status="error",
                )
            )
        elif isinstance(result, ToolMessage):
            messages.append(result)
        else:

16. 超时、取消与重试 ​

异步执行器可为每个调用设置上限：

python
import asyncio

from langchain_core.messages import ToolMessage
from langchain_core.tools import BaseTool


async def invoke_with_timeout(
    selected: BaseTool,
    call: dict[str, Any],
    timeout_seconds: float,
) -> ToolMessage:
    try:
        result = await asyncio.wait_for(
            selected.ainvoke(call),
            timeout=timeout_seconds,
        )
    except TimeoutError:
        return ToolMessage(
            content="Tool timed out before a confirmed result.",
            name=call["name"],
            tool_call_id=call["id"],
            status="error",
        )

    if not isinstance(result, ToolMessage):
        raise TypeError("expected ToolMessage")
    return result

重试策略：

情况策略
临时网络错误、限流指数退避、随机抖动、总次数上限
参数校验失败向模型反馈精简 Schema 错误，有限重试

未知执行结果使用幂等键查询，不能盲目再执行
程序缺陷失败并告警，不伪装成业务错误

17. 幂等设计 ​

模型、网络客户端和编排器都可能重试。写工具必须让同一个业务操作重复提交时得到同一结果，而不是重复产生副作用。

python
from collections.abc import Callable
from threading import Lock
from typing import TypeVar


T = TypeVar("T")


class IdempotencyLedger:
    def __init__(self) -> None:
        self._lock = Lock()
        self._results: dict[str, object] = {}

    def run_once(self, key: str, operation: Callable[[], T]) -> T:
        with self._lock:
            if key in self._results:
                return self._results[key]  # type: ignore[return-value]

            result = operation()
            self._results[key] = result
            return result

from typing import Any


SENSITIVE_TOOLS = {

22. 常见错误 ​

把 bind_tools() 当成执行器 ​

绑定只向模型展示工具。没有应用循环或 Agent/ToolNode，tool call 不会自动执行。

直接执行模型提供的函数名 ​

python
# 严重反例：绝不能 eval 或 globals 动态执行模型文本。
result = globals()[call["name"]](**call["args"])
1
2

必须使用本轮明确允许的 dict[str, BaseTool] 白名单。

把租户和权限放进模型参数 ​

模型可被 Prompt Injection 影响。可信上下文应由已认证请求通过 InjectedToolArg 或 ToolRuntime 注入。

丢失 tool_call_id ​

没有正确 ID，模型无法把结果与并行调用关联，供应商还可能拒绝消息序列。

捕获所有异常后返回“成功” ​

这会让模型基于错误数据继续行动。失败应使用 status="error" 或向上抛出，并区分预期业务错误与程序缺陷。

写工具没有幂等性 ​

模型重试或网络超时会重复产生退款、邮件和库存变更。副作用工具必须有业务幂等键与真实状态核对。

动态工具集替代最终授权 ​

减少可见工具只是第一层。执行器和领域服务仍必须检查 scope 与对象级权限。

并行执行所有调用 ​

调用可能相互依赖或修改同一对象。只有独立、只读且受并发预算约束的调用才适合并行。

23. 练习 ​

练习一：严格查询工具 ​

为 get_order 增加可选字段 include_events，要求严格布尔类型；拒绝额外字段和非法订单号。测试普通 dict 调用和完整 ToolCall 调用。

练习二：content 与 artifact ​

编写检索工具，向模型返回三条精简引用，把完整文档放入 artifact。断言 artifact 不会自动拼入 ToolMessage.content。

练习三：并行读取 ​

让 Fake AIMessage 一次调用订单查询与政策查询。并行执行，故意让一个失败，确认每个 ToolMessage 仍保留正确 ID 和状态。

练习四：动态最小工具集 ​

根据 orders:read、refunds:draft 和 refunds:submit 三个 scope 选择工具。证明仅绑定只读工具时，执行器仍会拒绝伪造的 submit_refund 调用。

练习五：Runtime 与 Store ​

使用 ToolRuntime[AppContext] 注入租户和用户，将偏好写入 (tenant_id, user_id) 隔离的命名空间。断言 Runtime 不出现在模型工具 Schema 中。

练习六：审批与幂等 ​

实现退款草稿与提交两个工具。草稿可自动执行，提交必须暂停审批；批准后使用服务端生成的幂等键，重复恢复不得产生第二次退款。

练习七：超时未知状态 ​

模拟写请求在客户端超时、服务端已成功的情况。执行器必须用幂等键查询结果，不能直接重复提交。
