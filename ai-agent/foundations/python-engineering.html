4. 依赖声明、锁定、升级与复现 ​

4.1 声明与锁定是两件事 ​

pyproject.toml 表达意图：

toml
dependencies = ["pydantic==2.13.4"]
1

uv.lock 表达一次完整解析结果，包括间接依赖和适用平台。两者都应提交 Git，.venv 不应提交。

在已有项目中复现环境：

powershell
uv sync --locked
1

--locked 要求锁文件与项目声明一致；不一致时失败，而不是悄悄重写锁文件。这适合 CI 和部署。

检查锁文件仍有效：

powershell
uv lock --check
1

4.2 添加和删除依赖 ​

不要先手改环境再忘记项目声明。使用：

powershell
uv add httpx
uv add --dev pytest-cov
uv remove httpx
1
2
3

命令会同步更新项目声明和锁文件。这里的 httpx、pytest-cov 只是命令示例，不是本页运行所必需的依赖。

4.3 谨慎升级 ​

升级前先保证测试通过并提交当前锁文件：

powershell
uv run pytest
uv lock --upgrade-package pytest
uv run pytest
1
2
3

这个命令只升级 pytest 及解析所需的相关依赖。Pydantic 仍保持 2.13.4 基线；如果将来要改变精确固定的 Pydantic 版本，应先更新直接依赖声明，再审查锁文件。生产项目也应一次升级一小组相关依赖，查看锁文件 diff，再执行完整测试。

WARNING

不要删除锁文件来“解决”依赖冲突。那会把原问题变成一次不可控的全量重新解析。先读冲突信息，确认到底是哪两个版本约束不兼容。

5.2 使用 Pydantic 校验配置 ​

稍后会创建异常类型。先看完整的 src/support_agent/config.py：

python
from __future__ import annotations

import os
from collections.abc import Mapping
from pathlib import Path
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, SecretStr, ValidationError, field_validator

from support_agent.exceptions import ConfigurationError


PROJECT_ROOT = Path(__file__).resolve().parents[2]


class Settings(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True, str_strip_whitespace=True)

    model_api_key: SecretStr = Field(min_length=1)
    model_name: str = Field(default="demo-model", min_length=1)
    log_level: Literal["DEBUG", "INFO", "WARNING", "ERROR"] = "INFO"
    request_timeout: float = Field(default=10.0, gt=0, le=120)
    data_path: Path = PROJECT_ROOT / "data" / "answers.json"

    @field_validator("data_path")
    @classmethod
    def resolve_data_path(cls, value: Path) -> Path:
        path = value.expanduser()
        if path.is_absolute():
            return path
        return (PROJECT_ROOT / path).resolve()


def load_settings(environ: Mapping[str, str] | None = None) -> Settings:
    source = os.environ if environ is None else environ
    raw: dict[str, object] = {}

    variable_map = {
        "MODEL_API_KEY": "model_api_key",
        "AGENT_MODEL": "model_name",
        "AGENT_LOG_LEVEL": "log_level",
        "AGENT_REQUEST_TIMEOUT": "request_timeout",
        "AGENT_DATA_PATH": "data_path",
    }

    for environment_name, field_name in variable_map.items():
        value = source.get(environment_name)
        if value is not None:
            raw[field_name] = value

    try:
        return Settings.model_validate(raw)
    except ValidationError as exc:
        raise ConfigurationError(f"配置校验失败：{exc}") from exc

6.2 恢复必须有明确语义 ​

可恢复情况：

  • 某个可选缓存文件不存在，可以重建；
  • 一条用户输入校验失败，可以要求重新输入；
  • 一个只读查询短暂超时，可以按策略重试。

不可随意恢复的情况：

  • 密钥缺失；
  • 数据格式与约定不一致；
  • 写操作结果未知；
  • 代码触发 AttributeError、NameError 等编程错误。

Agent 涉及外部副作用时，盲目重试可能重复退款或重复发信。重试和幂等会在Web 与数据基础继续讲。

7.2 完整的知识文件边界 ​

创建 src/support_agent/knowledge.py：

python
from __future__ import annotations

import json
from pathlib import Path

from support_agent.exceptions import KnowledgeBaseError


class KnowledgeBase:
    def __init__(self, path: Path) -> None:
        self.path = path
        self._answers = self._load()

    def _load(self) -> dict[str, str]:
        try:
            raw = self.path.read_text(encoding="utf-8")
        except FileNotFoundError as exc:
            raise KnowledgeBaseError(f"知识文件不存在：{self.path}") from exc
        except UnicodeError as exc:
            raise KnowledgeBaseError(f"知识文件不是有效 UTF-8：{self.path}") from exc
        except OSError as exc:
            raise KnowledgeBaseError(f"知识文件读取失败：{self.path}") from exc

        try:
            data: object = json.loads(raw)
        except json.JSONDecodeError as exc:
            raise KnowledgeBaseError(
                f"知识文件不是合法 JSON：{self.path}:{exc.lineno}:{exc.colno}"
            ) from exc

        if not isinstance(data, dict):
            raise KnowledgeBaseError("知识文件顶层必须是 JSON object")

        answers: dict[str, str] = {}
        for keyword, answer in data.items():
            if not isinstance(keyword, str) or not isinstance(answer, str):
                raise KnowledgeBaseError("知识文件的关键词和答案必须都是字符串")
            if not keyword.strip() or not answer.strip():
                raise KnowledgeBaseError("知识文件的关键词和答案不能为空")
            answers[keyword] = answer

        return answers

    def lookup(self, message: str) -> tuple[str, str] | None:
        for keyword, answer in self._answers.items():
            if keyword in message:
                return keyword, answer
        return None

python
from enum import StrEnum

from pydantic import BaseModel, ConfigDict, Field, StrictBool


class Priority(StrEnum):
    LOW = "low"
    NORMAL = "normal"
    HIGH = "high"


class Ticket(BaseModel):
    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)

    ticket_id: str = Field(pattern=r"^T-\d{4}$")
    user_message: str = Field(min_length=2, max_length=2000)
    priority: Priority = Priority.NORMAL

    answer: str = Field(min_length=1)
    matched_keyword: str | None = None
    confidence: float = Field(ge=0, le=1, strict=True)

9. 结构化日志与关联 ID ​

print() 适合练习，生产日志需要等级、时间、模块和请求标识。创建 src/support_agent/logging_config.py：

python
from __future__ import annotations

import json
import logging
from datetime import UTC, datetime
from typing import Any


class JsonFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        payload: dict[str, Any] = {
            "timestamp": datetime.now(UTC).isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "event": record.getMessage(),
        }

        for field in ("request_id", "ticket_id", "matched_keyword"):
            value = getattr(record, field, None)
            if value is not None:
                payload[field] = value

        if record.exc_info:
            payload["exception"] = self.formatException(record.exc_info)

        return json.dumps(payload, ensure_ascii=False)


def configure_logging(level: str) -> None:
    handler = logging.StreamHandler()
    handler.setFormatter(JsonFormatter())

    root_logger = logging.getLogger()
    root_logger.handlers.clear()
    root_logger.addHandler(handler)
    root_logger.setLevel(level)

10. 服务层：把校验、数据与行为组合起来 ​

创建 src/support_agent/service.py：

python
import logging

from support_agent.knowledge import KnowledgeBase
from support_agent.models import AgentReply, Ticket


logger = logging.getLogger(__name__)


class SupportAgent:
    def __init__(self, knowledge_base: KnowledgeBase) -> None:
        self._knowledge_base = knowledge_base

    def handle(self, ticket: Ticket, *, request_id: str) -> AgentReply:
        match = self._knowledge_base.lookup(ticket.user_message)

        if match is None:
            reply = AgentReply(
                ticket_id=ticket.ticket_id,
                answer="暂时没有找到可靠答案，已建议转人工。",
                confidence=0.0,
                needs_handoff=True,
            )
        else:
            keyword, answer = match
            reply = AgentReply(
                ticket_id=ticket.ticket_id,
                answer=answer,
                matched_keyword=keyword,
                confidence=1.0,
                needs_handoff=False,
            )

        logger.info(
            "ticket_handled",
            extra={
                "request_id": request_id,
                "ticket_id": ticket.ticket_id,
                "matched_keyword": reply.matched_keyword,
            },
        )
        return reply

def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(description="运行规则型客服 Agent")
    parser.add_argument("message", help="用户工单内容")
    parser.add_argument("--ticket-id", default="T-1001", help="形如 T-1001")
    parser.add_argument(

def main() -> int:

    request_id = f"req-{uuid4().hex[:12]}"

    try:
        settings = load_settings()
        configure_logging(settings.log_level)

        ticket = Ticket.model_validate(
            {

                "user_message": args.message,

        return 1

    print(reply.model_dump_json(indent=2))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

13.3 把问题变成失败测试 ​

稳定调试流程：

  1. 保存最小复现输入；
  2. 写一个当前会失败的测试；
  3. 确认测试因预期原因失败；
  4. 修复实现；
  5. 运行相关测试和完整测试；
  6. 保留测试，防止回归。

Agent 的模型输出可能不稳定，因此首先保存经过脱敏的原始输入、结构化输出和关联 ID，再用 Fake 或 Mock 构造确定性复现。

16. 常见工程错误 ​

16.1 pip 和 python 不属于同一环境 ​

症状：安装成功后仍然 ModuleNotFoundError。检查：

powershell
python -c "import sys; print(sys.executable)"
python -m pip --version
1
2

优先使用 python -m pip，或统一使用 uv run。

16.2 从错误目录直接运行包内文件 ​

powershell
python src\support_agent\cli.py
1

可能导致 support_agent 无法导入。安装项目后，从根目录运行：

powershell
uv run python -m support_agent.cli "我要退款"
1

16.3 只验证正常路径 ​

“文件存在且 JSON 正确”只是一个路径。至少补充：文件不存在、编码/读取失败、JSON 损坏、结构错误、空字段和未知问题转人工。

16.4 把 Pydantic 当静态类型检查器 ​

Pydantic 校验运行时边界，mypy 检查代码内部类型；二者互补。已经有 Pydantic 不代表可以删除类型标注，已经有 mypy 也不代表可以信任网络 JSON。

16.5 记录了密钥或完整用户内容 ​

日志可搜索、可导出、保留时间可能很长。只记录定位所需的标识、状态和统计信息，对业务内容先做分类和脱敏。

16.6 测试依赖执行顺序 ​

每个测试都应独立。使用 tmp_path、Fixture 和 monkeypatch 隔离文件与环境，不要让前一个测试创建的全局状态成为后一个测试的前提。

16.7 修改声明却没有更新锁文件 ​

CI 的 uv sync --locked 会失败。这是好事：它阻止未经审查的新解析结果进入构建。使用 uv add、uv remove 或显式 uv lock 同步更新，再审查 diff。

18. 本页验收标准 ​

完成本页不等于“命令运行过一次”。你的项目应满足：

  • 使用 Python 3.12.13，并能说明 uv run 与激活 .venv 的区别；
  • pyproject.toml 声明直接依赖，uv.lock 已提交且 uv sync --locked 可复现；
  • .venv、.env、缓存和构建产物不会进入 Git；
  • 普通配置有默认值，必需配置启动时校验，密钥不在代码、错误输出和日志中；
  • 文件路径不依赖当前工作目录，所有文本显式使用 UTF-8；
  • 非法 JSON、错误数据结构和缺失文件被转换为清晰的领域异常；
  • Pydantic 2.13.4 对输入和输出执行运行时校验，并拒绝额外字段；
  • 日志至少包含 UTC 时间、等级、事件、request_id 和 ticket_id；
  • pytest 覆盖正常、无答案、配置缺失、JSON 损坏和结构错误路径；
  • 测试使用 Fixture、参数化、Mock、tmp_path、monkeypatch，并保持互相独立；
  • Ruff 格式与检查、mypy 严格检查、pytest 全部通过；
  • 能从一条 traceback 定位到自己代码中的首个相关行，并把缺陷转成回归测试。

最终验收模拟一次新成员接手：在一个干净目录克隆项目，只提供 .env.example 中说明的环境变量，执行 uv sync --locked，然后运行质量门禁和 CLI。若对方不需要猜解释器、依赖、工作目录或密钥位置，并且错误输入能得到明确失败，工程化基础才算完成。
