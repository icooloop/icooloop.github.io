结构化输出 ​

自由文本适合人阅读，程序更需要类型明确、字段稳定、错误可定位的数据。本章将模型输出从“看起来像 JSON”推进到完整链路：

text
定义数据契约
→ 请求模型按契约输出
→ 解析 JSON
→ Pydantic 校验
→ 业务规则校验
→ 有限修复重试
→ 返回类型化对象

本章以 Pydantic 2.13.4 为锁定版本，所有离线示例不需要 API Key。厂商原生结构化输出的代码会单独标明为版本相关。

1. 为什么“请返回 JSON”还不够 ​

下面的 Prompt 只能表达期望，不能保证结果有效：

text
分析工单并返回 JSON，包含 category 和 confidence。
1

模型可能返回：

text
```json
{"category": "退款", "confidence": "非常高"}
```
1
2
3

问题包括：

  • Markdown 代码围栏不是 JSON 文档的一部分；
  • category 使用中文自由文本，不是允许的枚举；
  • confidence 应是数字，却返回字符串；
  • 缺少模型版本或 Schema 版本；
  • 即使语法正确，也可能违反业务规则。

因此要区分四层正确性：

层次检查内容典型失败
JSON 语法能否解析少引号、尾随逗号、代码围栏
Schema字段、类型、枚举、范围缺字段、错误类型、额外字段
跨字段规则字段之间是否一致拒答却仍给出置信度 0.99
业务规则当前订单和用户是否允许操作退款金额超过可退金额

结构化输出的目标不是让程序“尽量解析”，而是让错误尽早、明确地暴露。

exc.errors() 会给出结构化错误列表。可转换成适合日志或修复 Prompt 的摘要：

python
def summarize_validation_error(exc: ValidationError) -> list[dict[str, str]]:
    summary: list[dict[str, str]] = []

    for error in exc.errors():
        path = ".".join(str(part) for part in error["loc"])
        summary.append(
            {
                "path": path or "$",
                "type": error["type"],
                "message": error["msg"],
            }
        )

    return summary

from decimal import Decimal
from typing import Annotated, Literal

from pydantic import BaseModel, ConfigDict, Field


class RefundAction(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    kind: Literal["refund"]
    amount: Decimal = Field(gt=0)
    reason: str = Field(min_length=1, max_length=120)


class EscalateAction(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    kind: Literal["escalate"]
    queue: Literal["billing", "risk", "manual_review"]
    reason: str = Field(min_length=1, max_length=120)


class NoAction(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    kind: Literal["none"]
    reason: str = Field(min_length=1, max_length=120)


Action = Annotated[
    RefundAction | EscalateAction | NoAction,
    Field(discriminator="kind"),
]


class ActionDecision(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    action: Action

8. 字段校验器与跨字段校验 ​

8.1 字段规范化 ​

python
from pydantic import BaseModel, field_validator


class UserSummary(BaseModel):
    display_name: str
    tags: list[str]

    @field_validator("display_name")
    @classmethod
    def strip_display_name(cls, value: str) -> str:
        cleaned = value.strip()
        if not cleaned:
            raise ValueError("display_name 不能为空")
        return cleaned

    @field_validator("tags")
    @classmethod
    def normalize_tags(cls, values: list[str]) -> list[str]:
        cleaned = {value.strip().lower() for value in values if value.strip()}
        return sorted(cleaned)

8.2 跨字段约束 ​

python
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, model_validator


class GroundedAnswer(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    status: Literal["answered", "insufficient_evidence"]
    answer: str
    confidence: float = Field(ge=0.0, le=1.0)
    citation_ids: list[str]

    @model_validator(mode="after")
    def validate_consistency(self) -> "GroundedAnswer":
        if self.status == "answered":
            if not self.answer.strip():
                raise ValueError("answered 状态必须包含答案")
            if not self.citation_ids:
                raise ValueError("answered 状态必须包含引用")
        else:
            if self.citation_ids:
                raise ValueError("证据不足时不应返回引用")
            if self.confidence > 0.5:
                raise ValueError("证据不足时置信度不应高于 0.5")

        return self

10. 模型原生结构化输出 ​

支持原生结构化输出的模型服务可以在生成阶段使用 Schema 约束结果。它通常比“Prompt 要求 JSON，然后手工截取花括号”更可靠。

11. 结构化输出与 Tool Calling 的区别 ​

两者都使用 Schema，但语义不同：

能力结构化输出Tool Calling
目的返回程序可消费的结果请求应用执行某个工具
结果去向作为本次任务最终或中间数据交给工具执行器
是否产生副作用本身通常不会工具可能查询、写入或支付
后续动作校验后交给业务代码校验、鉴权、执行，再返回 Tool Result
例子工单分类结果调用 create_refund(order_id, amount)

不要为了获得 JSON 就把所有输出伪装成工具调用；也不要把工具参数当成已经执行成功的业务结果。

一个工具调用只表达模型的请求：

13. 有限修复重试 ​

失败后可以把精简的校验错误反馈给模型，但必须限制次数。

python
from collections.abc import Callable

from pydantic import ValidationError

ModelCall = Callable[[str], str]


def parse_with_repair(
    model_call: ModelCall,
    original_prompt: str,
    *,
    max_attempts: int = 3,
) -> TicketAnalysis:
    feedback = ""

    for attempt in range(1, max_attempts + 1):
        prompt = original_prompt

        if feedback:
            prompt += f"""

上一次输出未通过校验。请重新生成完整 JSON，不要解释。
校验错误：
{feedback}
"""

        raw = model_call(prompt)

        try:
            return TicketAnalysis.model_validate_json(raw)
        except ValidationError as exc:
            errors = summarize_validation_error(exc)
            feedback = str(errors[:5])

    raise RuntimeError(f"结构化输出连续 {max_attempts} 次校验失败")

14. Schema 校验与业务校验必须分开 ​

Pydantic 可以证明金额大于零，却不知道该订单最多能退多少钱。

python
from dataclasses import dataclass
from decimal import Decimal


@dataclass(frozen=True)
class RefundContext:
    order_id: str
    refundable_amount: Decimal
    user_can_refund: bool
    order_status: str


class BusinessRuleError(ValueError):
    pass


def validate_refund_business_rule(
    action: RefundAction,
    context: RefundContext,
) -> None:
    if not context.user_can_refund:
        raise BusinessRuleError("当前用户没有退款权限")

    if context.order_status not in {"paid", "shipped", "delivered"}:
        raise BusinessRuleError(f"订单状态 {context.order_status} 不允许退款")

    if action.amount > context.refundable_amount:
        raise BusinessRuleError(
            f"退款金额 {action.amount} 超过可退金额 {context.refundable_amount}"
        )

16. 完整离线示例 ​

下面的文件可以直接运行，演示枚举、嵌套引用、跨字段校验、业务校验、失败反馈和有限重试。

python
from __future__ import annotations

import json
from collections.abc import Callable
from dataclasses import dataclass
from enum import StrEnum
from typing import Literal

from pydantic import (
    BaseModel,
    ConfigDict,
    Field,
    ValidationError,
    model_validator,
)


class Category(StrEnum):
    ORDER = "order"
    LOGISTICS = "logistics"
    REFUND = "refund"
    OTHER = "other"


class Citation(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    source_id: str = Field(min_length=1)
    quote: str = Field(min_length=1, max_length=200)


class Analysis(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    schema_version: Literal["1.0"]
    category: Category
    confidence: float = Field(ge=0.0, le=1.0)
    answer: str = Field(max_length=500)
    citations: list[Citation] = Field(default_factory=list, max_length=5)
    needs_human: bool

    @model_validator(mode="after")
    def check_answer_and_citations(self) -> "Analysis":
        if self.answer.strip() and not self.citations:
            raise ValueError("提供事实性答案时必须给出引用")
        if self.confidence < 0.5 and not self.needs_human:
            raise ValueError("低置信度结果必须进入人工处理")
        return self


@dataclass(frozen=True)
class BusinessContext:
    allowed_source_ids: frozenset[str]


def validate_business(result: Analysis, context: BusinessContext) -> None:
    unknown = {
        citation.source_id
        for citation in result.citations
        if citation.source_id not in context.allowed_source_ids
    }
    if unknown:
        raise ValueError(f"引用了未提供的来源: {sorted(unknown)}")


def error_summary(exc: ValidationError) -> str:
    compact = [
        {
            "path": ".".join(map(str, item["loc"])),
            "message": item["msg"],
            "type": item["type"],
        }
        for item in exc.errors()
    ]
    return json.dumps(compact, ensure_ascii=False)


def generate_validated(
    call_model: Callable[[str], str],
    prompt: str,
    *,
    max_attempts: int = 3,
) -> Analysis:
    feedback = ""

    for attempt in range(1, max_attempts + 1):
        current_prompt = prompt
        if feedback:
            current_prompt += (
                "\n上一次输出无效。请返回完整 JSON，不要解释。"
                f"\n错误：{feedback}"
            )

        raw = call_model(current_prompt)

        try:
            return Analysis.model_validate_json(raw)
        except ValidationError as exc:
            feedback = error_summary(exc)

    raise RuntimeError(f"经过 {max_attempts} 次仍无法得到有效结构")


def main() -> None:
    # 前两次分别违反枚举和跨字段规则，第三次通过。
    outputs = iter(
        [
            """{
              "schema_version": "1.0",
              "category": "shipping",
              "confidence": 0.9,
              "answer": "包裹正在运输。",
              "citations": [],
              "needs_human": false
            }""",
            """{
              "schema_version": "1.0",
              "category": "logistics",
              "confidence": 0.4,
              "answer": "",
              "citations": [],
              "needs_human": false
            }""",
            """{
              "schema_version": "1.0",
              "category": "logistics",
              "confidence": 0.88,
              "answer": "订单仍在运输途中。",
              "citations": [
                {
                  "source_id": "shipment-o-1001",
                  "quote": "运输中，预计明日送达"
                }
              ],
              "needs_human": false
            }""",
        ]
    )

    call_count = 0

    def fake_model(prompt: str) -> str:
        nonlocal call_count
        call_count += 1
        print(f"attempt={call_count}, prompt_length={len(prompt)}")
        return next(outputs)

    result = generate_validated(
        fake_model,
        "分析物流工单，严格按照 Analysis Schema 返回 JSON。",
    )

    validate_business(
        result,
        BusinessContext(
            allowed_source_ids=frozenset({"shipment-o-1001"}),
        ),
    )

    print(result.model_dump_json(indent=2))
    print("attempts:", call_count)


if __name__ == "__main__":
    main()

18. 常见错误 ​

只在 Prompt 中贴 Schema ​

模型看到 Schema 不等于服务端强制 Schema。必须解析并校验。

捕获错误后返回空对象 ​

python
# 反例：下游无法区分真实空结果与解析失败。
try:
    return TicketAnalysis.model_validate_json(raw)
except ValidationError:
    return {}
1
2
3
4
5

应该返回明确失败状态、抛出领域异常或进入有限重试。

过度自动修复 ​

自动删除代码围栏、补引号、转换类型可能短期“提高成功率”，长期却会隐藏 Prompt 或模型回归。每一种修复都应可观测、可测试并有上限。

把置信度当真实概率 ​

模型自报的 confidence=0.95 不等于校准后的 95% 正确率。置信度必须通过历史数据评测，不能单独决定高风险操作。

Schema 过大 ​

一次要求模型生成几十个深层字段，失败定位和重试成本都会增加。复杂任务应拆分成几个有明确边界的结构化步骤。

忽略拒答和不完整状态 ​

结构合法不代表模型正常回答。必须同时检查响应状态、拒答信息和业务内容。

19. 本章练习 ​

练习一：定义嵌套 Schema ​

定义一份研究摘要，包含标题、三条结论、来源列表和风险等级。禁止额外字段，并限制数组长度。

练习二：设计联合动作 ​

定义 reply、create_ticket、escalate 三种动作，用 kind 作为判别字段，确保每种动作只能拥有自己的参数。

练习三：跨字段校验 ​

规定 status="answered" 时必须有引用，status="insufficient_evidence" 时答案为空且置信度不超过 0.5。

练习四：业务校验 ​

让模型输出退款建议，再使用应用提供的订单金额、状态和用户权限进行二次校验。验证 Schema 正确但业务非法的案例会被拒绝。

练习五：有限修复 ​

Fake Model 依次返回非法 JSON、类型错误和正确数据；断言第三次成功。再让它始终失败，断言达到上限后终止。

练习六：兼容性迁移 ​

设计 V1 和 V2 Schema，为 V1 历史数据编写迁移函数，并测试重命名字段、增加默认字段和收紧枚举的影响。
