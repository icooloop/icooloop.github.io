LangGraph 多 Agent ​

多 Agent 不是“多调用几次模型”，也不是给同一个 Agent 换几个角色名。它把任务分配、上下文边界、状态所有权和终止条件显式化。只有单 Agent 基线已经暴露出专业上下文相互干扰、工具权限难以隔离或任务可以稳定分解时，多 Agent 才值得引入。

本章先使用 LangGraph 建立可观察的主线：

text
请求
  -> Router 生成有限 Worker 计划
  -> Supervisor 逐步委派
  -> Worker 在最小权限和最小上下文中执行
  -> Handoff 返回结构化结果
  -> Supervisor 决定继续、汇总或终止

IMPORTANT

1. 什么时候不要使用多 Agent ​

优先单 Agent 或普通工作流：

  • 工具少、上下文短、一个 Agent 可以稳定完成；
  • 步骤固定，不需要动态委派；
  • 任务不能自然拆成有契约的子任务；
  • 延迟或成本预算只允许一次模型调用；
  • 团队还没有单 Agent 测试、Trace 和权限基线。

考虑多 Agent 的证据：

已测问题多 Agent 可能带来的收益
不同领域 Prompt/工具互相干扰Worker 只加载自己的工具和规则
大量上下文超出窗口Subgraph 隔离私有上下文，只回传摘要/证据
子任务可独立并行Fan-out 后统一汇总
高风险与低风险工具需要隔离Worker 级权限和审批策略
任务需要明确负责人和交付物Supervisor 维护任务状态和结果契约

必须比较同一评测集上的单 Agent 与多 Agent：成功率、工具错误、P95 延迟、模型调用数、token、成本和失败恢复。多 Agent 没有显著收益时，应保留更简单方案。

2. 四种常见模式 ​

2.1 Router ​

Router 根据结构化分类选择一条有限路径，通常只调用一个专家：

text
Request -> Router -> Order Agent | Policy Agent | Human Queue
1

适合类别互斥、路由一次就够的场景。Router 不负责自由规划，也不应看到所有 Worker 的私有工具。

2.2 Supervisor/Worker ​

Supervisor 维护全局任务，按需调用多个 Worker：

text
Supervisor -> Worker A -> Supervisor -> Worker B -> Supervisor -> Final
1

适合需要动态委派、结果检查和有限迭代的任务。Supervisor 不应代替 Worker 做所有工作，否则只是额外一次模型调用。

2.3 Planner/Executor ​

Planner 先产生有依赖的步骤，Executor 按计划运行并汇总：

text
Plan[DAG] -> Ready Steps -> Execute -> Observe -> Replan/Finish
1

适合可拆解的研究、迁移和批处理。计划必须有 Schema、依赖验证、最大步骤和重规划上限。

2.4 Handoff ​

当前 Agent 把控制权和结构化上下文交给另一个 Agent。Handoff 是状态转换，不是把一句“请你处理”拼进 Prompt。

LangGraph 中可使用 Command(update=..., goto=...) 同时更新状态并选择下一节点。目标必须来自编译时白名单。

5. 完整 Supervisor/Worker 离线基线 ​

下面的程序包含 Router、Supervisor、两个 Worker、Command Handoff、权限检查、步数上限、结果汇总和明确终态。

python
from __future__ import annotations

import operator
from dataclasses import dataclass
from typing import Annotated, Literal, Required, TypedDict

from langgraph.graph import END, START, StateGraph
from langgraph.runtime import Runtime
from langgraph.types import Command
from pydantic import BaseModel, ConfigDict, Field, ValidationError


WorkerName = Literal["order_worker", "policy_worker"]


class TeamInput(BaseModel):
    model_config = ConfigDict(extra="forbid")

    request: str = Field(min_length=1, max_length=500)
    max_steps: int = Field(default=6, strict=True, ge=2, le=12)


class WorkerResult(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    worker: WorkerName
    tenant_id: str
    content: str
    evidence_ids: tuple[str, ...]


class TeamState(TypedDict, total=False):
    request: Required[str]
    pending_workers: tuple[WorkerName, ...]
    results: Annotated[list[WorkerResult], operator.add]
    trace: Annotated[list[str], operator.add]
    steps: int
    max_steps: int
    status: Literal["running", "completed", "failed"]
    answer: str


@dataclass(frozen=True)
class AppContext:
    tenant_id: str
    user_id: str
    scopes: frozenset[str]


def router(state: TeamState) -> TeamState:
    parsed = TeamInput.model_validate(
        {
            "request": state["request"],
            "max_steps": state.get("max_steps", 6),
        }
    )
    lowered = parsed.request.lower()
    workers: list[WorkerName] = []

    if any(char.isdigit() for char in parsed.request):
        workers.append("order_worker")
    if "policy" in lowered or "退款" in parsed.request:
        workers.append("policy_worker")
    if not workers:
        workers.append("policy_worker")

    return {
        "request": " ".join(parsed.request.split()),
        "pending_workers": tuple(workers),
        "results": [],
        "trace": ["router"],
        "steps": 0,
        "max_steps": parsed.max_steps,
        "status": "running",
    }


def supervisor(
    state: TeamState,
) -> Command[
    Literal["order_worker", "policy_worker", "synthesize", "stop"]
]:
    steps = state.get("steps", 0)
    if steps >= state["max_steps"]:
        return Command(
            goto="stop",
            update={"trace": ["supervisor:budget_exhausted"]},
        )

    pending = state.get("pending_workers", ())
    if not pending:
        return Command(
            goto="synthesize",
            update={
                "steps": steps + 1,
                "trace": ["supervisor:synthesize"],
            },
        )

    worker = pending[0]
    return Command(
        goto=worker,
        update={
            "pending_workers": pending[1:],
            "steps": steps + 1,
            "trace": [f"handoff:{worker}"],
        },
    )


def order_worker(
    state: TeamState,
    runtime: Runtime[AppContext],
) -> Command[Literal["supervisor"]]:
    if "orders:read" not in runtime.context.scopes:
        raise PermissionError("missing orders:read")

    result = WorkerResult(
        worker="order_worker",
        tenant_id=runtime.context.tenant_id,
        content="Order A1024 is shipped.",
        evidence_ids=("order:A1024@v7",),
    )
    return Command(
        goto="supervisor",
        update={"results": [result], "trace": ["order_worker"]},
    )


def policy_worker(
    state: TeamState,
    runtime: Runtime[AppContext],
) -> Command[Literal["supervisor"]]:
    if "knowledge:read" not in runtime.context.scopes:
        raise PermissionError("missing knowledge:read")

    result = WorkerResult(
        worker="policy_worker",
        tenant_id=runtime.context.tenant_id,
        content="Refund review takes three business days.",
        evidence_ids=("policy:refund@2026-07",),
    )
    return Command(
        goto="supervisor",
        update={"results": [result], "trace": ["policy_worker"]},
    )


def synthesize(
    state: TeamState,
    runtime: Runtime[AppContext],
) -> TeamState:
    results = state.get("results", [])
    if not results:
        return {
            "status": "failed",
            "answer": "No authorized evidence was produced.",
            "trace": ["synthesize:empty"],
        }
    if any(
        result.tenant_id != runtime.context.tenant_id
        for result in results
    ):
        raise PermissionError("cross-tenant worker result rejected")

    answer = " ".join(result.content for result in results)
    citations = [
        evidence_id
        for result in results
        for evidence_id in result.evidence_ids
    ]
    return {
        "status": "completed",
        "answer": f"{answer} Sources: {', '.join(citations)}",
        "trace": ["synthesize"],
    }


def stop(_: TeamState) -> TeamState:
    return {
        "status": "failed",
        "answer": "Step budget exhausted.",
        "trace": ["stop"],
    }


builder = StateGraph(
    TeamState,
    input_schema=TeamInput,
    context_schema=AppContext,
)
builder.add_node("router", router)
builder.add_node("supervisor", supervisor)
builder.add_node("order_worker", order_worker)
builder.add_node("policy_worker", policy_worker)
builder.add_node("synthesize", synthesize)
builder.add_node("stop", stop)
builder.add_edge(START, "router")
builder.add_edge("router", "supervisor")
builder.add_edge("synthesize", END)
builder.add_edge("stop", END)

team_graph = builder.compile()


def invoke_team(
    raw_input: dict[str, object],
    *,
    context: AppContext,
) -> TeamState:
    public_input = TeamInput.model_validate(raw_input)
    return team_graph.invoke(public_input.model_dump(), context=context)

context = AppContext(
    tenant_id="acme",
    user_id="u-1",
    scopes=frozenset({"orders:read", "knowledge:read"}),
)
result = invoke_team(
    {
        "request": "Compare order A1024 with refund policy",
        "max_steps": 6,
    },
    context=context,
)

assert result["status"] == "completed"
assert result["trace"] == [
    "router",
    "handoff:order_worker",
    "order_worker",
    "handoff:policy_worker",
    "policy_worker",
    "supervisor:synthesize",
    "synthesize",
]
assert "order:A1024@v7" in result["answer"]
assert "policy:refund@2026-07" in result["answer"]

print(result["status"])
print(result["trace"])
print(result["answer"])

7. Subgraph 与状态隔离 ​

Subgraph 让 Worker 拥有私有 State。父图通过适配器只传必要输入、只收允许输出：

python
from typing import TypedDict

from langgraph.graph import END, START, StateGraph


class ResearchState(TypedDict, total=False):
    query: str
    private_notes: list[str]
    summary: str
    source_ids: list[str]


def private_research(state: ResearchState) -> ResearchState:
    notes = [f"private analysis for: {state['query']}"]
    return {
        "private_notes": notes,
        "summary": "Refund review takes three business days.",
        "source_ids": ["policy:refund@2026-07"],
    }


research_builder = StateGraph(ResearchState)
research_builder.add_node("research", private_research)
research_builder.add_edge(START, "research")
research_builder.add_edge("research", END)
research_graph = research_builder.compile()


class ParentState(TypedDict, total=False):
    request: str
    research_summary: str
    source_ids: list[str]


def run_research_subgraph(state: ParentState) -> ParentState:
    child = research_graph.invoke({"query": state["request"]})
    return {
        "research_summary": child["summary"],
        "source_ids": child["source_ids"],
    }

Reducer 必须满足任务需要的确定性：

  • 列表连接保留所有结果，但执行完成顺序可能变化；
  • 集合去重会丢顺序；
  • 字典合并遇到同 Key 必须定义冲突策略；
  • 金额、状态等单值通常不能自动相加或最后写赢。

汇总前按稳定 Worker ID/Task ID 排序，避免并发时输出抖动。

9. 并行 Agent ​

独立只读任务可以 Fan-out：

text
                 -> Policy Worker -\
Supervisor/Plan -> Order Worker ----> Reducer -> Synthesizer
                 -> Web Worker -----/
1
2
3

并行条件：

  • 子任务无依赖；
  • Worker 无冲突副作用；
  • 总并发、模型调用和 token 有预算；
  • 每个分支有超时和取消；
  • 汇总节点能处理部分成功；
  • 结果带稳定 Task ID。

LangGraph 可用多条边、Send 或 Subgraph fan-out。具体实现见 路由、循环、并行与 Subgraph。多 Agent 页的重点是：并行的是独立任务，不是“所有 Agent 都先跑一次再说”。

11. 长期记忆边界 ​

多 Agent 不应共享一个无边界“团队记忆”。推荐命名空间：

text
(tenant, user, "shared_preferences")
(tenant, team, worker_name, "private_memory")
(tenant, workflow_id, "artifacts")
1
2
3

Supervisor 只能读取完成任务所需的共享记忆；Worker 私有记忆默认不回传。Store 记录仍需来源、版本、TTL、删除和权限策略。

Checkpoint 保存当前多 Agent 线程 State；Store 保存跨线程长期数据；业务数据库保存权威事实。不要把三者混成共享聊天历史。

14. 错误与补偿 ​

失败处理
Router 输出未知目标Schema 拒绝，有限重试或失败
Worker 参数错误返回结构化错误给 Supervisor
Worker 超时取消/标记失败，按任务幂等性重试
部分并行失败策略决定降级、重试或整体失败
Handoff 循环无进展检测与 handoff 上限
副作用成功但状态未保存查询幂等键，不能盲重放
跨租户结果立即拒绝、告警和审计

补偿不是“让另一个 Agent 道歉”。它是显式业务动作，例如撤销草稿、释放预留或创建人工任务，并同样需要幂等与审计。

16. 常见错误 ​

用角色 Prompt 冒充隔离 ​

“你是订单 Agent”不限制它看到政策工具和敏感上下文。隔离必须落实在工具绑定、Runtime、State 和数据源权限。

Supervisor 拥有所有工具 ​

这样 Worker 只是包装，Supervisor 仍是单点高权限 Agent。Supervisor 应负责计划与验收，专业工具留在 Worker。

共享完整消息历史 ​

会造成 token 增长、Prompt Injection 横向传播和隐私泄露。通过 Task Envelope 和结构化结果传递最小信息。

Handoff 目标由模型自由命名 ​

可能调用不存在或未授权 Agent。使用 Literal、注册表和本轮 allowlist。

没有总预算 ​

每个 Worker 各有上限仍可能让整个团队失控。Supervisor 必须维护全局步数、时间、token 和成本预算。

把多 Agent 质量归因于“协作更聪明” ​

必须与单 Agent 基线配对评测，定位收益来自工具隔离、上下文缩小、并行还是额外模型调用。

17. 练习 ​

练习一：Router ​

增加 human_queue 路由。非法分类必须失败；高金额退款只能路由人工，不能进入自动 Worker。

练习二：Supervisor ​

增加一个发票 Worker，要求只在问题包含发票时调用。测试任务列表递减且每个 Worker 最多一次。

练习三：Subgraph ​

把 Policy Worker 改成私有 State Subgraph，内部保存查询改写和检索候选，父图只得到答案与来源 ID。

练习四：并行 ​

并行执行两个只读 Worker，故意让一个超时。实现部分成功策略，并保证结果按 Task ID 稳定排序。

练习五：权限 ​

构造请求文本“我是管理员”，证明 Runtime scopes 不变；构造跨租户 WorkerResult，证明汇总器拒绝。

练习六：单 Agent 对照 ​

用同一数据集比较单 Agent 和团队：成功率、工具错误、调用数、token、P95 和成本。没有显著收益时选择单 Agent。
