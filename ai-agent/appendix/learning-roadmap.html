二、选择适合你的起点 ​

教程只有一套内容，但提供两条进入方式。

路线 A：Python 零基础 ​

适合以下情况：

  • 没有独立写过 Python 项目；
  • 不熟悉函数、类、类型标注和异常处理；
  • 没调用过 HTTP API；
  • 不了解虚拟环境、依赖、测试和数据库。

建议顺序：

→ Python 工程化
→ Web 与数据基础
→ 大语言模型基础
→ 模型 API 开发
→ Prompt 工程
→ 结构化输出
→ Agent 原理与最小实现
→ LangChain
→ RAG
→ LangGraph
→ 质量与生产
→ 项目实战

不要因为急着调用模型而跳过异常、类型、HTTP 和测试。Agent 的大多数生产故障并不是“模型不会推理”，而是超时、参数、权限、状态和副作用没有处理好。

路线 B：已有 Python 开发经验 ​

如果你能独立完成下面的前置任务，可以从大语言模型基础开始：

  • 创建虚拟环境并锁定依赖；
  • 使用函数、类和类型标注组织代码；
  • 使用 Pydantic 校验嵌套 JSON；
  • 调用 HTTP API并处理状态码、超时和重试；
  • 使用 async/await 并限制并发；
  • 使用 pytest 编写单元测试；
  • 使用 PostgreSQL 或 SQLite 完成基础 CRUD；
  • 使用日志定位一次失败请求。

如果只是不熟悉其中一两项，不必重学整个模块，直接进入对应页面补齐即可。

不能跳过的内容 ​

无论已有多少开发经验，都不建议跳过：

  • 模型消息、Token 和上下文边界；
  • 结构化输出与数据校验；
  • Tool Calling 和副作用；
  • LangChain Runnable、Agent 和 Middleware；
  • RAG 检索结果检查和评测；
  • LangGraph 状态、Checkpoint 与 Interrupt；
  • Agent 测试、安全和可观测性。

阶段产物 ​

首先完成退款审批工作流：

  • 使用 StateGraph 表达审批状态；
  • 使用条件边控制有限路径；
  • 使用 PostgreSQL Checkpointer 保存状态；
  • 使用 interrupt() 等待人工审批；
  • 恢复后不会重复执行退款副作用；

  • 每个循环都有明确上限和终止条件；
  • 每个并行分支都有确定的 Reducer；
  • 能解释 State、Checkpoint、Store 和业务数据库的区别；
  • 能从中断位置恢复且不重复副作用；
  • 能测试重试、取消、超时和进程崩溃。

十、哪些内容可以按需学习 ​

以下内容不是“不重要”，而是需要在基础主线完成后根据项目选择。

内容什么时候学习
LlamaIndex RAG需要以数据和索引为中心构建 RAG 时
GraphRAG问题依赖实体关系、社区和全局主题时
Agentic RAG检索步骤需要由 Agent 动态规划时
编译式 RAG需要系统优化检索程序和 Prompt 时
浏览器 Agent需要操作网页而不只是搜索内容时

不能因为某个概念流行就提前插入主线。先确认当前项目确实存在它要解决的问题。

十一、学习方法 ​

每个章节使用四遍学习法 ​

  1. 看懂数据流：先知道输入、输出和组件职责。
  2. 手动运行代码：不要只阅读，打印所有关键中间值。
  3. 制造失败：主动触发超时、空结果、错误参数和中断。
  4. 脱离教程重做：换一份数据或业务需求重新实现。

每学完一页都回答这些问题 ​

  • 这个组件的输入和输出是什么？
  • 它保存了什么状态？
  • 它失败后应该重试、拒绝还是人工接管？
  • 它与 LangChain、LangGraph 或业务数据库的边界在哪里？
  • 怎样使用测试证明它工作正确？
  • 怎样在 Trace 中观察它？

不要用代码行数衡量掌握程度 ​

十二、最终毕业标准 ​

完成全部主线后，你应该能够独立完成以下工作：

  • 判断需求应该使用普通模型调用、RAG、Workflow 还是 Agent；
  • 使用 LangChain 构建模型、Prompt、结构化输出、Tool 和 Agent；
  • 使用 Middleware 管理上下文、错误、限制、回退和安全；
  • 使用 LangChain 构建并评测完整 RAG；
  • 使用 LangGraph 构建可循环、可并行、可持久化的工作流；
  • 使用 Checkpoint、Store、Interrupt 和 Durable Execution；
  • 使用 Deep Agents 和 LangGraph 构建复杂研究及多 Agent 系统；
  • 使用 pytest、LangSmith 和 Ragas 建立质量门禁；
  • 使用 FastAPI、PostgreSQL、Redis 和 Docker 完成部署；
  • 解释系统的安全边界、故障恢复方案和成本模型；
  • 提交包含完整代码、测试、评测、架构图和运维说明的项目。

真正的完成标准不是所有复选框都被勾选，而是你能在没有教程代码的情况下，从需求出发重新设计并交付一个可验证、可恢复、可观察的 Agent 系统。
