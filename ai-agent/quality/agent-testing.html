Agent 测试 ​

Agent 测试不是把一句问题交给真实模型，然后人工判断回答“看起来不错”。一个 Agent 同时包含输入校验、Prompt、模型、工具、检索、状态迁移、持久化和外部副作用；只测最终文本，失败时既不知道坏在哪，也无法稳定复现。

本页建立一套从零到生产的 Python 测试方法。你会把随机组件隔离在边界，把确定性业务规则写成快速测试，再用少量集成测试验证真实依赖。

学完本页，你应该能够：

  • 为 Agent 定义输入、输出、工具、状态和副作用契约；
  • 区分单元测试、组件测试、路径测试、端到端测试和离线评测；
  • 使用 unittest，并理解 pytest 的 Fixture、参数化与异常断言；
  • 正确选择 Stub、Fake、Mock、Spy 和 Record/Replay；
  • 测试模型结构化输出、Tool Call、工具权限和重试边界；
  • 测试 RAG 的数据隔离、召回、排序、空结果与引用绑定；
  • 测试 LangGraph Node、State、Reducer、Router 和完整路径；
  • 验证 Interrupt、Checkpoint、恢复、幂等和并发语义；
  • 建立可维护的测试数据、失败路径矩阵和 CI 门禁。

IMPORTANT

本页的“已验证”只指仓库锁定环境：Python 3.12.13、langchain==1.3.14、langchain-core==1.4.9、langgraph==1.2.9、langgraph-checkpoint==4.1.1、pydantic==2.13.4。仓库质量示例使用标准库 unittest。pytest 当前未安装，因此 pytest 代码用于展示测试形状，未冒充已运行结果；采用时必须先锁定版本。

1. 先分清测试与评测 ​

测试回答的是可判定问题：

  • 非法 order_id 是否在工具执行前被拒绝；
  • 退款路径是否一定进入人工审批；
  • 同一幂等键重放是否只产生一次外部提交；
  • 检索器是否永远不会返回其他租户的文档；
  • 达到最大循环次数后是否进入明确终态。

评测回答的是质量问题：

  • 回答是否有帮助；
  • 引用是否支持结论；
  • 检索结果是否相关；
  • 任务完成率是否达到发布门槛；
  • 新 Prompt 相比基线是否退化。

两者会协作，但不能互相替代。status == "waiting_approval" 应用断言测试，不必交给 Judge 模型；“语气是否清晰”适合评测，不应硬编码整段字符串。

text
确定性测试：代码规则是否正确？     -> 每次提交都运行
离线评测：Agent 整体质量是否足够？ -> 数据集回归与发布门禁
线上监控：真实分布是否发生变化？   -> 灰度、告警与回滚

2. Agent 测试金字塔 ​

传统 Web 应用常画“单元、集成、端到端”三层。Agent 更适合五层：

层级典型对象是否调用真实模型速度数量
L1 纯函数与 Schema解析、Reducer、Router、权限否毫秒最多
L2 组件契约模型适配器、工具、检索器、NodeFake 为主毫秒到秒多
L3 工作流路径LangChain Runnable、LangGraph GraphFake/录制秒级中等
L4 基础设施集成向量库、Checkpoint DB、Redis、HTTP可选秒到分钟少
L5 真实端到端锁定模型、真实沙箱工具是慢且有成本最少

一个实用比例不是固定数字，而是以下原则：

  • 能在 L1 判断的规则，不推迟到 L5；
  • L2/L3 使用确定性替身覆盖分支和失败；
  • L4 验证驱动、事务和序列化，不重复业务排列组合；
  • L5 只验证关键用户旅程和供应商契约；
  • 非确定性质量交给数据集评测，不靠反复重跑碰运气。

2.1 每个功能先写五类契约 ​

以“退款 Agent”为例：

  1. 数据契约：输入字段、类型、范围、额外字段策略；
  2. 行为契约：什么条件走查询、草稿、审批或拒绝；
  3. 副作用契约：提交几次、使用哪个幂等键、失败后能否重试；
  4. 恢复契约：哪个状态可持久化，恢复时从哪里继续；
  5. 安全契约：租户、权限、工具允许列表、敏感信息处理。

契约必须写成可观察结果。不要写“Agent 应该聪明地处理退款”，应写“金额超过阈值时状态是 waiting_approval，且 submit_refund 调用次数为 0”。

3. 第一个测试：Arrange、Act、Assert ​

所有测试都可用三个阶段阅读：

python
import unittest

from evaluation_harness import evaluate_case, sample_case, sample_trace


class EvaluationHarnessTests(unittest.TestCase):
    def test_expected_trace_passes_all_contracts(self) -> None:
        # Arrange：构造固定输入和预期。
        case = sample_case()
        trace = sample_trace()

        # Act：只执行一个明确行为。
        result = evaluate_case(case, trace)

        # Assert：验证业务结果，而不是实现细节。
        self.assertTrue(result.passed)
        self.assertEqual(result.score, 1.0)
        self.assertEqual(result.safety_violations, [])


if __name__ == "__main__":
    unittest.main()

4. unittest 与 pytest 怎样选择 ​

unittest 属于 Python 标准库，不需要新增依赖；pytest 提供更简洁的 Fixture、参数化、Marker 和失败信息。团队可以用 pytest 收集 unittest.TestCase，但不应在同一个测试函数里混用两套风格。

4.1 unittest：零依赖基线 ​

python
import unittest

from pydantic import ValidationError

from langgraph_workflow import ticket_graph


class TicketGraphTests(unittest.TestCase):
    def test_invalid_attempt_type_is_rejected(self) -> None:
        with self.assertRaises(ValidationError):
            ticket_graph.invoke(
                {
                    "request": "refund review time",
                    "max_attempts": "2",
                    "trace": [],
                }
            )

    def test_order_request_finishes_without_review(self) -> None:
        result = ticket_graph.invoke(
            {"request": "Where is order A1024?", "trace": []}
        )

        self.assertEqual(result["status"], "completed")
        self.assertEqual(result["trace"], ["classify", "answer_order"])

5. 测试替身：Fake、Stub、Mock、Spy ​

“Mock 一切”会让测试只验证自己的 Mock 配置。先按用途选择替身：

类型用途Agent 示例
Stub返回预先安排的结果固定模型响应、固定检索结果
Fake有简化但可工作的实现内存向量库、内存 Checkpointer、Fake 支付服务
Mock验证一次交互是否发生高风险工具是否完全未调用
Spy使用真实逻辑并记录调用记录工具参数、调用顺序和次数
Record/Replay重放已脱敏的供应商响应模型、搜索 API、HTTP 工具契约回归

5.1 用 Protocol 定义你真正依赖的接口 ​

python
from dataclasses import dataclass
from typing import Protocol


@dataclass(frozen=True)
class SearchHit:
    document_id: str
    tenant: str
    content: str
    score: float


class Retriever(Protocol):
    def search(self, query: str, *, tenant: str, k: int) -> list[SearchHit]: ...


class FakeRetriever:
    def __init__(self, hits: list[SearchHit]) -> None:
        self.hits = hits
        self.calls: list[tuple[str, str, int]] = []

    def search(self, query: str, *, tenant: str, k: int) -> list[SearchHit]:
        self.calls.append((query, tenant, k))
        return [hit for hit in self.hits if hit.tenant == tenant][:k]

6. Record/Replay 不是永久真相 ​

真实模型和外部 API 有时只能用录制响应稳定回归。录制文件至少保存：

  • provider、model、API 版本和请求 Schema 版本；
  • 脱敏后的消息、Tool Schema 与响应；
  • finish reason、tool call ID、usage 和错误类型；
  • 录制日期与过期日期；
  • 哪些字段因随机性被规范化。
python
import json
from pathlib import Path
from typing import Any


def load_cassette(path: Path) -> dict[str, Any]:
    payload = json.loads(path.read_text(encoding="utf-8"))
    if payload["schema_version"] != 1:
        raise ValueError("unsupported cassette schema")
    if "authorization" in json.dumps(payload).lower():
        raise ValueError("cassette may contain credentials")
    return payload

Record/Replay 的局限：

  • 它证明你的适配器能处理一个旧响应，不证明供应商今天仍兼容；

7. 模型边界测试 ​

模型不可预测，但模型边界完全可以测试。至少覆盖四类输出：

  1. 正常文本；
  2. 合法结构化输出；
  3. 合法 Tool Call；
  4. 缺字段、错误类型、未知工具、重复 Tool Call 等畸形输出。

7.1 结构化输出先独立解析 ​

from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, ValidationError

    route: Literal["answer", "retrieve", "review"]
    confidence: float = Field(ge=0.0, le=1.0)


def parse_route(payload: object) -> RouteDecision:
    return RouteDecision.model_validate(payload)


def test_route_rejects_unknown_destination() -> None:

        parse_route({"route": "delete_database", "confidence": 1.0})
    except ValidationError:
        pass
    else:
        raise AssertionError("unknown route must be rejected")

7.2 Fake Model 驱动完整 Tool 循环 ​

python
import json

from langchain_core.language_models.fake_chat_models import (
    FakeMessagesListChatModel,
)
from langchain_core.messages import AIMessage, HumanMessage, ToolMessage
from pydantic import BaseModel, ConfigDict, Field


class OrderArguments(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    order_id: str = Field(pattern=r"^A\d{4}$")


def make_tool_then_answer_model() -> FakeMessagesListChatModel:
    return FakeMessagesListChatModel(
        responses=[
            AIMessage(
                content="",
                tool_calls=[
                    {
                        "name": "get_order",
                        "args": {"order_id": "A1024"},
                        "id": "call-1",
                        "type": "tool_call",
                    }
                ],
            ),
            AIMessage(content="Order A1024 has shipped."),
        ]
    )


def run_scripted_tool_loop(
    model: FakeMessagesListChatModel,
    *,
    max_steps: int = 4,
) -> tuple[str, list[object], set[str]]:
    messages: list[object] = [HumanMessage(content="Where is order A1024?")]
    executed_call_ids: set[str] = set()

    for _ in range(max_steps):
        reply = model.invoke(messages)
        messages.append(reply)
        if not reply.tool_calls:
            return str(reply.content), messages, executed_call_ids

        for call in reply.tool_calls:
            if call["name"] != "get_order":
                raise PermissionError("tool is not in this run's allowlist")
            call_id = call["id"]
            if call_id in executed_call_ids:
                raise RuntimeError("duplicate tool call id")
            arguments = OrderArguments.model_validate(call["args"])
            executed_call_ids.add(call_id)
            tool_result = {
                "order_id": arguments.order_id,
                "status": "shipped",
            }
            messages.append(
                ToolMessage(
                    content=json.dumps(tool_result),
                    tool_call_id=call_id,
                )
            )

    raise RuntimeError("tool loop exceeded max_steps")


answer, messages, executed = run_scripted_tool_loop(
    make_tool_then_answer_model()
)
tool_messages = [message for message in messages if isinstance(message, ToolMessage)]

assert answer == "Order A1024 has shipped."
assert executed == {"call-1"}
assert len(tool_messages) == 1
assert tool_messages[0].tool_call_id == "call-1"
assert '"status": "shipped"' in tool_messages[0].content

8.3 超时与错误分类 ​

from enum import StrEnum


class ToolFailure(StrEnum):
    TEMPORARY = "temporary"
    PERMANENT = "permanent"
    UNKNOWN_COMMIT = "unknown_commit"


class OperationKind(StrEnum):
    READ = "read"
    WRITE = "write"


def classify_tool_error(
    error: Exception,
    *,
    operation: OperationKind,
    request_may_have_reached_service: bool,
) -> ToolFailure:
    if isinstance(error, PermissionError):
        return ToolFailure.PERMANENT
    if isinstance(error, TimeoutError):
        if (
            operation is OperationKind.WRITE
            and request_may_have_reached_service
        ):
            return ToolFailure.UNKNOWN_COMMIT
        return ToolFailure.TEMPORARY
    return ToolFailure.UNKNOWN_COMMIT


def test_timeout_is_retryable_temporary_failure() -> None:
    assert classify_tool_error(
        TimeoutError(),
        operation=OperationKind.READ,
        request_may_have_reached_service=True,
    ) is ToolFailure.TEMPORARY


def test_write_timeout_after_send_is_unknown_commit() -> None:
    assert classify_tool_error(
        TimeoutError(),
        operation=OperationKind.WRITE,
        request_may_have_reached_service=True,

12. Reducer 测试：并行正确性的核心 ​

Reducer 不是“列表相加就行”。你必须定义结合顺序、去重、覆盖和上限。

12.1 自定义确定性 Reducer ​

python
from itertools import permutations

from pydantic import BaseModel, ConfigDict, Field, ValidationError


class EvidenceItem(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True, frozen=True)

    evidence_id: str = Field(min_length=1)
    score: float = Field(
        ge=0.0,
        le=1.0,
        allow_inf_nan=False,
    )


def merge_evidence(
    left: list[EvidenceItem],
    right: list[EvidenceItem],
) -> list[EvidenceItem]:
    by_id: dict[str, EvidenceItem] = {}
    for item in [*left, *right]:
        existing = by_id.get(item.evidence_id)
        if existing is None or item.score > existing.score:
            by_id[item.evidence_id] = item
    return sorted(by_id.values(), key=lambda item: (-item.score, item.evidence_id))


def test_reducer_is_stable_for_branch_completion_order() -> None:
    branches = [
        [EvidenceItem(evidence_id="a", score=0.80)],
        [EvidenceItem(evidence_id="b", score=0.90)],
        [EvidenceItem(evidence_id="a", score=0.75)],
    ]

    outcomes = []
    for order in permutations(branches):
        merged: list[EvidenceItem] = []
        for update in order:
            merged = merge_evidence(merged, update)
        outcomes.append(merged)

    assert all(outcome == outcomes[0] for outcome in outcomes)
    assert [item.evidence_id for item in outcomes[0]] == ["b", "a"]
    assert outcomes[0][1].score == 0.80


def test_evidence_score_rejects_non_finite_and_out_of_range() -> None:
    for invalid_score in (float("nan"), float("inf"), -0.01, 1.01):
        try:
            EvidenceItem(evidence_id="bad", score=invalid_score)
        except ValidationError:
            pass
        else:
            raise AssertionError(f"score must be rejected: {invalid_score}")

NaN 尤其危险：它与任何数比较都为假。若 Reducer 接受 NaN，item.score > existing.score 会重新依赖分支完成顺序，看似确定性的“取最高分”又变成不稳定结果。因此，边界校验不仅要检查 0 <= score <= 1，还必须显式拒绝 NaN 和无穷值。

  • 结合性：分组合并不改变结果；

  • 不修改输入：不会原地篡改其他分支持有的对象。

16. 幂等与并发测试 ​

单线程重放通过，不代表并发安全。生产幂等实现至少要验证：

  • 20 个相同请求同时到达，只创建一项业务记录；
  • 相同 Key、不同 Payload 中只有一个成功，其余冲突；
  • 进程重启后仍能识别重放；
  • 锁超时、事务回滚和唯一约束冲突被正确映射；
  • 下游调用也携带稳定幂等键。

至少维护：

  • Happy path：最常见成功任务；
  • Boundary：0、1、最大值、预算刚好耗尽；
  • Invalid：缺字段、错类型、未知枚举、额外字段；
  • Adversarial：Prompt Injection、越权、工具参数污染；
  • Recovery：超时、限流、未知提交、Checkpoint 故障；
  • Historical regression：每个线上事故最小化后的复现用例。

禁止直接复制生产 PII。样本要脱敏或合成，同时保留触发问题的结构特征。

17.3 用稳定 ID，不用随机断言 ​

测试可以生成唯一 thread_id 避免互相污染，但不要断言随机 UUID 的具体值。断言格式、关联关系和唯一性即可。

18. 失败路径矩阵 ​

每个外部边界按阶段整理失败，而不是只测一个 except Exception：

阶段失败应验证
输入Schema 不合法未调用模型和工具
模型超时/限流有界重试、记录分类
模型畸形 Tool Call拒绝或修复次数有上限
工具权限不足无副作用、稳定错误码
工具未知提交查询权威状态，不盲重试
检索空结果明确 no_evidence/改写路径
检索跨租户结果立即阻断并产生安全事件
图Router 未知目标编译/运行前拒绝
图循环无进展no_progress 终态
持久化Checkpoint 不可用不伪装成功，恢复策略明确
人工审批过期/参数变化拒绝执行高风险工具

一个高质量测试不仅断言“抛错”，还断言：错误类型、状态是否可恢复、调用次数、是否产生副作用、Trace 是否脱敏。

20. 怎样避免 Flaky Test ​

常见不稳定来源：

  • 调用真实模型却断言精确文本；
  • 使用真实时间和 sleep()；
  • 并行分支断言固定完成顺序；
  • 测试共享全局内存 Store；
  • 复用相同 thread_id 或幂等键；
  • 依赖网络、供应商限流或未锁定模型别名；
  • 向量相似度断言过细浮点值；
  • 测试间依赖执行顺序。

处理方法：

  • 注入 Clock，并固定 now；
  • 为每个测试创建新 Fake/Store；
  • 使用唯一作用域 ID；
  • 并行结果断言集合，只有业务有序时才断言列表；
  • 浮点数使用容差，但排序契约仍要明确；
  • 真实模型测试单独 Marker，不进入快速单元层；
  • 失败后先找非确定性根因，不直接加重试掩盖。

23. 常见错误 ​

23.1 只测最终文本 ​

问题：无法定位模型、检索、工具还是路径错误。修复：断言结构化终态、轨迹、引用、调用和副作用。

23.2 所有测试都调用真实模型 ​

问题：慢、贵、易漂移、难覆盖畸形输出。修复：大多数分支用 Fake，少量锁定模型契约独立运行。

23.3 Mock 框架内部实现 ​

问题：升级 LangChain/LangGraph 后大量无意义破裂。修复：Mock 自己的 Port/Adapter，验证公开输入输出。

23.4 只测正常路径 ​

问题：生产事故集中在超时、重试、恢复和权限。修复：维护失败路径矩阵，每个外部边界至少一个失败用例。

23.5 用覆盖率代替质量 ​

问题：执行过代码不代表断言业务结果。修复：每个测试写明契约和故障模型，覆盖率只用于发现完全未触达区域。

23.6 Snapshot 整个 Prompt 或 State ​

问题：任意文字调整都造成噪声，敏感数据也可能入库。修复：只 Snapshot 稳定 Schema 或规范化后的关键消息结构。

23.7 内存 Fake 通过就宣称生产安全 ​

问题：没有验证事务、进程重启和并发。修复：明确教学边界，并补真实基础设施集成测试。

23.8 Flaky 后直接加重试 ​

问题：掩盖竞态和共享状态。修复：固定时钟、隔离依赖、移除真实网络，找出不确定来源。

24. 实战练习 ​

练习一：模型畸形输出 ​

为路由模型构造五个响应：合法回答、合法 Tool Call、未知工具、缺少参数、重复 call ID。断言未知或畸形调用不会执行工具，循环在预算内结束。

练习二：RAG 租户隔离 ​

向测试索引写入两个租户的同主题文档。分别查询并证明结果、上下文和引用中都没有跨租户 ID；再检查过滤确实下推到向量库查询。

练习三：Reducer 性质 ​

实现带去重和 Top-K 的 Evidence Reducer。测试结合性、交换顺序、重复更新、相同分数和最多 20 项限制。

练习四：人在回路 ​

扩展退款图，覆盖批准、拒绝、超时、跨租户、旧版本和重复 Resume。所有拒绝路径都应断言 commit_count == 0。

练习五：故障恢复 ​

在工具“已提交但响应丢失”处注入故障。恢复后先按幂等键查询权威状态，不能再次创建业务记录。

练习六：并发幂等 ​

用 PostgreSQL 唯一约束实现 Durable Registry，20 个线程并发相同 Key。断言只有一条业务记录；相同 Key 的不同 Payload 必须返回冲突。

练习七：历史回归 ​

选择一次真实缺陷，脱敏并缩成最小 Case。先证明旧代码失败，再修复并把 Case 永久加入快速测试集。
