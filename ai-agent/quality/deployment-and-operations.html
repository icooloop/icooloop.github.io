部署与运维 ​

本地运行一个 Agent，只需要 Python 进程和 API Key；生产系统还必须面对多实例、数据库迁移、Worker 崩溃、模型限流、灰度发布、旧 Checkpoint 恢复、Secret 轮换、备份恢复和事故处置。

部署不是把代码塞进 Docker 就结束。真正的交付目标是：

text
同一份经过测试的 Artifact
  + 可验证配置
  + 外部持久状态
  + 受控迁移
  + 版本化工作流
  + 健康检查与可观测性
  + 灰度/回滚策略
  + 恢复演练
= 可运营 Agent 服务

学完后，你应该能够：

  • 划分 API、Agent Worker、Queue、数据库、Redis、对象存储和审批服务；
  • 构建不可变、非 Root、可复现的容器镜像；
  • 使用环境配置与 Secret 管理，不把凭据写入镜像；
  • 区分 Liveness、Readiness、Startup 和业务依赖健康；
  • 设计数据库、Checkpoint、Store 和业务 Schema 迁移；
  • 为长运行 Thread 绑定 Graph Version；
  • 使用 Rolling、Canary、Blue/Green、Shadow 和 Feature Flag；
  • 明确回滚不能撤销外部副作用；
  • 建立 SLO、Error Budget、Runbook、备份与灾难恢复演练。

IMPORTANT

当前环境验证了 Python 代码、langgraph==1.2.9、pydantic-settings==2.14.2 和内存运行时契约。FastAPI、Docker Engine、PostgreSQL、Redis、Kubernetes、CI 平台、远程 Secret Manager 与持久 Checkpointer 没有在本机组成一套部署环境，因此相关清单和配置是生产基线，不是“已上线”声明。资料能力边界截至 2026-07-13。

不要让 API 进程同时承担所有长任务：

  • HTTP 连接断开不应取消任务；
  • Web Pod 扩缩容不应丢失状态；
  • 长任务需要 Queue、Lease、Heartbeat、Retry 和 Dead Letter；
  • Worker 必须能从持久状态恢复；
  • 任务状态与业务副作用需要权威记录。

小型内部工具可以同进程起步，但接口、任务和状态边界仍应先设计好，避免以后无法拆分。

2. 进程与所有权 ​

2.1 API ​

负责：认证、Schema、幂等接收、限流、创建任务、查询状态、流式事件、取消请求。API 不直接持有长期内存状态。

2.2 Worker ​

负责：恢复 Graph、执行 Node、调用依赖、写 Checkpoint、心跳和终态。Worker 必须带 Graph Version，并在失去 Lease 后停止副作用。

2.3 Scheduler/Queue ​

负责：投递、延时、租约、重试、优先级和死信。Queue 不应成为唯一业务状态库。

2.4 数据库 ​

业务数据库保存订单、退款和审批等权威状态；Checkpointer 保存 Graph 恢复状态；Store 保存跨 Thread 记忆。职责不能混为一个 JSON 字段。

3. 配置管理 ​

配置分三类：

类型示例处理
非敏感静态配置环境名、Graph Version、超时环境变量/配置文件
SecretAPI Key、数据库凭据、签名密钥Secret Manager/挂载文件
动态业务策略模型路由、租户配额、Feature Flag版本化配置服务/数据库

使用 Pydantic Settings 做启动时校验：

python
from typing import Literal

from pydantic import Field, SecretStr, model_validator
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_prefix="AGENT_",
        env_file=None,
        extra="ignore",
    )

    environment: Literal["development", "staging", "production"]
    graph_version: str = Field(pattern=r"^[a-z0-9][a-z0-9._-]+$")
    database_url: SecretStr = Field(min_length=1)
    redis_url: str = Field(min_length=1)
    model_api_key: SecretStr = Field(min_length=1)
    max_parallel_tasks: int = Field(ge=1, le=200)
    request_timeout_seconds: float = Field(gt=0, le=300)
    tracing_enabled: bool = True
    allow_debug_payloads: bool = False

    @model_validator(mode="after")
    def production_safety(self) -> "Settings":
        if not self.database_url.get_secret_value().strip():
            raise ValueError("database_url must not be blank")
        if not self.redis_url.strip():
            raise ValueError("redis_url must not be blank")
        if not self.model_api_key.get_secret_value().strip():
            raise ValueError("model_api_key must not be blank")
        if self.environment == "production" and self.allow_debug_payloads:
            raise ValueError("debug payloads are forbidden in production")
        return self

4. Secret 生命周期 ​

Secret 管理包括：

  1. 创建与授权；
  2. 注入到运行环境；
  3. 进程内最小暴露；
  4. 日志/Trace 脱敏；
  5. 定期与紧急轮换；
  6. 吊销旧版本；
  7. 访问审计；
  8. 泄露响应。

禁止：

  • 写进 Git、Dockerfile 或镜像 Layer；
  • 放进前端构建；
  • 作为命令行参数出现在进程列表；
  • 记录到异常、Trace 和测试快照；
  • 多环境复用同一个生产 Key；
  • 把个人开发 Key 当服务身份。

7. 健康检查 ​

7.1 Liveness ​

回答“进程是否活着、事件循环是否还能响应”。不要因为模型供应商临时失败就杀死所有 Pod，否则会形成重启风暴。

7.2 Readiness ​

回答“当前实例能否接收新任务”。必需数据库不可用、迁移未完成、Queue 连接失败或实例正在排空时应 Not Ready。

7.3 Startup ​

给慢启动过程更长窗口，例如加载模型、预热索引或完成迁移检查，避免 Liveness 过早杀死进程。

7.4 Degraded ​

可选依赖失败时仍可 Readiness=True，但 API 应暴露降级状态，并阻止依赖该能力的路由。

python
from http import HTTPStatus

from pydantic import BaseModel


class Dependency(BaseModel):
    name: str
    required: bool
    healthy: bool


def readiness(
    dependencies: list[Dependency],
    *,
    draining: bool,
) -> tuple[int, dict[str, object]]:
    failed = [item.name for item in dependencies if not item.healthy]
    required_failed = any(
        item.required and not item.healthy for item in dependencies
    )
    ready = not draining and not required_failed
    body: dict[str, object] = {
        "live": True,
        "ready": ready,
        "draining": draining,
        "degraded": bool(failed),
        "failed_dependencies": failed,
    }
    status_code = HTTPStatus.OK if ready else HTTPStatus.SERVICE_UNAVAILABLE
    return int(status_code), body

8. 优雅关闭 ​

发布或缩容时：

  1. 实例进入 Not Ready；
  2. API 停止接收新任务；
  3. Worker 停止获取新 Lease；
  4. 在途安全点写 Checkpoint；
  5. 可完成的幂等操作在 Grace Period 内结束；
  6. 长任务释放 Lease，由其他 Worker 恢复；
  7. Flush Trace/Log；
  8. 关闭连接池；
  9. 超时后强制退出并告警。

不应在 SIGTERM 时盲目等待所有人工审批完成。

9. 数据库与迁移 ​

至少有四类迁移：

  • 业务表；
  • Task/Approval/Audit 表；
  • LangGraph Checkpointer/Store；
  • Vector Index 与 Embedding 数据版本。

使用 Expand/Contract：

text

Release B: deploy code that writes old + new fields and still reads old
Backfill: copy historical rows in bounded batches with restart checkpoints
Verify: compare counts, null rate, checksums and sampled business invariants
Release C: switch reads to new field while dual-write continues
Release D: stop old writes after the rollback window
Release E: remove old field only after every old worker is retired

11. 长 Thread 的版本粘性 ​

危险场景：

text
Thread 在 graph-v1 的 approval 节点暂停
  -> 发布 graph-v2，删除/重命名节点
  -> Resume 被随机路由到 v2 Worker
  -> 无法恢复或执行错误路径
1
2
3
4

解决方案：

  • Task/Thread 创建时写入 graph_version；
  • Queue 根据版本路由 Worker；
  • 在最长 Thread 生命周期内保留兼容 Worker；
  • 或执行显式 State/Checkpoint 迁移；
  • 新版本先验证旧 Fixture；
  • 退役旧 Worker 前确认无活跃 Thread。

不要让负载均衡器随机决定恢复版本。

13. 发布策略 ​

13.1 Rolling ​

逐步替换实例，资源成本低。要求版本兼容、Readiness 和优雅关闭可靠。

13.2 Blue/Green ​

新旧环境并存，切流和回滚快，但数据库与外部副作用仍共享，迁移必须兼容。

13.3 Canary ​

按稳定哈希把一小部分新 Task 分配给新版本。已有 Thread 继续旧版本。比较质量、安全、延迟、成本和错误率。

13.4 Shadow ​

复制请求给新版本但不执行外部副作用，结果不返回用户。适合比较路径和答案；必须脱敏并控制双倍模型成本。

13.5 Feature Flag ​

用于独立开关模型、Retriever、Tool 或策略。Flag 自身要版本化、审计并有默认安全值。

14. 回滚的真实边界 ​

代码回滚不能自动撤销：

  • 已退款、已发邮件或已创建工单；
  • 已写入的新 Schema 数据；
  • 已迁移的 Checkpoint；
  • 已构建的新 Embedding Index；
  • 已泄露的 Secret；
  • 已发送到第三方 Trace 的数据。

因此发布前要有 Forward/Backward Compatibility、幂等、补偿和 Feature Flag。必要时“停止新任务 + 保持旧 Worker + 前滚修复”比直接回滚安全。

15. 完整离线实现：灰度、版本粘性与门禁 ​

python
from __future__ import annotations

import hashlib
from dataclasses import dataclass
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field


class ReleaseMetrics(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        strict=True,
        allow_inf_nan=False,
    )

    sample_size: int = Field(ge=1)
    success_rate: float = Field(ge=0, le=1)
    safety_violations: int = Field(ge=0)
    duplicate_side_effects: int = Field(ge=0)
    p95_active_ms: int = Field(ge=0)
    cost_per_success_usd: float = Field(ge=0)
    old_checkpoint_pass_rate: float = Field(ge=0, le=1)


class ReleasePolicy(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        strict=True,
        allow_inf_nan=False,
    )

    min_sample_size: int = Field(ge=1)
    min_success_rate: float = Field(ge=0, le=1)
    max_p95_active_ms: int = Field(ge=1)
    max_cost_per_success_usd: float = Field(gt=0)
    require_old_checkpoint_pass_rate: float = Field(ge=0, le=1)
    max_success_rate_drop: float = Field(default=0.01, ge=0, le=1)
    max_p95_active_ms_increase_ratio: float = Field(default=0.10, ge=0)
    max_cost_per_success_increase_ratio: float = Field(default=0.10, ge=0)


class ReleaseDecision(BaseModel):
    action: Literal["hold", "promote", "rollback"]
    reasons: list[str]


def decide_release(
    metrics: ReleaseMetrics,
    policy: ReleasePolicy,
    *,
    baseline: ReleaseMetrics | None = None,
) -> ReleaseDecision:
    hard_failures: list[str] = []
    if metrics.safety_violations:
        hard_failures.append("safety_violation")
    if metrics.duplicate_side_effects:
        hard_failures.append("duplicate_side_effect")
    if metrics.old_checkpoint_pass_rate < policy.require_old_checkpoint_pass_rate:
        hard_failures.append("checkpoint_incompatible")
    if hard_failures:
        return ReleaseDecision(action="rollback", reasons=hard_failures)

    if metrics.sample_size < policy.min_sample_size:
        return ReleaseDecision(action="hold", reasons=["insufficient_sample"])

    regressions: list[str] = []
    if metrics.success_rate < policy.min_success_rate:
        regressions.append("success_rate")
    if metrics.p95_active_ms > policy.max_p95_active_ms:
        regressions.append("latency")
    if metrics.cost_per_success_usd > policy.max_cost_per_success_usd:
        regressions.append("cost")
    if regressions:
        return ReleaseDecision(action="hold", reasons=regressions)

    if baseline is None:
        return ReleaseDecision(action="hold", reasons=["baseline_required"])
    if baseline.sample_size < policy.min_sample_size:
        return ReleaseDecision(
            action="hold",
            reasons=["insufficient_baseline_sample"],
        )

    baseline_regressions: list[str] = []
    if (
        metrics.success_rate
        < baseline.success_rate - policy.max_success_rate_drop
    ):
        baseline_regressions.append("success_rate_regression")
    if metrics.p95_active_ms > baseline.p95_active_ms * (
        1 + policy.max_p95_active_ms_increase_ratio
    ):
        baseline_regressions.append("latency_regression")
    if metrics.cost_per_success_usd > baseline.cost_per_success_usd * (
        1 + policy.max_cost_per_success_increase_ratio
    ):
        baseline_regressions.append("cost_regression")
    if baseline_regressions:
        return ReleaseDecision(action="hold", reasons=baseline_regressions)
    return ReleaseDecision(action="promote", reasons=["all_gates_passed"])


def stable_bucket(identity: str, *, buckets: int = 10_000) -> int:
    if buckets < 1:
        raise ValueError("buckets must be positive")
    digest = hashlib.sha256(identity.encode("utf-8")).digest()
    return int.from_bytes(digest[:8], "big") % buckets


@dataclass
class VersionRouter:
    stable_version: str
    candidate_version: str
    canary_percent: float
    thread_versions: dict[str, str]

    def assign_new_thread(self, thread_id: str) -> str:
        if not 0 <= self.canary_percent <= 100:
            raise ValueError("canary_percent must be in [0, 100]")
        existing = self.thread_versions.get(thread_id)
        if existing is not None:
            return existing
        threshold = int(self.canary_percent * 100)
        version = (
            self.candidate_version
            if stable_bucket(thread_id) < threshold
            else self.stable_version
        )
        self.thread_versions[thread_id] = version
        return version

    def resume_thread(self, thread_id: str) -> str:
        try:
            return self.thread_versions[thread_id]
        except KeyError as exc:
            raise LookupError("thread version is unknown") from exc


def main() -> None:
    policy = ReleasePolicy(
        min_sample_size=100,

关键点：

  • 安全、重复副作用和 Checkpoint 兼容是硬门槛；
  • 候选或基线样本不足只 Hold，不因几次成功直接全量；
  • 绝对门槛通过后仍要比较基线成功率、延迟和单位成功成本；
  • 缺少基线时保持 Hold，不能把“没有比较数据”解释成没有回退；
  • Thread 首次分配后保存版本；
  • 调整 Canary 比例不会改变已有 Thread；
  • 稳定哈希让同一新任务分流可复现。

生产中 thread_versions 必须是持久、事务化记录，内存字典只用于教学。

16. 扩缩容 ​

分别扩缩：

  • API：按请求率、CPU、连接；
  • Worker：按 Queue Depth、最老任务年龄、活跃 Lease、模型限流；
  • Retrieval Worker：按查询延迟与连接池；
  • Ingestion Worker：按文档积压和 Embedding 配额。

不要只按 CPU 扩 Agent Worker。大量任务可能在等待模型，CPU 很低但 Queue 已经积压。

Scale Down 前必须 Drain，确认 Lease 和 Checkpoint 安全转移。设置最大并发以避免扩容后瞬间击穿模型或数据库。

17. 可靠性模式 ​

Timeout ​

入口 Deadline 向下游递减；模型、工具、数据库分别有连接和调用超时。

Retry ​

只重试临时错误和幂等操作。限制次数、指数退避、Jitter 和总预算。

Circuit Breaker ​

依赖持续失败时快速拒绝或降级，避免每个任务等待完整超时。

Bulkhead ​

按租户、工具或模型隔离并发池，避免一个热点拖垮全部任务。

Idempotency ​

Key 必须绑定业务指纹；未知提交先查权威状态。

Dead Letter ​

保存失败分类、Attempt、版本和恢复入口，不能把 Secret 和完整敏感 State 直接塞进消息。

20. 事故响应 ​

20.1 准备 ​

Owner、On-call、严重级别、告警、Runbook、权限、沟通渠道和演练。

20.2 处置 ​

  1. 确认影响、租户、版本和安全范围；
  2. 阻止扩大：Flag、限流、禁用 Tool、暂停新任务；
  3. 保存 Trace、Audit 和版本证据；
  4. 选择回滚、降级或前滚；
  5. 核对外部副作用与待补偿任务；
  6. 恢复并验证 SLI；
  7. 通知相关方。

20.3 复盘 ​

无责分析时间线、根因、检测缺口、处置效果和长期动作。把真实失败脱敏后加入评测与故障注入集。

21. 安全运维 ​

  • 网络默认拒绝，仅开放必要 Egress；
  • 服务身份最小权限；
  • 工具和数据源按租户隔离；
  • 容器只读、非 Root、资源限制；
  • 依赖锁定、来源验证、SBOM 和漏洞处置；
  • Secret 轮换和泄露演练；
  • Trace、Log、Artifact 的访问与保留；
  • 管理接口独立鉴权；
  • 审批与高风险操作保留不可变审计。

23. 常见错误 ​

把迁移放到每个 Pod 启动 ​

多个实例可能同时迁移。使用独立、受控、幂等的 Migration Job。

Readiness 永远返回 200 ​

流量会进入尚未完成迁移或已在 Drain 的实例。

新版本随机恢复旧 Thread ​

Graph 拓扑变化导致失败。使用 Version Sticky 与兼容 Worker。

回滚代码等于回滚业务 ​

外部副作用不会消失。需要幂等、补偿与审计。

自动扩容没有下游上限 ​

新增 Worker 会同时打满模型和数据库。并发预算必须端到端一致。

有备份但从未恢复 ​

无法知道密钥、权限、迁移和索引是否可用。必须做 Restore Drill。

在镜像里放 Secret ​

即使后续删除，旧 Layer 仍可能保留。Build 不接触生产 Secret。
