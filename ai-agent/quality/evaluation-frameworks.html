评测框架 ​

上一页已经建立案例、指标、Judge 校准和发布门禁。本页解决工程落地问题：这些逻辑分别放在哪里，用什么工具运行，如何保存结果，哪些能力已经在本项目验证。

先给结论：不要寻找一个“包办全部质量问题”的评测框架。 更可靠的组合是：

1. 先按职责选择工具 ​

工具主要职责最适合不能证明
unittest标准库测试运行器零额外依赖、离线单元/集成测试模型回答语义质量
pytest测试运行器与插件生态fixture、参数化、标记、丰富报告线上分布与业务价值
LangSmithLLM 应用可观测与评测平台Trace、数据集、实验、反馈你的业务权限天然正确
RagasRAG 评测指标库Faithfulness、Context 等语义指标工具幂等、审批与租户隔离
DeepEvalLLM 测试/指标候选框架用例、指标和 CI 风格集成无校准 Judge 就可信

选择顺序应是：

  1. 先明确评测合同与金标；
  2. 用普通 Python 实现业务硬约束；
  3. 选 unittest 或 pytest 运行快速回归；
  4. 需要实验管理与 Trace 时接 LangSmith；
  5. 需要语义指标时评估 Ragas 或 DeepEval；
  6. 最终门禁仍由你的业务规则决定。

框架能降低执行和管理成本，不能替你定义“什么是正确”。

3. 共同核心：框架无关的评测函数 ​

无论最后用哪个框架，业务检查都应是普通 Python 函数：

python
from dataclasses import dataclass


@dataclass(frozen=True)
class ExpectedTrace:
    final_status: str
    required_tools: frozenset[str]
    forbidden_tools: frozenset[str]
    max_steps: int


@dataclass(frozen=True)
class ActualTrace:
    final_status: str
    tool_calls: tuple[str, ...]
    steps: int


@dataclass(frozen=True)
class MetricResult:
    key: str
    score: float
    detail: str


def final_status_metric(
    expected: ExpectedTrace,
    actual: ActualTrace,
) -> MetricResult:
    passed = actual.final_status == expected.final_status
    return MetricResult(
        key="final_status",
        score=float(passed),
        detail=(
            f"expected={expected.final_status}, "
            f"actual={actual.final_status}"
        ),
    )


def forbidden_tool_metric(
    expected: ExpectedTrace,
    actual: ActualTrace,
) -> MetricResult:
    used = sorted(expected.forbidden_tools & set(actual.tool_calls))
    return MetricResult(
        key="forbidden_tools",
        score=float(not used),
        detail="ok" if not used else f"used={used}",
    )

4.1 正常与违规路径 ​

python
import unittest


class MetricTests(unittest.TestCase):
    def setUp(self) -> None:
        self.expected = ExpectedTrace(
            final_status="waiting_approval",
            required_tools=frozenset(
                {"get_order", "create_refund_draft"}
            ),
            forbidden_tools=frozenset({"submit_refund"}),
            max_steps=4,
        )

    def test_expected_trace_passes(self) -> None:
        actual = ActualTrace(
            final_status="waiting_approval",
            tool_calls=("get_order", "create_refund_draft"),
            steps=3,
        )

        self.assertEqual(
            final_status_metric(self.expected, actual).score,
            1.0,
        )
        self.assertEqual(
            forbidden_tool_metric(self.expected, actual).score,
            1.0,
        )

    def test_forbidden_submit_fails(self) -> None:
        actual = ActualTrace(
            final_status="completed",
            tool_calls=("get_order", "submit_refund"),
            steps=2,
        )

        result = forbidden_tool_metric(self.expected, actual)

        self.assertEqual(result.score, 0.0)
        self.assertIn("submit_refund", result.detail)


if __name__ == "__main__":
    unittest.main()

from collections.abc import Awaitable, Callable


async def run_with_timeout(
    operation: Callable[[], Awaitable[str]],
    *,
    seconds: float,

6. unittest 与 pytest 如何选择 ​

情况建议
教程、库、最小依赖unittest
已有大量 unittest继续运行；pytest 能收集多数用例
fixture 和参数表很多评估 pytest
需要特定报告/并行插件pytest，但锁定插件版本
仅为了几个 assert不必迁移

两者都只是运行器。测试质量取决于断言、Fake、失败路径和数据覆盖，而不是测试函数前缀。

7. LangSmith：Trace 与实验平台 ​

LangSmith 在这套体系中负责：

  • 记录 LangChain/LangGraph/自定义代码运行树；
  • 管理远程评测数据集和 Example；
  • 对同一数据集运行 Experiment；
  • 绑定确定性或模型 Evaluator；
  • 对比不同 Prompt、模型、图和索引版本；
  • 汇集线上反馈和抽样评测。

7.1 已验证的本地边界 ​

项目示例：

python
from langsmith import traceable, tracing_context


@traceable(name="deterministic_agent_evaluation", run_type="chain")
def traced_metric(
    expected: ExpectedTrace,
    actual: ActualTrace,
) -> dict[str, object]:
    result = forbidden_tool_metric(expected, actual)
    return {
        "key": result.key,
        "score": result.score,
        "detail": result.detail,

expected = ExpectedTrace(
    final_status="waiting_approval",

actual = ActualTrace(
    final_status="waiting_approval",

    steps=1,

7.2 远程 Experiment 的接入形状 ​

以下代码需要 LANGSMITH_API_KEY、网络、已创建数据集和经过治理的输入。项目没有执行：

python
# Remote integration shape for langsmith==0.10.2; not run here.
from langsmith import Client


def target(inputs: dict[str, object]) -> dict[str, object]:
    return run_agent(str(inputs["question"]))


def forbidden_tool_evaluator(run, example) -> dict[str, object]:
    outputs = run.outputs or {}
    tools = set(outputs.get("tool_calls", []))
    forbidden = set((example.outputs or {}).get("forbidden_tools", []))
    violations = sorted(tools & forbidden)
    return {
        "key": "forbidden_tools",
        "score": float(not violations),
        "comment": "ok" if not violations else str(violations),
    }


client = Client()
experiment = client.evaluate(
    target,
    data="refund-agent-regression-v3",
    evaluators=[forbidden_tool_evaluator],
    experiment_prefix="candidate-graph-v8",
    metadata={
        "graph_version": "v8",
        "prompt_version": "refund-v12",
        "dataset_version": "v3",
    },
    max_concurrency=4,
)

7.3 LangSmith 不是业务规则引擎 ​

LangSmith 可以执行 Evaluator，但不会自动知道：

  • 哪个租户能看哪份文档；
  • 哪个金额必须由谁审批；
  • 哪个工具有不可逆副作用；
  • 什么状态转换在你的领域合法；
  • 哪种投诉代表任务真正失败。

这些规则必须由你的代码、数据和专家定义。

8.2 先做小型资格测试 ​

  1. 选择 30 至 100 个专家已标注案例；
  2. 包含正确、部分支持、矛盾、无答案和跨租户案例；
  3. 运行候选指标；
  4. 比较人工标签与指标；
  5. 统计 False Pass、False Fail 和重复稳定性；
  6. 检查中文、长上下文和领域术语偏差；
  7. 记录成本与吞吐；
  8. 通过后再纳入 CI 或批量实验。

Ragas 分数不能替代相关文档金标的 Recall@K，也不能检查审批、幂等和权限。

如何进入 CI快速/慢速分层、失败是否阻止发布
如何防止双重真值指标定义与现有报表如何统一

“框架有很多内置指标”不是采用理由。无法解释、无法校准的指标越多，质量系统越难维护。

10. 统一适配层 ​

不要让业务代码分别依赖多个框架的结果对象。定义内部协议：

12. 分层执行策略 ​

层级触发内容目标
L0每次保存/提交Schema、纯函数、Fake秒级
L1每个 PR组件、图路径、固定回归集分钟级
L2合并前/定时真实模型、向量库、Judge受控成本
L3发布前全量 Test/Challenge、故障演练发布结论
L4线上抽样评测、反馈、漂移持续监控

快速层不应访问网络；模型层需要显式凭据、预算、超时和最大并发。每一层都必须保存配置指纹。

12.1 一个框架无关的门禁入口 ​

python
from pydantic import BaseModel, ConfigDict, Field, ValidationError, model_validator


class GateSummary(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True, frozen=True)

    total: int = Field(ge=0)
    passed: int = Field(ge=0)
    safety_violations: int = Field(ge=0)
    p95_latency_ms: int = Field(ge=0)

    @model_validator(mode="after")
    def validate_counts(self) -> "GateSummary":
        if self.passed > self.total:
            raise ValueError("passed must not exceed total")
        return self


def gate_failures(summary: GateSummary) -> list[str]:
    if summary.total <= 0:
        return ["empty_dataset"]

    failures: list[str] = []
    if summary.passed / summary.total < 0.95:
        failures.append("pass_rate_below_0.95")
    if summary.safety_violations:
        failures.append("safety_violation")
    if summary.p95_latency_ms > 2_000:
        failures.append("p95_latency_exceeded")
    return failures


assert gate_failures(
    GateSummary(
        total=100,
        passed=98,
        safety_violations=0,
        p95_latency_ms=1_500,
    )
) == []

assert gate_failures(
    GateSummary(
        total=100,
        passed=99,
        safety_violations=1,
        p95_latency_ms=1_000,
    )
) == ["safety_violation"]

try:
    GateSummary(
        total=100,
        passed=101,
        safety_violations=0,
        p95_latency_ms=1_000,

except ValidationError:
    pass
else:
    raise AssertionError("invalid gate counts must be rejected")

13. Record/Replay 与成本控制 ​

评测真实模型和工具昂贵且有波动，可保存经过脱敏的交互用于离线 Replay：

python
import json
from dataclasses import dataclass
from pathlib import Path


@dataclass(frozen=True)
class RecordedCall:
    request_fingerprint: str
    response: dict[str, object]
    provider: str
    model: str


class ReplayStore:
    def __init__(self, path: Path) -> None:
        payload = json.loads(path.read_text(encoding="utf-8"))
        self._records = {
            item["request_fingerprint"]: RecordedCall(**item)
            for item in payload
        }

    def get(self, fingerprint: str) -> dict[str, object]:
        try:
            return self._records[fingerprint].response
        except KeyError as error:
            raise LookupError(f"no recording: {fingerprint}") from error

14. 评测器也要测试 ​

评测代码错误会给整个系统发错误结论。至少测试：

  • 空数据集会失败，而不是除零；
  • 缺少候选案例会失败，而不是静默忽略；
  • 重复 case_id 会被拒绝；
  • 指标边界限制在预期范围；
  • 安全违规不会被平均分抵消；
  • Judge 解析失败有明确错误类别；
  • 超时、限流与重试不会重复计数；
  • 结果保存失败不会被误报为评测通过；
  • Evaluator 版本会写入每条记录。

示例：

python
class GateTests(unittest.TestCase):

16. 常见错误 ​

把平台当成质量定义 ​

平台展示分数，业务专家和工程契约定义分数含义。

同时接入多个重叠框架 ​

如果没有统一结果模型，同一个“忠实性”可能有不同定义、Judge 和量纲，报表无法比较。

未校准就信任内置指标 ​

指标名字相同不代表适合中文、你的领域和风险阈值。

CI 临时安装最新版 ​

依赖和评分行为可能在两次运行之间改变。候选也必须锁版本。

只保存平均分 ​

没有 per-case 明细、Trace 与配置指纹，就不能归因或重现。

将模型波动当作测试不稳定而忽略 ​

先区分系统缺陷、供应商波动和 Judge 波动；用多次运行与切片记录，不要长期标记为允许失败。
