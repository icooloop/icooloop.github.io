RAG 评测与生产 ​

一个 RAG Demo 回答对三个问题，不代表它可以上线。生产质量必须能区分：正确证据是否被召回、无关证据是否挤入上下文、模型是否忠于证据、引用是否真的支持结论，以及新索引或 Prompt 是否造成回归。

本章建立下面的质量闭环：

text
真实失败与业务需求
  -> 版本化离线数据集
  -> 检索/生成/引用分阶段评测
  -> 发布质量门禁
  -> 灰度与影子流量
  -> Trace、指标、反馈和告警
  -> 归因后的新案例回流数据集

1. RAG 评测必须拆成阶段 ​

text
文档接入 -> Chunk/索引 -> 检索 -> Rerank -> Context -> 生成 -> 引用校验
1
阶段核心问题主要指标
接入权威文档是否完整、可追溯解析成功率、缺页/表率、版本覆盖
检索相关证据是否进入 Top-KRecall@K、Precision@K、MRR、nDCG
Rerank最佳证据是否排到前面MRR、nDCG、Top-1 命中
Context交给模型的内容是否相关且授权Context Relevance、权限违规率
生成结论是否由上下文支持Faithfulness、答案完整性、拒答正确率
引用引用是否存在且支持对应声明Citation Validity、Citation Correctness
系统是否满足服务目标P50/P95 延迟、错误率、成本、吞吐

只看最终答案会丢失归因：答案错可能因为没召回，也可能因为正确证据已经在 Top-1、模型仍然编造。

2.1 案例来源 ​

  • 真实用户问题，脱敏并获得允许；

3. 相关性标注 ​

相关不是“出现相同关键词”。先写标注指南：

  • 文档是否直接包含回答所需事实；
  • 是完整支持还是部分支持；
  • 是否属于当前版本；
  • 当前主体是否有权访问；
  • 冲突文档如何标记；
  • 多文档问题需要哪些证据组合。

二元标注适合 Recall/Precision；多级标注适合 nDCG：

text
0 = 不相关
1 = 有背景帮助但不能支持答案
2 = 部分支持
3 = 直接、完整支持
1
2
3
4

高风险数据应由至少两名标注者复核并记录裁决。模型生成的相关性标签可以帮助预标注，但不能默认当真值。

4. 检索指标 ​

设 Top-K 检索结果为 R_K，相关文档集合为 G。

4.1 Recall@K ​

text
Recall@K = |R_K intersect G| / |G|
1

回答需要三份证据、只召回一份时，Recall 是 1/3。

4.2 Precision@K ​

text
Precision@K = |R_K intersect G| / K
1

Precision 高说明上下文噪声少。若系统返回不足 K 条，本章仍以 K 为分母，把空位视为未命中；也可以使用实际返回数，但必须固定定义。

4.3 MRR@K ​

text
MRR@K = mean(1 / 第一条相关结果的排名)
1

适合“首个正确证据越靠前越好”的任务；它不奖励召回第二、第三份必要证据，因此不能替代 Recall。

4.4 可运行实现 ​

python
def retrieval_metrics(
    retrieved_ids: list[str],
    relevant_ids: frozenset[str],
    *,
    k: int,
) -> dict[str, float]:
    if k < 1:
        raise ValueError("k must be positive")
    if not relevant_ids:
        raise ValueError("use a separate no-answer metric")

    top_k = retrieved_ids[:k]
    hits = [item for item in top_k if item in relevant_ids]
    first_rank = next(
        (
            rank
            for rank, item in enumerate(top_k, start=1)
            if item in relevant_ids
        ),
        None,
    )

    return {
        "recall_at_k": len(set(hits)) / len(relevant_ids),
        "precision_at_k": len(hits) / k,
        "mrr_at_k": 0.0 if first_rank is None else 1.0 / first_rank,
    }


metrics = retrieval_metrics(
    ["noise", "policy-review", "policy-apply"],
    frozenset({"policy-review", "policy-apply"}),
    k=3,
)

assert metrics == {
    "recall_at_k": 1.0,
    "precision_at_k": 2 / 3,
    "mrr_at_k": 0.5,
}

5. Context、生成与引用指标 ​

5.1 Context Relevance ​

交给模型的上下文中，有多少内容与问题相关。可以按相关 Chunk 比例、token 比例或 LLM Judge 评分。定义不同，不能混着比较。

5.2 Faithfulness ​

把回答拆成可验证声明，计算多少声明被本次授权上下文支持：

text
Faithfulness = 支持的回答声明数 / 全部可验证声明数
1

它不判断回答是否完整。一个只说正确半句话的答案可以 Faithfulness 很高。

5.3 Answer Completeness ​

text
Completeness = 回答覆盖的参考事实数 / 必要参考事实数
1

参考事实应原子化，例如退款时效和申请条件是两个事实。

5.4 Citation Validity 与 Correctness ​

  • Validity：引用 ID 是否来自本次授权检索结果；
  • Correctness：该引用是否真的支持它旁边的声明；
  • Completeness：需要引用的声明是否都有引用。

只检查“答案里有 [1]”没有意义。

5.5 无答案与拒答 ​

为 answerable=False 的案例单独统计：

  • 正确拒答率；
  • 错误回答率；
  • 有答案案例误拒答率。

把无答案案例的 relevant_ids 设为空后硬算 Recall，会产生未定义行为。应使用独立指标。

6. 完整离线评测器 ​

下面的程序输入已标注案例和一次 RAG 运行记录，同时计算检索、Faithfulness、完整性、引用、拒答和延迟。声明支持与事实覆盖由人工或独立评审阶段提供，不用关键词重叠冒充语义判断。

python
from __future__ import annotations

from dataclasses import dataclass
from math import ceil


@dataclass(frozen=True)
class EvalCase:
    case_id: str
    relevant_ids: frozenset[str]
    reference_fact_ids: frozenset[str]
    answerable: bool
    tags: frozenset[str]


@dataclass(frozen=True)
class RagRun:
    retrieved_ids: tuple[str, ...]
    cited_ids: tuple[str, ...]
    claim_count: int
    supported_claim_count: int
    covered_fact_ids: frozenset[str]
    refused: bool
    retrieval_ms: int
    generation_ms: int


@dataclass(frozen=True)
class CaseResult:
    case_id: str
    recall_at_k: float | None
    precision_at_k: float | None
    mrr_at_k: float | None
    faithfulness: float | None
    completeness: float | None
    citation_validity: float | None
    refusal_correct: bool
    latency_ms: int


def evaluate_case(
    case: EvalCase,
    run: RagRun,
    *,
    k: int,
) -> CaseResult:
    if k < 1:
        raise ValueError("k must be positive")
    if not 0 <= run.supported_claim_count <= run.claim_count:
        raise ValueError("invalid supported claim count")

    top_k = run.retrieved_ids[:k]
    allowed_citations = set(top_k)
    citation_validity = (
        None
        if not run.cited_ids
        else sum(item in allowed_citations for item in run.cited_ids)
        / len(run.cited_ids)
    )

    if case.answerable:
        if not case.relevant_ids or not case.reference_fact_ids:
            raise ValueError("answerable cases require evidence and facts")
        hits = [item for item in top_k if item in case.relevant_ids]
        first_rank = next(
            (
                rank
                for rank, item in enumerate(top_k, start=1)
                if item in case.relevant_ids
            ),
            None,
        )
        recall = len(set(hits)) / len(case.relevant_ids)
        precision = len(hits) / k
        mrr = 0.0 if first_rank is None else 1.0 / first_rank
        completeness = (
            len(run.covered_fact_ids & case.reference_fact_ids)
            / len(case.reference_fact_ids)
        )
        refusal_correct = not run.refused
    else:
        recall = precision = mrr = completeness = None
        refusal_correct = run.refused

    faithfulness = (
        None
        if run.claim_count == 0
        else run.supported_claim_count / run.claim_count
    )

    return CaseResult(
        case_id=case.case_id,
        recall_at_k=recall,
        precision_at_k=precision,
        mrr_at_k=mrr,
        faithfulness=faithfulness,
        completeness=completeness,
        citation_validity=citation_validity,
        refusal_correct=refusal_correct,
        latency_ms=run.retrieval_ms + run.generation_ms,
    )


def mean(values: list[float]) -> float:
    if not values:
        raise ValueError("cannot average an empty metric")
    return sum(values) / len(values)


def summarize(results: list[CaseResult]) -> dict[str, float]:
    if not results:
        raise ValueError("results must not be empty")

    recalls = [
        item.recall_at_k
        for item in results
        if item.recall_at_k is not None
    ]
    faithfulness = [
        item.faithfulness
        for item in results
        if item.faithfulness is not None
    ]
    latencies = sorted(item.latency_ms for item in results)
    p95_index = ceil(len(latencies) * 0.95) - 1

    return {
        "mean_recall_at_k": mean(recalls),
        "mean_faithfulness": mean(faithfulness),
        "refusal_accuracy": mean(
            [float(item.refusal_correct) for item in results]
        ),
        "p95_latency_ms": float(latencies[p95_index]),
    }


answerable = EvalCase(
    case_id="refund-duration",
    relevant_ids=frozenset({"policy-review"}),
    reference_fact_ids=frozenset({"review-duration"}),
    answerable=True,
    tags=frozenset({"refund", "zh-CN"}),
)
answerable_run = RagRun(
    retrieved_ids=("policy-review", "policy-apply"),
    cited_ids=("policy-review",),
    claim_count=1,
    supported_claim_count=1,
    covered_fact_ids=frozenset({"review-duration"}),
    refused=False,
    retrieval_ms=35,
    generation_ms=180,
)

unanswerable = EvalCase(
    case_id="annual-leave-missing",
    relevant_ids=frozenset(),
    reference_fact_ids=frozenset(),
    answerable=False,
    tags=frozenset({"no-answer", "zh-CN"}),
)
unanswerable_run = RagRun(
    retrieved_ids=(),
    cited_ids=(),
    claim_count=0,
    supported_claim_count=0,
    covered_fact_ids=frozenset(),
    refused=True,
    retrieval_ms=12,
    generation_ms=90,
)

results = [
    evaluate_case(answerable, answerable_run, k=2),
    evaluate_case(unanswerable, unanswerable_run, k=2),
]
summary = summarize(results)

assert summary["mean_recall_at_k"] == 1.0
assert summary["mean_faithfulness"] == 1.0
assert summary["refusal_accuracy"] == 1.0
print(summary)

7. 评测器也需要校准 ​

生成指标可以来自：

方式优点局限
确定性规则快、稳定、便宜只能检查格式、ID、集合等明确契约
人工评审能理解领域细节慢、贵、有标注分歧
LLM-as-Judge扩展快、能评自然语言有偏差、漂移、成本和非确定性
混合兼顾规模和可靠性流程更复杂

Judge 必须校准：

  1. 准备人工金标子集；
  2. 比较 Judge 与人工的一致性；
  3. 检查中文、长文本、拒答和不同模型回答的偏差；
  4. 固定 Judge 模型、Prompt、温度与版本；
  5. 定期重新抽检；
  6. 关键安全门禁优先使用确定性规则。

不要用被评模型无条件评自己，也不要让一个总分掩盖引用越权。

from langsmith import Client


def target(inputs: dict[str, object]) -> dict[str, object]:

def citation_evaluator(run, example) -> dict[str, object]:
    outputs = run.outputs or {}

当前环境没有安装 pytest，下面代码只展示测试形状，未执行。若项目决定采用，应先锁定版本并添加依赖，而不是临时在 CI 下载最新版本。

python
# Requires a pinned pytest version; not run in this repository.
import pytest


@pytest.mark.parametrize(
    ("retrieved", "relevant", "expected_recall"),
    [
        (["a", "b"], frozenset({"a"}), 1.0),
        (["x", "b"], frozenset({"a"}), 0.0),
        (["a"], frozenset({"a", "b"}), 0.5),
    ],
)
def test_recall_at_k(
    retrieved: list[str],
    relevant: frozenset[str],
    expected_recall: float,
) -> None:
    result = retrieval_metrics(retrieved, relevant, k=2)

11. 回归比较与发布门禁 ​

不要只规定“平均分不下降”。门禁示例：

指标门槛示例原因
Overall Recall@5不低于基线 1 个百分点控制整体召回
高风险政策 Recall@5必须 >= 0.98关键切片硬门槛
无答案错误回答率<= 0.02控制幻觉
Citation Validity必须 1.0不允许伪造来源 ID
跨租户证据率必须 0安全硬门槛
P95 总延迟<= 2.5 秒服务目标
单请求成本不高于预算控制经济性

候选比较需要同一数据集、同一索引快照或明确比较目的、相同 Judge 配置。模型输出有随机性时使用多次运行、配对比较和置信区间。

切片至少包括：

  • 语言；
  • 文档类型；
  • 租户/权限档位；
  • 有答案/无答案；
  • 单文档/多文档；
  • 事实/归纳/比较；
  • 新旧知识版本；
  • 高风险类别。

整体提升不能抵消安全切片下降。

15. Prompt Injection 与知识库投毒 ​

RAG 把外部数据放进模型上下文，因此检索内容必须标为不可信数据。

威胁：

  • 文档写入“忽略系统指令”；
  • 攻击者上传包含密钥窃取指令的 PDF；
  • SEO/关键词堆叠操纵召回；
  • 旧版本恶意文档未删除；
  • 引用合法 ID，但内容来自未授权租户。

防护：

  • 接入身份、来源签名和审批；
  • 权限过滤在候选生成前执行；
  • 外部内容用清晰数据边界包裹；
  • 模型不能从文档获得工具或系统权限；
  • 对指令模式、异常关键词和批量更新告警；
  • Citation Validator 检查本轮授权 Evidence；
  • 高风险答案和动作需要规则/人工复核；
  • 在评测集中加入投毒与 Injection 案例。

仅在 Prompt 中写“不要受攻击”不构成完整防御。

17. 灰度、影子流量与回滚 ​

影子流量 ​

候选系统读取真实请求但不影响用户响应。必须确认数据使用权限，并避免候选产生副作用。比较检索结果、延迟和 Judge/人工抽样。

灰度 ​

从内部流量或允许租户开始，持续比较错误、拒答、引用、延迟和成本。不要让同一用户在多轮会话中随机切换索引版本。

回滚 ​

18. 常见失败 ​

只测最终答案 ​

无法区分检索与生成失败。补充相关文档和阶段 Trace。

用关键词重叠当 Faithfulness ​

相同词不代表逻辑支持，反义句也可能高度重叠。关键词规则只能做初筛。

用 Test 集反复调 Top-K ​

已经污染最终评测。重新建立隔离 Test，并记录数据使用历史。

Ragas/LangSmith 分数变化却无法解释 ​

Judge、Prompt、依赖或数据集版本未固定。先恢复完整实验 Manifest。

整体平均分提升但安全回归 ​

关键切片被平均值掩盖。权限、引用和高风险 Recall 使用硬门槛。

线上零结果率下降就宣称质量提升 ​

可能只是返回了更多噪声。结合人工样本、点击、重问和离线 Recall/Precision。

索引发布后无法回滚 ​

原地覆盖向量或未保留 Manifest。改用不可变版本和 alias 切换。

19. 练习 ​

练习一：构建数据集 ​

准备至少 50 个问题，包含 relevant IDs、原子事实、权限、无答案和标签。按文档/时间而不是逐行随机切分。

练习二：检索指标 ​

实现 Recall@K、Precision@K、MRR 与 nDCG，分别在 Chunk 与 Document 层计算。制造重复 Chunk，验证不会虚增命中。

练习三：生成与引用 ​

把回答拆成声明，人工标注支持 Evidence。计算 Faithfulness、Completeness、Citation Validity 和 Correctness。

练习四：回归门禁 ​

比较 baseline 与 candidate，按语言、无答案和高风险政策切片。整体提升但高风险 Recall 下降时必须阻止发布。

练习五：Ragas 候选验证 ​

在单独分支锁定 ragas==0.4.3，配置明确 Judge，运行小金标集并与人工结果比较。记录 API、成本和一致性；不能只报告平均分。

练习六：LangSmith 实验 ​

建立脱敏远程数据集，运行 Client.evaluate()，把 index/prompt/model/dataset 版本写入 metadata。验证引用越权 evaluator 会阻止发布。

练习七：生产演练 ​

构建 staging index，执行离线门禁、影子流量、10% 灰度、全量与回滚。模拟删除、模型超时和向量库故障。
