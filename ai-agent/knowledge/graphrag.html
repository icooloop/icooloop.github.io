GraphRAG ​

向量 RAG 擅长回答“哪段文字与这个问题语义相近”，但有些问题关心的不是一段话，而是多个实体之间的关系、路径和整体结构：

text
哪个公司投资了供应商 A，而该供应商又服务哪些项目？
某次事故涉及哪些人员、系统和后续整改？
过去一年投诉集中在哪些产品群和共同原因？
1
2
3

GraphRAG 把图结构引入检索增强生成，让系统可以沿实体关系检索、多跳聚合，或者先形成社区级摘要再回答全局问题。

但必须先澄清一个命名问题：

Graph RAG 是一类“图结构 + 检索 + 生成”的通用架构；Microsoft GraphRAG 是微软开源的一套具体索引与查询方法/实现。二者不能画等号。

当前项目没有安装 Microsoft graphrag、Neo4j Python Driver 或图算法依赖，因此：

  • 本页的标准库图检索示例可以直接运行；
  • Neo4j Cypher 用于解释数据模型，不代表连接测试已通过；
  • Microsoft GraphRAG 命令和配置必须在锁定精确版本后按官方文档复核；
  • 不声明当前框架“最新版”或某个命令已执行。

1. 普通 RAG 为什么会漏掉关系 ​

假设有三段资料：

text
文档 1：星河公司投资了北辰科技。
文档 2：北辰科技为曙光项目提供支付网关。
文档 3：曙光项目由零售事业部负责。
1
2
3

问题是：

text
星河公司间接关联哪个事业部？
1

单个 Chunk 都不包含完整答案。向量检索可能只召回与“星河公司”最相似的文档 1，却漏掉后续两跳关系。

图结构可以表示为：

text
(星河公司)-[INVESTED_IN]->(北辰科技)
    -[PROVIDES_TO]->(曙光项目)
    -[OWNED_BY]->(零售事业部)

3

查询变成从“星河公司”出发，沿允许的关系做有限深度遍历，再把路径和来源交给模型解释。

import re


def normalize_name(name: str) -> str:
    return re.sub(r"\s+", "", name).casefold()


def can_merge(
    left: Entity,
    right: Entity,
) -> bool:
    if left.entity_type != right.entity_type:
        return False

    left_names = {
        normalize_name(left.canonical_name),
        *(normalize_name(alias) for alias in left.aliases),
    }
    right_names = {
        normalize_name(right.canonical_name),
        *(normalize_name(alias) for alias in right.aliases),
    }
    return bool(left_names & right_names)

8.1 标准库可运行图 ​

python
from __future__ import annotations

from collections import defaultdict, deque
from dataclasses import dataclass


@dataclass(frozen=True)
class Edge:
    source: str
    relation: str
    target: str
    evidence_id: str


class KnowledgeGraph:
    def __init__(self, edges: list[Edge]) -> None:
        self.adjacency: dict[str, list[Edge]] = defaultdict(list)
        for edge in edges:
            self.adjacency[edge.source].append(edge)

    def paths_from(
        self,
        start: str,
        *,
        max_depth: int = 2,
        max_paths: int = 20,
        allowed_relations: set[str] | None = None,
    ) -> list[list[Edge]]:
        if max_depth < 1:
            raise ValueError("max_depth must be positive")

        queue = deque([(start, [], {start})])
        paths: list[list[Edge]] = []

        while queue and len(paths) < max_paths:
            current, path, visited = queue.popleft()
            if len(path) >= max_depth:
                continue

            for edge in sorted(
                self.adjacency.get(current, []),
                key=lambda item: (
                    item.relation,
                    item.target,
                    item.evidence_id,
                ),
            ):
                if (
                    allowed_relations is not None
                    and edge.relation not in allowed_relations
                ):
                    continue
                if edge.target in visited:
                    continue

                next_path = [*path, edge]
                paths.append(next_path)
                queue.append(
                    (edge.target, next_path, visited | {edge.target})
                )

        return paths

9. 路径如何变成模型上下文 ​

不要只把实体名称拼成句子。模型还需要原始证据：

def format_path(
    path: list[Edge],
    evidence_by_id: dict[str, str],
) -> str:
    lines: list[str] = []
    for edge in path:
        evidence = evidence_by_id.get(edge.evidence_id)
        if evidence is None:
            raise ValueError(
                f"missing evidence: {edge.evidence_id}"
            )
        lines.append(
            f"{edge.source} -[{edge.relation}]-> {edge.target}\n"
            f"证据 [{edge.evidence_id}]：{evidence}"
        )
    return "\n\n".join(lines)

from collections import defaultdict


def rrf(
    ranked_lists: list[list[str]],
    *,
    k: int = 60,
) -> list[tuple[str, float]]:
    scores: dict[str, float] = defaultdict(float)
    for ranked in ranked_lists:
        for rank, item_id in enumerate(ranked, start=1):
            scores[item_id] += 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda item: (-item[1], item[0]))

11.1 连通分量教学实现 ​

python
def connected_components(
    edges: list[Edge],
) -> list[set[str]]:
    undirected: dict[str, set[str]] = defaultdict(set)
    for edge in edges:
        undirected[edge.source].add(edge.target)
        undirected[edge.target].add(edge.source)

    seen: set[str] = set()
    components: list[set[str]] = []

    for node in sorted(undirected):
        if node in seen:
            continue
        component: set[str] = set()
        queue = deque([node])
        seen.add(node)

        while queue:
            current = queue.popleft()
            component.add(current)
            for neighbor in sorted(undirected[current]):
                if neighbor not in seen:
                    seen.add(neighbor)
                    queue.append(neighbor)

        components.append(component)

    return components

12. Microsoft GraphRAG 是什么 ​

Microsoft GraphRAG 是一个具体开源项目。其核心思想包括从非结构化文本抽取实体、关系与声明，构建图结构，进行社区层次分析和社区报告，并提供针对不同问题类型的搜索方法。

应重点理解而不是死记命令：

能力解决的问题
索引流水线从文本生成图、社区和报告等派生数据
Local Search围绕具体实体组合图、文本和上下文
Global Search基于社区报告回答全局主题问题
DRIFT Search在较高层社区信息与局部探索之间结合

这些名称是 Microsoft GraphRAG 的具体方法，不应反过来断言所有通用 Graph RAG 都必须实现相同接口。

15. 查询时的权限过滤 ​

Graph 路径可能跨越多个权限域。只有起点有权限不代表整条路径都能展示。

python
def path_is_authorized(
    path: list[Edge],
    evidence: dict[str, EvidenceChunk],
    *,
    tenant_id: str,
    role: str,
) -> bool:
    for edge in path:
        chunk = evidence.get(edge.evidence_id)
        if chunk is None:
            return False
        if chunk.tenant_id != tenant_id:
            return False
        if role not in chunk.allowed_roles:
            return False
    return True

17. 何时应该使用 GraphRAG ​

适合：

  • 问题经常需要多跳关系；
  • 实体与关系是核心业务对象；
  • 需要实体中心探索；
  • 需要语料全局主题与群组摘要；
  • 关系可通过 Schema 和来源验证。

不适合：

  • 简单 FAQ 和单段事实问答；
  • 语料很小，向量 RAG 已达到质量目标；
  • 无法定义稳定实体/关系 Schema；
  • 数据更新极快，却没有增量图维护能力；
  • 预算无法承担抽取、消歧、社区和摘要成本；
  • 团队没有图数据治理能力。

GraphRAG 不是“RAG 进阶的必经升级”。应先证明普通 RAG 的失败来自关系和全局结构，而不是切分、Embedding、过滤或 Rerank 没做好。

19. 评测与普通 RAG 有什么不同 ​

除了 Recall@K、Faithfulness 和引用正确性，还应评估：

  • 实体抽取 Precision/Recall；
  • 实体链接/消歧准确率；
  • 关系类型和方向准确率；
  • 关系证据覆盖率；
  • 多跳路径命中率；
  • 路径最短不等于语义最正确；
  • Global Search 的主题覆盖；
  • 社区摘要事实保真；
  • 图更新后的陈旧边比例；
  • 越权路径暴露率。

20. 常见失败路径 ​

20.1 图中有很多重复实体 ​

先修实体规范化、唯一标识和消歧，不要靠更深遍历掩盖问题。

20.2 路径存在但没有来源 ​

不能用于回答。把无来源边移入待审核区，不进入生产检索。

20.3 遍历结果爆炸 ​

限制关系类型、深度、路径数、节点度数和时间预算；按问题意图选择扩展方向。

20.4 Global Search 给出漂亮但空泛的总结 ​

检查社区报告是否保留原始 Evidence ID，Map 阶段是否覆盖相关社区，Reduce 阶段是否丢失少数但重要事实。

20.5 文档更新后仍返回旧关系 ​

检查 Chunk 版本、Statement 有效期、受影响社区重算和缓存失效。

20.6 图检索越权 ​

这是数据安全事故。权限必须应用于实体、Statement、Evidence 和向量结果，并加入跨租户自动化测试。

21. 动手练习 ​

练习一：手工建图 ​

从 10 段文本手工标注实体、关系和证据，使用 KnowledgeGraph.paths_from() 回答两个两跳问题。

练习二：抽取质量 ​

定义 5 种实体和 5 种关系，建立 50 条标注数据，计算实体和关系 Precision/Recall。

练习三：消歧 ​

准备同名不同公司、别名和缩写，证明保守合并策略不会把不同注册号实体合并。

练习四：Hybrid ​

分别运行图遍历和向量/关键词检索，用 RRF 融合，比较多跳问题与描述性问题的结果。

练习五：Local 与 Global ​

设计 10 个实体问题和 10 个全局主题问题，分别选择检索模式并解释原因。

练习六：增量更新 ​

让项目归属从部门 A 变为 B，更新有效期和社区摘要，证明当前与历史问题得到不同答案。
