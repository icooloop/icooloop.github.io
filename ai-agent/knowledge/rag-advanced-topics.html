RAG 高级专题 ​

高级 RAG 不是把更多名词接到检索链上。每一种技术都应回答一个已经被数据证明的问题：召回不够、长文档定位不准、跨数据源问题无法完成、图片表格被文本解析破坏，还是 Prompt 与检索参数需要系统优化。

  -> 比较质量、延迟、成本与运维复杂度

1. 先确认是否真的需要高级 RAG ​

已观察到的失败优先尝试不应先做
同义问法召回差Query Rewrite、混合检索、Rerank直接构建知识图谱
长手册只命中局部，缺少全局主题父子检索、层次摘要无限增大 Chunk
精细实体匹配差Late Interaction 或领域 Reranker只换更大的生成模型
表格、图片中的证据丢失保结构解析、多模态索引只对 OCR 文本做向量化
问题跨订单 API 与制度文档模块化规划与受控联合查询把订单快照写入向量库
Prompt、示例和检索参数靠人工猜编译式优化在测试集上手工过拟合
问题需要多跳实体关系图与向量混合把所有 Chunk 两两连边

引入新模块前至少保存：

  • 基线版本与配置；
  • 固定的开发集和隔离测试集；
  • 每个失败案例的阶段归因；
  • Recall@K、MRR、Faithfulness、引用正确性；
  • P50/P95 延迟、请求成本和索引成本；
  • 可回滚的索引与 Prompt 版本。

没有基线就无法判断“高级方案”是否只是更复杂。

2. 编译式 RAG 的准确含义 ​

“编译式”至少有三种不同含义，不能混用：

方向输入编译/优化结果主要目标
LM 程序优化Signature、模块、示例、指标Prompt、Few-shot 示例、模块参数提升任务指标
检索程序搜索候选 Retriever、Top-K、Rerank 配置一份冻结的 RAG 配置在质量/成本约束下选配置
执行计划编译多查询依赖图和工具调用可并行、可缓存的执行计划降低多步 RAG 延迟

它们都不是把 Python 代码编译成机器码。

2.1 DSPy 的边界 ​

DSPy 把 LM 调用表达成 Signature 和 Module，再使用带指标的 Optimizer 根据训练样例选择或生成 Prompt、示例和参数。它适合：

  • 有可重复的数据集和任务指标；
  • RAG 程序结构相对稳定；
  • 愿意为编译过程支付额外模型调用；
  • 能把开发集与最终测试集隔离。

它不会自动解决：

  • 文档解析错误；
  • 越权检索；
  • 删除后残留的旧向量；
  • 数据集中没有覆盖的业务风险；
  • 真实服务的事务和幂等问题。

下面是 DSPy 的概念形状，不是本项目可运行代码。当前环境没有安装或锁定 dspy，实际 API 必须按所选版本的官方文档确认：

python
# Version-sensitive illustration; not run in this repository.
import dspy


class GroundedAnswer(dspy.Signature):
    """Answer only from retrieved evidence and include source IDs."""

    question: str = dspy.InputField()
    context: list[str] = dspy.InputField()
    answer: str = dspy.OutputField()


class RagProgram(dspy.Module):
    def __init__(self, retriever) -> None:
        super().__init__()
        self.retriever = retriever
        self.answer = dspy.ChainOfThought(GroundedAnswer)

    def forward(self, question: str):
        context = self.retriever(question)
        return self.answer(question=question, context=context)

2.2 RAGCompiler 的边界 ​

RAGCompiler 类方案关注多查询 RAG 的执行计划：分析查询依赖、提前调度独立检索、并行执行并复用中间结果。它解决的是调度和延迟，不是一个通用的检索质量优化器。

适合的任务具有：

text
问题分解 -> 多个独立/部分依赖的检索 -> 汇总
1

3. 用离线指标“编译”一份候选配置 ​

下面的纯 Python 示例演示最小原则：候选程序在开发集上评分，质量门槛优先于延迟，然后冻结最佳配置。它不是 DSPy 或 RAGCompiler 的替代实现。

python
from dataclasses import dataclass


@dataclass(frozen=True)
class RagConfig:
    name: str
    use_keyword: bool
    use_dense: bool
    top_k: int
    estimated_latency_ms: int


@dataclass(frozen=True)
class EvalCase:
    query: str
    relevant_ids: frozenset[str]


def recall_at_k(retrieved: list[str], relevant: frozenset[str]) -> float:
    if not relevant:
        raise ValueError("relevant_ids must not be empty")
    return len(set(retrieved) & relevant) / len(relevant)


def compile_config(
    candidates: list[RagConfig],
    cases: list[EvalCase],
    runs: dict[tuple[str, str], list[str]],
    *,
    min_recall: float,
) -> RagConfig:
    if not candidates or not cases:
        raise ValueError("candidates and cases must not be empty")

    accepted: list[tuple[float, int, str, RagConfig]] = []
    for candidate in candidates:
        recalls = [
            recall_at_k(
                runs[(candidate.name, case.query)][: candidate.top_k],
                case.relevant_ids,
            )
            for case in cases
        ]
        mean_recall = sum(recalls) / len(recalls)
        if mean_recall >= min_recall:
            accepted.append(
                (
                    -mean_recall,
                    candidate.estimated_latency_ms,
                    candidate.name,
                    candidate,
                )
            )

    if not accepted:
        raise RuntimeError("no candidate passed the recall gate")

    accepted.sort()
    return accepted[0][3]


configs = [
    RagConfig("dense", False, True, 2, 35),
    RagConfig("hybrid", True, True, 3, 52),
]
cases = [
    EvalCase("refund duration", frozenset({"policy-review"})),
    EvalCase("order status", frozenset({"order-api"})),
]
runs = {
    ("dense", "refund duration"): ["policy-review", "policy-apply"],
    ("dense", "order status"): ["policy-order", "policy-review"],
    ("hybrid", "refund duration"): ["policy-review", "policy-apply"],
    ("hybrid", "order status"): ["order-api", "policy-order"],
}

compiled = compile_config(configs, cases, runs, min_recall=1.0)
assert compiled.name == "hybrid"
print(compiled)

5. 多模态 RAG ​

多模态 RAG 的目标不是“把图片 URL 塞给模型”，而是让非纯文本证据可检索、可定位、可授权、可引用。

5.1 四种常见知识 ​

模态索引内容必须保留的定位信息常见失败
表格标题、表头、行列、单元格关系表名、行键、列名、页码扁平文本丢失行列语义
图片OCR、caption、视觉向量文件、页码、坐标框、图像哈希OCR 错误、裁剪丢上下文
音频转写、说话人、时间段、音频向量起止时间、说话人、文件版本转写错误、说话人混淆
视频镜头、关键帧、字幕、音轨时间码、镜头 ID、原始文件采样过稀、音画不同步

searchable_text 可以来自 OCR、ASR 或 caption，但必须保留原始资产和定位。最终引用应指向原图区域、表格单元格或时间码，不能只引用模型生成的 caption。

5.2 三种检索路线 ​

  1. 文本代理：先 OCR/ASR/caption，再使用文本 Embedding。部署简单，但代理文本会丢信息。
  2. 原生多模态向量：图片和文本进入共享向量空间。适合跨模态查询，但需要验证语言、领域和图像类型。
  3. 双路召回：文本代理与视觉/音频向量分别召回，再融合或 Rerank。质量潜力更高，索引与延迟也更高。

真实接入前应建立模态级评测集。只用文本问题测试图片检索，不能证明图片内细节已被正确理解。

5.3 安全边界 ​

  • 图像和文档中的文字是外部数据，不是系统指令；
  • OCR/ASR 服务可能把数据发送到第三方，必须确认地域与保留策略；
  • 资产 URL 应短期签名，并在服务端检查租户权限；
  • 人脸、声音和屏幕截图可能属于敏感数据；
  • 缓存的缩略图、转写和向量都必须进入删除链路。

6.2 RAPTOR ​

RAPTOR 的核心是递归地聚类文本表示并生成更高层摘要，查询时可以从多个树层检索。它适合全局主题、跨章节归纳和长文档集合。

它的代价包括：

  • 建树需要大量 Embedding、聚类与摘要调用；
  • 摘要可能遗漏限定条件或引入事实错误；
  • 增量更新可能影响祖先节点；
  • 引用不能停在生成摘要，仍需回溯叶子证据；
  • 权限变化必须传播到所有祖先摘要。

生产记录至少包含：

text
node_id, level, child_ids, source_versions,
summary_model, prompt_version, build_id, tenant_id

7. ColBERT 与 Late Interaction ​

普通 Dense Retrieval 常把整个 Query 和文档各压成一个向量。ColBERT 保留 token 级表示，在查询时通过 Late Interaction 计算细粒度匹配。

简化的 MaxSim：

text
score(Q, D) = sum over q in Q of max over d in D similarity(q, d)
1

纯 Python 示意：

python
from math import sqrt


def cosine(left: list[float], right: list[float]) -> float:
    if len(left) != len(right) or not left:
        raise ValueError("vectors must have the same non-zero dimension")
    dot = sum(a * b for a, b in zip(left, right, strict=True))
    left_norm = sqrt(sum(value * value for value in left))
    right_norm = sqrt(sum(value * value for value in right))
    if left_norm == 0 or right_norm == 0:
        return 0.0
    return dot / (left_norm * right_norm)


def maxsim(
    query_tokens: list[list[float]],
    document_tokens: list[list[float]],
) -> float:
    if not query_tokens or not document_tokens:
        return 0.0
    return sum(
        max(cosine(query, document) for document in document_tokens)
        for query in query_tokens
    )


query = [[1.0, 0.0], [0.0, 1.0]]
document = [[0.9, 0.1], [0.1, 0.9], [-1.0, 0.0]]
assert maxsim(query, document) > 1.9

from dataclasses import dataclass
from typing import Literal


@dataclass(frozen=True)
class QueryPlan:
    route: Literal["vector", "sql", "api", "combined"]
    normalized_question: str
    required_scopes: frozenset[str]
    max_sources: int


def plan_question(question: str) -> QueryPlan:
    normalized = " ".join(question.split())
    has_order_id = any(char.isdigit() for char in normalized)
    asks_policy = "政策" in normalized or "policy" in normalized.lower()

    if has_order_id and asks_policy:
        return QueryPlan(
            "combined",
            normalized,
            frozenset({"orders:read", "knowledge:read"}),
            2,
        )
    if has_order_id:
        return QueryPlan(
            "api",
            normalized,
            frozenset({"orders:read"}),
            1,
        )
    return QueryPlan(
        "vector",
        normalized,
        frozenset({"knowledge:read"}),
        1,
    )

  • 实体 ID 与 Chunk ID 必须可追溯；
  • 图边来自抽取时要保存来源和置信度；
  • 遍历深度、节点数和查询时间必须有上限；
  • 权限过滤必须在遍历之前或遍历过程中执行；
  • 图结论需要回到原始证据引用。

完整的实体消歧、社区摘要和 Local/Global Search 见 GraphRAG。本章只说明混合架构，不把 GraphRAG 简化成“向量库旁边加一个图数据库”。

10. 多租户与权限隔离 ​

高级索引会产生更多派生数据：摘要节点、OCR、caption、图实体、缓存、token 向量。每一份派生数据都必须继承权限和删除语义。

安全过滤顺序：

text
认证得到 tenant/user/scopes
  -> 在候选生成前过滤允许分区
  -> 在 Rerank 前再次确认
  -> Context Builder 只接收授权 Evidence
  -> Citation Validator 校验来源白名单
1
2
3
4
5

反例：先在全租户索引中 Top-100，再过滤当前租户。即使最终结果被过滤，未授权文档仍可能影响排名、缓存、日志和时延侧信道。

推荐隔离方式取决于风险：

  • 高隔离：每租户独立数据库/Collection/密钥；
  • 中等隔离：共享服务、独立分区与服务端强制过滤；
  • 大规模共享：共享索引但所有查询必须带不可绕过的租户过滤，并接受更高审计成本。

不要只相信模型输出的 tenant_id。它必须来自认证上下文。

11.3 灾难恢复 ​

向量索引可以从权威文档重建，但恢复时间可能很长。至少演练：

  • Manifest 与原始文档备份；
  • 恢复索引和元数据数据库；
  • 校验文档数、向量数、删除墓碑和哈希；
  • 恢复后运行固定检索集；
  • 达到 RTO/RPO 前不切流量。

12. 完整离线模块化示例 ​

下面把路由、模块注册表、权限和证据标准化放进一个可运行示例。它使用确定性 Fake 数据，不代表真实向量、SQL 或 API 客户端。

python
from __future__ import annotations

from dataclasses import dataclass
from enum import StrEnum
from typing import Protocol


class SourceKind(StrEnum):
    VECTOR = "vector"
    API = "api"


@dataclass(frozen=True)
class Evidence:
    evidence_id: str
    source_kind: SourceKind
    content: str
    tenant_id: str
    source_version: str


@dataclass(frozen=True)
class Principal:
    tenant_id: str
    scopes: frozenset[str]


class Retriever(Protocol):
    required_scope: str

    def retrieve(
        self,
        query: str,
        principal: Principal,
    ) -> list[Evidence]: ...


class FakePolicyRetriever:
    required_scope = "knowledge:read"

    def retrieve(
        self,
        query: str,
        principal: Principal,
    ) -> list[Evidence]:
        if "退款" not in query and "policy" not in query.lower():
            return []
        return [
            Evidence(
                "policy-review",
                SourceKind.VECTOR,
                "退款审核通常需要三个工作日。",
                principal.tenant_id,
                "policy-2026-07",
            )
        ]


class FakeOrderApi:
    required_scope = "orders:read"

    def retrieve(
        self,
        query: str,
        principal: Principal,
    ) -> list[Evidence]:
        if "A1024" not in query:
            return []
        return [
            Evidence(
                "order-A1024",
                SourceKind.API,
                "订单 A1024 状态为 shipped。",
                principal.tenant_id,
                "orders@2026-07-16T10:00:00Z",
            )
        ]


def routes(question: str) -> tuple[str, ...]:
    selected: list[str] = []
    if "退款" in question or "policy" in question.lower():
        selected.append("policy")
    if any(char.isdigit() for char in question):
        selected.append("order")
    return tuple(selected)


def retrieve_all(
    question: str,
    principal: Principal,
    registry: dict[str, Retriever],
) -> list[Evidence]:
    evidence: list[Evidence] = []
    for route in routes(question):
        retriever = registry[route]
        if retriever.required_scope not in principal.scopes:
            raise PermissionError(f"missing scope: {retriever.required_scope}")
        evidence.extend(retriever.retrieve(question, principal))

    if any(item.tenant_id != principal.tenant_id for item in evidence):
        raise PermissionError("cross-tenant evidence rejected")
    return evidence


registry: dict[str, Retriever] = {
    "policy": FakePolicyRetriever(),
    "order": FakeOrderApi(),
}
principal = Principal(
    tenant_id="acme",
    scopes=frozenset({"knowledge:read", "orders:read"}),
)

result = retrieve_all(
    "订单 A1024 是否符合退款政策？",
    principal,
    registry,
)

assert [item.evidence_id for item in result] == [
    "policy-review",
    "order-A1024",
]
for item in result:
    print(item.source_kind, item.evidence_id, item.content)

13. 失败路径与排错 ​

编译结果在测试集下降 ​

原因通常是开发集过拟合、指标设计偏差或底层模型变化。保留未参与编译的测试集，并记录编译产物完整版本。

模块越拆越多，质量没有变化 ​

接口拆分只改善可替换性，不自动提高检索质量。用 Trace 查看真正的失败模块，删除没有指标收益的分支。

多模态结果有文字但无法引用 ​

OCR/caption 没有关联资产坐标或时间码。重新设计 Chunk 契约，保留原始定位，不要把生成文本当权威来源。

RAPTOR 摘要回答与原文冲突 ​

摘要是派生索引，不是证据终点。回溯叶子 Chunk，校验来源版本；必要时只用摘要做路由，不直接作为最终事实。

ColBERT 质量高但服务不可用 ​

把索引体积、硬件、更新和 P95 延迟纳入门槛。无法稳定部署的离线高分方案不能上线。

联合查询泄露其他租户数据 ​

权限过滤放得太晚，或 SQL/API 模块接受模型提供的 tenant。身份必须由 Runtime 注入，每个模块在数据源侧强制过滤。

删除后仍能检索到内容 ​

只删了主向量，未删摘要、图边、缓存或多模态派生物。建立可审计的删除任务和墓碑，逐索引验证。

14. 练习 ​

练习一：建立技术选择记录 ​

从真实失败集中选择一个问题，写出基线、候选技术、成功指标、最大延迟/成本和回退条件。没有指标收益时明确拒绝引入。

练习二：编译候选配置 ​

扩展 compile_config()，加入 MRR、P95 延迟和成本门槛。把案例分成中文、英文和无答案三个切片，禁止只看整体平均分。

练习三：模块化联合检索 ​

增加一个只读发票 API 模块。模型不能选择 tenant，未知 route 必须失败；所有 Evidence 都要有版本和授权来源。

练习四：多模态证据 ​

设计表格、图片和音频 Chunk，分别包含单元格坐标、图片框和时间码。模拟删除源文件，证明全部派生记录都会进入删除清单。

练习五：层次化检索 ​

为一份长文档建立章节摘要、父段落和叶子 Chunk。测试全局问题与局部问题，并验证最终引用总能回到叶子原文。

练习六：Late Interaction ​

使用小向量比较单向量平均池化与 maxsim() 在实体词匹配上的差异。记录质量收益与表示大小，不把示意函数当生产 ColBERT。

练习七：蓝绿迁移 ​

设计 index-v1 到 index-v2 的 Manifest、回填、影子流量、切换、回滚和旧索引删除流程。
