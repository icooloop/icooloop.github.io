RAG 进阶 ​

基础 RAG 的路径是固定的：把用户问题向量化，取 Top-K Chunk，再让模型依据证据回答。它简单、可控，也应该是第一个基线。只有当评测显示具体失败模式后，才需要增加高级策略。

本页不会把“高级”理解为堆更多模型调用，而是学习怎样针对不同失败进行精确修复：

失败优先考虑
精确编号、缩写召回差关键词 + 向量混合检索
用户表达含糊查询改写、Multi-Query
一个问题包含多个事实查询分解
Top-K 相关但顺序不佳扩大候选后 Rerank
Chunk 太短、答案需更大上下文Parent-Child Retrieval
结果高度重复MMR 或去重
没有足够证据门槛、拒答、转人工
授权证据相互冲突冲突检测、needs_review

学完本页，你应该能够设计一条：

text
受信身份
  -> 查询分析/变换
  -> 权限前置过滤
  -> 稀疏候选 + 稠密候选
  -> 去重与 RRF 融合
  -> Rerank
  -> 上下文选择
  -> 证据冲突与充分性判断
  -> 回答 / 拒答 / 人工复核
  -> 引用白名单校验

2.2 Parent-Child Retrieval ​

小 Chunk 适合精确匹配，大段上下文适合回答：

2.3 Multi-Vector Retrieval ​

一个文档可以有多种用于召回的表示：

  • 原始 Chunk Embedding；
  • 标题 + 正文 Embedding；
  • 模型生成的摘要；
  • 可能问题；
  • 图片或表格的文本描述。

所有表示指回同一个权威 document_id。生成的摘要和问题只能帮助召回，最终回答仍应引用原始授权内容。

2.4 表格与代码不能只按字符切 ​

表格应保留表头与行关系；代码应保留函数/类边界。解析失败比检索算法不足更常见。对 PDF 表格、扫描件和多栏排版建立专门抽样测试。

3.3 Multi-Query ​

为同一意图生成多个表达：

text
退款审核需要多久
退款申请的人工审核时效
返款审核要几个工作日
1
2
3

每条查询独立召回，再按稳定 Chunk ID 去重与融合。查询数会线性增加 Embedding 与检索成本，应设置上限，并用评测证明收益。

3.4 查询分解 ​

问题“退款条件是什么，审核又要多久？”包含两个子问题：

text
退款申请条件
退款审核时效
1
2

分别召回后再组合证据。分解必须保留父问题，并验证每个子问题确实服务于原任务，防止模型无边界扩展任务。

3.5 HyDE ​

Hypothetical Document Embeddings 先生成一段“可能的答案文档”，再用它检索。它有时能弥合短查询与长文档的表达差异，但假设文本可能包含虚构事实。

安全边界：

  • 假设文本只用于检索，不是证据；
  • 最终回答只能引用真实授权文档；
  • 记录是否启用 HyDE；
  • 用负样本评估它是否把系统带向错误主题。

4.2 为什么不直接加原始分数 ​

BM25 分数和余弦相似度不在同一尺度：

python
# 脆弱：0.7 和 12.4 没有可直接相加的共同单位。
combined = 0.5 * cosine_score + 0.5 * bm25_score
1
2

可以归一化，但分布会随查询和语料变化。Reciprocal Rank Fusion（RRF）只依赖名次，更容易跨检索器组合。

5. RRF：按名次融合候选 ​

对文档 d：

text
RRF(d) = Σ 1 / (c + rank_r(d))
1

c 是平滑常数，常见示例使用 60，但它仍应通过评测确定。

python
from collections import defaultdict
from collections.abc import Sequence


def reciprocal_rank_fusion(
    rankings: Sequence[Sequence[str]],
    *,
    constant: int = 60,
) -> list[tuple[str, float]]:
    if constant < 1:
        raise ValueError("constant must be positive")

    scores: dict[str, float] = defaultdict(float)
    for ranking in rankings:
        # 同一路结果先去重，避免一个 ID 重复加分。
        for rank, item_id in enumerate(dict.fromkeys(ranking), start=1):
            scores[item_id] += 1.0 / (constant + rank)

    return sorted(scores.items(), key=lambda item: (-item[1], item[0]))


print(
    reciprocal_rank_fusion(
        [
            ["refund", "shipping", "invoice"],
            ["refund", "invoice", "returns"],
        ]
    )
)

对外部 Rerank 服务要设置：

  • 候选上限和正文截断策略；
  • 超时；
  • 有限重试；

7.2 Rerank 与 MMR 不同 ​

  • Rerank 优先“每条与查询有多相关”；
  • MMR 在相关性之外惩罚候选间重复。

可以先 Rerank 再在高相关候选中做多样性选择，但每层都要有评测依据。

8. 上下文选择不是简单 Top-N ​

最终进入 Prompt 前还要处理：

  • 相同来源的相邻 Chunk 合并；
  • Parent 去重；
  • 完全重复内容去重；
  • 版本优先级；
  • Token 预算；
  • 来源多样性；
  • 证据冲突；
  • 引用所需的来源元数据。
python
def select_under_budget(
    candidates: list[tuple[Document, int]],
    *,
    token_budget: int,
) -> list[Document]:
    selected: list[Document] = []
    used = 0
    for document, estimated_tokens in candidates:
        if estimated_tokens < 1:
            raise ValueError("token estimate must be positive")
        if used + estimated_tokens > token_budget:
            continue
        selected.append(document)
        used += estimated_tokens
    return selected

9. 自适应检索：不是每个问题都走最贵路径 ​

可按明确规则路由：

含糊跟进问题 -> 查询改写 + 检索
多事实问题 -> 查询分解 + 检索
低置信或冲突 -> 拒答/人工复核

路由应是有限集合，记录命中原因。不要让模型生成任意索引名、Filter 或数据库表达式。

RAG 进阶仍可以是固定 Workflow。只有模型动态决定是否继续检索、选择工具或反复验证时，才进入 Agentic RAG 范畴，后续有独立章节。

10. Self-RAG、Corrective RAG（CRAG）与 Adaptive RAG ​

这三个名称经常被混用，但它们观察的失败信号不同：

方法首要问题核心信号典型纠错动作
Self-RAG当前生成内容是否需要检索、是否被证据支持、是否有用检索必要性、证据相关性、事实支持度、回答效用检索、重写某段、补充证据、拒答
Corrective RAG（CRAG）首轮检索结果是否足够可靠检索质量/正确性分级保留并精炼、扩展检索、替换来源、拒答
Adaptive RAG这个问题应该走多复杂的检索路径查询意图、复杂度、风险、置信度与预算不检索、单步 RAG、多步检索或转人工

它们不是某个 LangChain 类名，而是可以用 Runnable、Graph 或普通服务代码实现的控制策略。原始论文还包含训练和模型设计细节；应用层不能把一个 LLM 打分 Prompt 直接等同于完整论文方法。

10.1 Self-RAG：对检索与生成做自我反思 ​

Self-RAG 解决的是：模型生成到当前阶段时是否需要外部证据，检索结果是否相关，草稿是否被证据支持且真正回答了问题。

最小控制流：

text
问题
  -> 判断 retrieve_needed
      ├─ false -> 生成草稿
      └─ true  -> 检索 -> 评估 evidence_relevance -> 生成草稿
  -> 评估 support 与 utility
      ├─ 通过 -> 回答 + 引用
      ├─ 缺证据且仍有预算 -> 再检索/重写一次
      └─ 不通过或预算耗尽 -> 拒答/人工复核

  • retrieval_needed：当前问题能否不依赖知识库回答；
  • evidence_relevance：检索片段是否真的讨论问题；
  • support：草稿中的事实是否能由证据推出；
  • utility：草稿是否完整、有用，而不只是“没有明显冲突”。

这些分数不是天然概率。若使用 LLM Judge，必须用人工标注样本校准阈值，分别测误放行和误拒答；高风险事实还要使用确定性引用白名单与业务规则。

适合 Self-RAG 的场景：问题开放、证据需求在生成过程中才显现，且额外反思延迟可接受。以下情况优先退回固定 2-Step RAG：

  • 基础链已经在目标切片稳定达标；
  • 延迟或成本预算只允许一次检索和一次生成；
  • 没有可信的反思评测集；
  • 反思模型与生成模型重复同一种偏差；
  • 任务要求路径高度可审计、不可循环。

即使启用 Self-RAG，也必须设置 max_reflections、整轮超时和明确拒答终态。不能让“支持度不足”触发无限自我修正。

10.2 Corrective RAG（CRAG）：先评价检索，再纠正 ​

CRAG 关注检索层：第一批文档到底可靠、含糊还是错误。最小实现可把检索评价离散成三类：

text
初始检索
  -> retrieval evaluator
      ├─ correct
      │    -> 保留高质量片段 -> knowledge refinement -> 生成
      ├─ ambiguous
      │    -> 扩大/改写查询 -> 合并并重新排序 -> 再评价一次
      └─ incorrect
           -> 丢弃低质候选 -> 查询可信备用来源
              -> 有证据则生成；否则拒答

评价信号不应只有向量分数，还可包括：

  • 期望实体、时间和条件是否覆盖；
  • 来源版本是否仍有效；
  • 多个候选是否冲突；
  • 查询中的子问题是否都有证据；
  • 权限过滤后是否仍有足够候选。

“查询备用来源”不能自动等于开放 Web Search。企业场景应使用显式允许列表、网络超时、内容安全检查和来源标记；外部页面仍是不可信数据，不能变成系统指令。

适合 CRAG 的场景：基础召回偶尔返回离题、过时或覆盖不足的候选，而且系统有可信的扩展查询或备用知识源。以下情况退回固定 RAG 或直接拒答：

  • 没有经过授权的备用来源；
  • Retrieval Evaluator 未经校准，纠错反而降低 Recall；
  • 原始知识库本来就没有答案；
  • 高风险场景不允许使用开放外部资料；
  • 纠错预算耗尽后仍是 ambiguous。

CRAG 也应是有限状态机，例如最多一次扩展检索。反复“评价不佳 → 再搜”并不会自动增加事实。

10.3 Adaptive RAG：按问题复杂度选择路径 ​

Adaptive RAG 解决的是：不是每个问题都值得走同样昂贵的流程。它把查询路由到有限策略，而不是给每条请求永久开启 Multi-Query、Rerank 和多轮反思。

最小控制流：

text
查询分类器/规则
  ├─ no_retrieval
  │    -> 问候、纯格式转换，直接响应
  ├─ single_step
  │    -> 一次授权检索 + 一次生成
  ├─ multi_step
  │    -> 查询分解/多查询 + 融合 + Rerank + 生成
  └─ human_review
       -> 高风险、冲突或预算不足

  • 是否需要最新或私有知识；

  • 是否为含糊的对话跟进；
  • 是否包含精确 ID，应该走业务工具或关键词检索；
  • 风险等级、延迟预算和剩余调用预算；
  • 基础检索的分数、覆盖与冲突诊断。

10.5 与 Agentic RAG 的边界 ​

设计控制面是否天然属于 Agentic RAG
Self-RAG 反思固定的“检索/评价/修正”步骤和有限重试否
CRAG固定三态评价和预先允许的纠错分支否
Adaptive RAG路由到预定义的有限管线否
Agentic RAG模型基于状态动态选择工具、知识源、步骤和停止时机是

当模型只在代码预先定义的几个 Edge 中选择，系统仍可以是确定性 Workflow。只有当它拥有更开放的行动集合，能动态规划检索、验证、浏览或工具调用时，才更接近 Agentic RAG。

边界不影响安全要求：无论叫什么，工具允许列表、权限前置、最大步数、总超时、引用校验和终态都必须由运行时强制执行。后续 Agentic RAG 章节会专门展开动态工具选择和规划，本页只保留有限、可评测的纠错闭环。

12. 完整离线高级检索程序 ​

下面程序不连接模型服务，完整展示权限前置、关键词/向量两路召回、RRF、启发式 Rerank、空证据拒答、冲突检测和引用。教学评分器用于理解数据流，不代表生产质量。

python
from __future__ import annotations

import math
import re
from collections import Counter, defaultdict
from dataclasses import dataclass, field
from typing import Literal


@dataclass(frozen=True)
class Chunk:
    chunk_id: str
    document_id: str
    tenant_id: str
    allowed_roles: frozenset[str]
    text: str
    claims: dict[str, str] = field(default_factory=dict)


@dataclass(frozen=True)
class Principal:
    tenant_id: str
    roles: frozenset[str]


@dataclass(frozen=True)
class Candidate:
    chunk: Chunk
    keyword_score: float
    vector_score: float
    fused_score: float
    rerank_score: float = 0.0


@dataclass(frozen=True)
class Response:
    status: Literal["answered", "refused", "needs_review"]
    answer: str
    citations: tuple[str, ...]
    reason: str


CONCEPTS = {
    "退款": "refund",
    "退货": "refund",
    "审核": "review",
    "工作日": "day",
    "多久": "duration",
    "多长时间": "duration",
    "物流": "shipping",
    "订单": "order",
}


def tokens(text: str) -> list[str]:
    lowered = text.lower()
    result = re.findall(r"[a-z0-9]+", lowered)
    for phrase, concept in CONCEPTS.items():
        if phrase in text:
            result.append(concept)
    if "how long" in lowered:
        result.append("duration")
    return result


def vector(text: str) -> Counter[str]:
    result = Counter(f"token:{token}" for token in tokens(text))
    compact = re.sub(r"\s+", " ", text.lower()).strip()
    for index in range(max(0, len(compact) - 2)):
        result[f"char3:{compact[index:index + 3]}"] += 0.1
    return result


def cosine(left: Counter[str], right: Counter[str]) -> float:
    if not left or not right:
        return 0.0
    dot = sum(value * right.get(key, 0.0) for key, value in left.items())
    if dot <= 0:
        return 0.0
    left_norm = math.sqrt(sum(value * value for value in left.values()))
    right_norm = math.sqrt(sum(value * value for value in right.values()))
    return dot / (left_norm * right_norm)


def authorized(chunk: Chunk, principal: Principal) -> bool:
    return (
        chunk.tenant_id == principal.tenant_id
        and not chunk.allowed_roles.isdisjoint(principal.roles)
    )


def keyword_score(query: str, chunk: Chunk) -> float:
    query_tokens = Counter(tokens(query))
    chunk_tokens = Counter(tokens(chunk.text))
    if not query_tokens:
        return 0.0
    overlap = sum(
        min(count, chunk_tokens.get(token, 0))
        for token, count in query_tokens.items()
    )
    return overlap / sum(query_tokens.values())


def fuse(
    keyword_rank: list[Chunk],
    vector_rank: list[Chunk],
    *,
    constant: int = 60,
) -> dict[str, float]:
    scores: dict[str, float] = defaultdict(float)
    for ranking in (keyword_rank, vector_rank):
        for rank, chunk in enumerate(ranking, start=1):
            scores[chunk.chunk_id] += 1.0 / (constant + rank)
    return scores


class AdvancedRetriever:
    def __init__(self, chunks: list[Chunk]) -> None:
        self._chunks = {chunk.chunk_id: chunk for chunk in chunks}

    def search(
        self,
        query: str,
        principal: Principal,
        *,
        candidate_k: int = 8,
        top_n: int = 4,
        min_relevance: float = 0.18,
    ) -> list[Candidate]:
        if not query.strip():
            raise ValueError("query must not be blank")
        if candidate_k < 1 or top_n < 1:
            raise ValueError("candidate_k and top_n must be positive")

        # 权限过滤在任何评分之前执行。
        visible = [
            chunk
            for chunk in self._chunks.values()
            if authorized(chunk, principal)
        ]

        keyword_scores = {
            chunk.chunk_id: keyword_score(query, chunk) for chunk in visible
        }
        query_vector = vector(query)
        vector_scores = {
            chunk.chunk_id: cosine(query_vector, vector(chunk.text))
            for chunk in visible
        }

        keyword_rank = sorted(
            [chunk for chunk in visible if keyword_scores[chunk.chunk_id] > 0],
            key=lambda chunk: (-keyword_scores[chunk.chunk_id], chunk.chunk_id),
        )[:candidate_k]
        vector_rank = sorted(
            [chunk for chunk in visible if vector_scores[chunk.chunk_id] > 0],
            key=lambda chunk: (-vector_scores[chunk.chunk_id], chunk.chunk_id),
        )[:candidate_k]

        fused = fuse(keyword_rank, vector_rank)
        if not fused:
            return []

        max_fused = max(fused.values())
        query_tokens = set(tokens(query))
        candidates: list[Candidate] = []
        for chunk_id, fused_score in fused.items():
            chunk = self._chunks[chunk_id]
            content_tokens = set(tokens(chunk.text))
            coverage = (
                len(query_tokens & content_tokens) / len(query_tokens)
                if query_tokens
                else 0.0
            )
            duration_bonus = float(
                "duration" in query_tokens and "day" in content_tokens
            )
            rerank_score = min(
                1.0,
                0.65 * coverage
                + 0.20 * duration_bonus
                + 0.15 * (fused_score / max_fused),
            )
            if rerank_score >= min_relevance:
                candidates.append(
                    Candidate(
                        chunk=chunk,
                        keyword_score=keyword_scores[chunk_id],
                        vector_score=vector_scores[chunk_id],
                        fused_score=fused_score,
                        rerank_score=rerank_score,
                    )
                )

        candidates.sort(
            key=lambda item: (
                -item.rerank_score,
                -item.fused_score,
                item.chunk.chunk_id,
            )
        )
        return candidates[:top_n]


def find_conflicts(candidates: list[Candidate]) -> set[str]:
    values: dict[str, set[str]] = defaultdict(set)
    documents: dict[str, set[str]] = defaultdict(set)
    for candidate in candidates:
        for key, value in candidate.chunk.claims.items():
            values[key].add(value.strip().casefold())
            documents[key].add(candidate.chunk.document_id)
    return {
        key
        for key in values
        if len(values[key]) > 1 and len(documents[key]) > 1
    }


def answer(
    retriever: AdvancedRetriever,
    query: str,
    principal: Principal,
) -> Response:
    evidence = retriever.search(query, principal)
    if not evidence:
        return Response(
            status="refused",
            answer="现有授权资料不足，无法确认。",
            citations=(),
            reason="no_authorized_evidence",
        )

    conflicts = find_conflicts(evidence)
    if conflicts:
        return Response(
            status="needs_review",
            answer="授权资料存在冲突，需要人工核验。",
            citations=tuple(item.chunk.chunk_id for item in evidence),
            reason="conflicting_authorized_evidence",
        )

    best = evidence[0].chunk
    return Response(
        status="answered",
        answer=best.text,
        citations=(best.chunk_id,),
        reason="grounded_in_authorized_evidence",
    )


def base_chunks() -> list[Chunk]:
    return [
        Chunk(
            chunk_id="acme/refund/2026-07/0",
            document_id="acme/refund/2026-07",
            tenant_id="acme",
            allowed_roles=frozenset({"support", "admin"}),
            text="退款申请需要审核，审核通常在三个工作日内完成。",
            claims={"refund.review_duration": "three business days"},
        ),
        Chunk(
            chunk_id="acme/shipping/2026-06/0",
            document_id="acme/shipping/2026-06",
            tenant_id="acme",
            allowed_roles=frozenset({"support", "admin"}),
            text="订单物流状态会在承运商扫描包裹后更新。",
        ),
        Chunk(
            chunk_id="other/refund/2026-07/0",
            document_id="other/refund/2026-07",
            tenant_id="other",
            allowed_roles=frozenset({"support", "admin"}),
            text="退款不需要审核，会立即完成。",
            claims={"refund.review_duration": "immediate"},
        ),
    ]


def main() -> None:
    principal = Principal("acme", frozenset({"support"}))
    retriever = AdvancedRetriever(base_chunks())

    grounded = answer(retriever, "退款审核需要多久？", principal)
    print(grounded.status, grounded.citations)

    refused = answer(retriever, "公司年假是多少？", principal)
    print(refused.status, refused.reason)

    conflict = Chunk(
        chunk_id="acme/refund/2026-08/0",
        document_id="acme/refund/2026-08",
        tenant_id="acme",
        allowed_roles=frozenset({"support"}),
        text="退款审核通常在五个工作日内完成。",
        claims={"refund.review_duration": "five business days"},
    )
    conflicting = answer(
        AdvancedRetriever([*base_chunks(), conflict]),
        "退款审核需要多久？",
        principal,
    )
    print(conflicting.status, conflicting.reason)


if __name__ == "__main__":
    main()

故障可选策略不能做什么

一路检索失败使用另一路并标记 degraded假装双路成功
Reranker 超时使用 RRF 排名返回随机顺序
生成超时返回稳定 timeout把半截文本当最终答案
引用非法失败或有限修复删除引用后照常回答
证据冲突needs_review随机挑一个事实
无授权证据refused使用模型记忆猜测

降级会改变质量和风险，必须写入响应或内部诊断，并独立评测。

18. 常见错误 ​

18.1 所有策略永久开启 ​

成本上升、延迟变长，错误来源更多。用评测决定哪些 Query Slice 需要哪种策略。

18.2 Multi-Query 结果直接拼接 ​

相同 Chunk 会重复，某一路结果会因数量多占据上下文。按稳定 ID 去重并融合排名。

18.3 Rerank 候选太少 ​

若正确证据未进入候选，精排无法创造它。先优化 Recall 和 Candidate K，再调 Reranker。

18.4 把 Reranker 分数当概率 ​

分数通常未校准，跨模型和查询不可直接解释。门槛由验证集确定。

18.5 HyDE 文本进入最终证据 ​

假设文档不是事实来源，只能作为检索查询表示。

18.6 权限后过滤 ​

无权数据已经影响 BM25、向量排名或 RRF。过滤必须在每路评分前。

18.7 旧版本和新版本同时回答 ​

接入 Manifest、版本优先和删除流程缺失。需要冲突检测与发布原子性。

18.8 只评最终答案 ​

无法判断是接入、召回、排序还是生成失败。保存分层指标和中间 ID。

20. 动手练习 ​

练习一：RRF 边界 ​

为 reciprocal_rank_fusion() 增加空列表、重复 ID、相同分数和非法常数测试。保证并列时按稳定 ID 确定排序。

练习二：权限前置证明 ​

用 Spy 替换关键词和向量评分函数，断言另一个租户的 Chunk 从未进入任何评分器。

练习三：Multi-Query ​

用 Fake Model 返回三条固定改写，分别检索并 RRF。记录新增召回、额外延迟和重复率，与单查询基线比较。

练习四：Parent-Child ​

为每个 Child 设置 parent_id。检索 Child 后按 Parent 去重，证明同一 Parent 不会占用多个上下文位置。

练习五：Reranker 降级 ​

实现一个会超时的 Fake Reranker。超时后返回 RRF 排名，并在诊断中设置 degraded_reason=reranker_timeout。

练习六：冲突与引用 ​

准备两个授权版本，对同一 Claim 给出不同值。结果必须是 needs_review；伪造不在证据集合中的引用必须失败。

练习七：评测报告 ​
