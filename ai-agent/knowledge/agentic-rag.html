Agentic RAG ​

基础 2-Step RAG 的执行顺序是固定的：

text
问题 -> 检索一次 -> 生成一次 -> 结束
1

Agentic RAG 把部分决策交给 Agent 或显式工作流：

text
是否需要检索？
应该查知识库、网页、SQL 还是业务 API？
一次检索是否足够？
证据不相关时要不要改写问题？
多个来源冲突时如何继续？
何时停止并拒答？
1
2
3
4
5
6

它的目标不是让 RAG 看起来更“智能”，而是在固定链无法处理数据源路由、多步问题和检索纠错时，引入受限、可观察、可终止的动态决策。

本章使用项目已锁定版本：

text
langchain==1.3.14
langchain-core==1.4.9
langgraph==1.2.9
pydantic==2.13.4
1
2
3
4

框架控制流可用确定性 Fake Model/离线检索器验证。真实语义检索、模型判断和网页搜索仍取决于最终选定的 Embedding、模型与数据源集成，必须另行锁定和评测。

1. 什么时候不需要 Agentic RAG ​

以下需求优先使用固定 RAG：

  • 单一知识库；
  • 问题清晰；
  • 一次 Top-K 检索通常能找到证据；
  • 延迟和成本敏感；
  • 需要稳定、容易回归的行为；
  • 还没有建立基础 RAG 评测集。

先优化：

text
文档解析
-> 切分
-> Embedding
-> 权限过滤
-> Hybrid Retrieval
-> Rerank
-> 引用与拒答
1
2
3
4
5
6
7

如果这些基础环节没有做好，加入 Agent 只会让错误路径更多。

适合升级 Agentic RAG 的信号：

  • 不同问题需要不同数据源；
  • 问题需要分解为多个子问题；
  • 第一次检索失败后，查询改写能显著提升召回；
  • 需要比较多个来源或核验冲突；
  • 工具调用与检索需要交替执行；
  • 需要显式的相关性、完整性或事实验证步骤。

3. 固定 RAG 与 Agentic RAG 的差异 ​

维度固定 2-Step RAGAgentic RAG
控制流预先确定运行时路由/循环
数据源通常一个可动态选择多个
检索次数通常一次0 到有限多次
延迟与成本较稳定波动更大
调试链路简单需要轨迹与 State
终止自然结束必须显式限制
评测检索 + 答案还要评测工具选择和轨迹

Agentic RAG 的复杂度只有在质量收益超过成本时才合理。

5. 用 LangChain 创建第一个 RAG Agent ​

5.1 把 Retriever 封装为工具 ​

python
from dataclasses import dataclass
from typing import Annotated

from langchain.tools import ToolRuntime, tool


@dataclass(frozen=True)
class RequestContext:
    tenant_id: str
    user_id: str
    role: str


@tool
def search_knowledge(
    query: Annotated[str, "可独立检索的具体问题"],
    runtime: ToolRuntime[RequestContext],
) -> dict:
    """搜索当前租户已授权的企业制度和产品知识。"""
    documents = retriever.invoke(
        query,
        config={
            "metadata": {
                "tenant_id": runtime.context.tenant_id,
                "role": runtime.context.role,
            }
        },
    )

    return {
        "query": query,
        "evidence": [
            {
                "chunk_id": document.metadata["chunk_id"],
                "source_id": document.metadata["source_id"],
                "text": document.page_content,
                "version": document.metadata.get("version"),
            }
            for document in documents
        ],
    }

7. 为什么复杂 Agentic RAG 更适合 LangGraph ​

create_agent() 适合模型驱动的工具循环。如果流程要求：

  • 检索后必须经过相关性评分；
  • 最多重写两次；
  • 冲突时进入固定分支；
  • 每一步都有明确 State；
  • 能从 Checkpoint 恢复；
  • 必须证明不会无限循环；

则应使用显式 LangGraph。

text
START
  -> retrieve
  -> grade
      ├─ enough -> generate -> END
      ├─ retry  -> rewrite -> retrieve
      └─ refuse -> END

9. 一个可运行的离线 LangGraph Agentic RAG ​

下面使用 langgraph==1.2.9 和标准库构建完整闭环。关键词 Retriever 和确定性生成器是教学替代物，但 State、路由、循环上限与终态是真实 LangGraph 控制流。

python
from __future__ import annotations

import re
from typing import Literal, TypedDict

from langgraph.graph import END, START, StateGraph


class RAGState(TypedDict):
    question: str
    query: str
    evidence: list[dict]
    used_queries: list[str]
    attempts: int
    max_attempts: int
    decision: Literal["retrieve", "retry", "generate", "refuse"]
    answer: str
    citations: list[str]
    failure_reason: str | None


KNOWLEDGE = [
    {
        "chunk_id": "refund-policy#review",
        "text": "退款审核通常需要三个工作日。",
        "tenant_id": "acme",
        "version": "2026-07",
    },
    {
        "chunk_id": "refund-policy#delay",
        "text": "超过三个工作日仍未完成，可提交人工工单。",
        "tenant_id": "acme",
        "version": "2026-07",
    },
    {
        "chunk_id": "other#secret",
        "text": "退款立即完成。",
        "tenant_id": "other",
        "version": "2026-07",
    },
]


def terms(text: str) -> set[str]:
    words = re.findall(r"[a-zA-Z0-9]+", text.casefold())
    chinese = re.findall(r"[\u4e00-\u9fff]", text)
    return set(words + chinese)


def retrieve(state: RAGState) -> dict:
    query_terms = terms(state["query"])
    scored: list[tuple[float, dict]] = []

    for chunk in KNOWLEDGE:
        # 教学中固定当前租户，生产应来自 Runtime Context。
        if chunk["tenant_id"] != "acme":
            continue
        chunk_terms = terms(chunk["text"])
        score = len(query_terms & chunk_terms)
        if score > 0:
            scored.append((float(score), chunk))

    evidence = [
        {**chunk, "score": score}
        for score, chunk in sorted(
            scored,
            key=lambda item: (-item[0], item[1]["chunk_id"]),
        )[:3]
    ]

    return {
        "evidence": evidence,
        "attempts": state["attempts"] + 1,
        "used_queries": [*state["used_queries"], state["query"]],
    }


def grade_evidence(state: RAGState) -> dict:
    if state["evidence"]:
        return {"decision": "generate", "failure_reason": None}

    if state["attempts"] >= state["max_attempts"]:
        return {
            "decision": "refuse",
            "failure_reason": "retrieval_exhausted",
        }

    return {
        "decision": "retry",
        "failure_reason": "no_relevant_evidence",
    }


def rewrite_query(state: RAGState) -> dict:
    # 确定性教学改写；真实系统可替换为结构化模型调用。
    normalized = " ".join(state["question"].split())
    supported_terms = ("退款", "退货", "审核")
    if not any(term in normalized for term in supported_terms):
        return {
            "decision": "refuse",
            "failure_reason": "rewrite_not_supported",
        }

    candidate = f"退款 审核 时长 {normalized}"

    if candidate in state["used_queries"]:
        return {
            "decision": "refuse",
            "failure_reason": "no_query_progress",
        }

    return {"query": candidate, "decision": "retrieve"}


def generate_answer(state: RAGState) -> dict:
    if not state["evidence"]:
        raise ValueError("generation requires evidence")

    citations = [
        chunk["chunk_id"] for chunk in state["evidence"]
    ]
    evidence_text = "；".join(
        chunk["text"] for chunk in state["evidence"]
    )
    return {
        "answer": f"根据授权证据：{evidence_text}",
        "citations": citations,
        "decision": "generate",
    }


def refuse(state: RAGState) -> dict:
    return {
        "answer": "没有找到足够的授权证据，无法确认。",
        "citations": [],
        "decision": "refuse",
    }


def after_grade(
    state: RAGState,
) -> Literal["generate", "rewrite", "refuse"]:
    return {
        "generate": "generate",
        "retry": "rewrite",
        "refuse": "refuse",
    }[state["decision"]]


def after_rewrite(
    state: RAGState,
) -> Literal["retrieve", "refuse"]:
    return (
        "refuse"
        if state["decision"] == "refuse"
        else "retrieve"
    )


builder = StateGraph(RAGState)
builder.add_node("retrieve", retrieve)
builder.add_node("grade", grade_evidence)
builder.add_node("rewrite", rewrite_query)
builder.add_node("generate", generate_answer)
builder.add_node("refuse", refuse)

builder.add_edge(START, "retrieve")
builder.add_edge("retrieve", "grade")
builder.add_conditional_edges(
    "grade",
    after_grade,
    {
        "generate": "generate",
        "rewrite": "rewrite",
        "refuse": "refuse",
    },
)
builder.add_conditional_edges(
    "rewrite",
    after_rewrite,
    {
        "retrieve": "retrieve",
        "refuse": "refuse",
    },
)
builder.add_edge("generate", END)
builder.add_edge("refuse", END)

app = builder.compile()


def initial_state(question: str) -> RAGState:
    return {
        "question": question,
        "query": question,
        "evidence": [],
        "used_queries": [],
        "attempts": 0,
        "max_attempts": 2,
        "decision": "retrieve",
        "answer": "",
        "citations": [],
        "failure_reason": None,
    }


if __name__ == "__main__":
    result = app.invoke(initial_state("退款审核需要几天？"))
    print(result["answer"])
    print(result["citations"])
    print(result["used_queries"])

9.1 这个图为什么能终止 ​

存在三个终止保障：

  1. 有证据时进入 generate -> END；
  2. attempts >= max_attempts 时进入 refuse -> END；
  3. 改写没有产生新 Query 时进入 refuse -> END。

仅设置 LangGraph recursion limit 是最后保护，不应替代业务终止逻辑。

            "question": state["question"],
            "evidence": format_evidence(state["evidence"]),
        }
    )
    answer = structured_model.invoke(prompt_value)
    return {
        "answer": answer.answer,
        "citations": answer.citations,
    }

17. 无进展检测 ​

仅比较 Query 字符串不够。Agent 可能反复换词但得到相同证据。

python
def evidence_signature(evidence: list[dict]) -> tuple[str, ...]:
    return tuple(sorted(item["chunk_id"] for item in evidence))


def made_progress(
    previous_evidence: list[dict],
    current_evidence: list[dict],
) -> bool:
    return evidence_signature(previous_evidence) != evidence_signature(
        current_evidence
    )

21. Agentic RAG 的可观测性 ​

每次运行至少记录：

  • 原始问题；
  • 每次 Query 与改写原因；
  • 选择的数据源和工具；
  • 每次检索的文档 ID、版本和分数；
  • 相关性/完整性判断；
  • 路由与终止原因；
  • 模型和 Prompt 版本；
  • Token、延迟和费用；
  • 最终引用；
  • 权限策略版本。

默认不要把完整敏感证据写入 Trace。记录 ID、哈希和脱敏摘要。

22. 怎样评测 Agentic RAG ​

除了普通 RAG 指标，还要评测决策轨迹：

22.1 路由指标 ​

  • 是否需要检索的判断准确率；
  • 数据源选择 Precision/Recall；
  • 不应调用的工具是否被调用；
  • 越权工具暴露率。

22.2 检索循环指标 ​

  • 首次检索成功率；
  • 改写后 Recall 提升；
  • 平均检索次数；
  • 无效重复 Query 比例；
  • 达到上限比例；
  • 正确拒答率。

22.3 答案指标 ​

  • Faithfulness；
  • 引用正确性；
  • 子问题覆盖率；
  • 冲突披露率；
  • 答案完整性。

22.4 系统指标 ​

  • P50/P95 延迟；
  • 模型和检索调用次数；
  • 单问题成本；
  • 上游失败恢复率；
  • Checkpoint 恢复正确率。

24. 常见失败路径 ​

24.1 所有问题都调用所有 Retriever ​

这不是 Agentic RAG，只是更昂贵的并行检索。修正数据源路由与工具描述。

24.2 相关性评分器总说“相关” ​

建立带正负样本的标注集，测试部分相关、关键词相同但语义错误、过期和越权证据。

24.3 Query 不断改写但结果相同 ​

加入 Query 去重、Evidence Signature 和最大尝试次数，触发 no_query_progress。

24.4 Web 内容改变了 Agent 指令 ​

将 Web 内容标为不可信数据，使用域名允许列表、Prompt Injection 检测和最小工具权限。

24.5 SQL/业务 API 被当成文本检索 ​

结构化实时事实应使用参数化 Tool/API 查询，不能让模型生成任意 SQL 后直接执行。

24.6 最终回答有引用，但引用不支持结论 ​

引用存在性校验不够。增加 Claim-Citation 对齐评测和人工抽样。

24.7 延迟不可控 ​

记录每轮调用，设置并行边界、超时、调用上限和降级路径；简单问题路由回固定 RAG。

25. 动手练习 ​

练习一：Retriever Tool ​

把前面 LangChain RAG 的 Retriever 封装成 search_knowledge，让 Fake Model 产生一次工具调用并检查完整消息轨迹。

练习二：数据源路由 ​

准备政策、产品手册和订单 API 三个工具，建立 60 个问题标注集，计算路由准确率与不必要调用数。

练习三：检索纠错图 ​

运行本章离线 LangGraph，加入 partial 分支：证据只覆盖一部分问题时先生成子问题再检索。

练习四：冲突证据 ​

加入两个不同版本政策。让图识别冲突，选择权威新版本或进入人工处理，不能静默拼接。

练习五：无进展与预算 ​

构造永远无结果的 Retriever，证明 Query 去重、Evidence Signature、模型次数和总耗时任一限制都能终止运行。

练习六：基线对比 ​

用同一评测集比较固定 RAG 与 Agentic RAG 的 Recall、Faithfulness、延迟、成本和正确拒答率。

26. 本章验收标准 ​

完成本章后，你应该能够：

  • 判断什么时候应继续使用固定 RAG；
  • 区分 Router、Tool-Using、Corrective 和多步研究型 RAG；
  • 使用 LangChain create_agent() 把 Retriever 作为工具；
  • 使用 Runtime Context 和 Middleware 隔离数据源权限；
  • 为复杂检索设计显式 LangGraph State；
  • 实现检索、评分、改写、生成和拒答节点；
  • 用最大尝试与无进展检测证明图可终止；
  • 组合知识库、Web、SQL/API，但保留来源信任边界；
  • 校验最终引用只能来自授权 Evidence；
  • 评测数据源路由、检索轨迹、答案和系统成本；
  • 用固定 RAG 基线证明引入 Agent 的实际收益。

如果系统只是让模型无限调用搜索工具，既没有 State、上限、拒答和轨迹评测，就不是可靠的 Agentic RAG。
