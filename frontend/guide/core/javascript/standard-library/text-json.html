String、RegExp 与 JSON ​

字符串、正则表达式和 JSON 共同承担文本处理与数据交换，但它们工作在不同层次：String 操作 UTF-16 文本，RegExp 描述模式匹配，JSON 在有限的数据模型中完成序列化和解析。

String 数据模型 ​

字符串是不可变的 UTF-16 码元序列。length 统计码元，不一定等于 Unicode 码点或用户看到的字符数量。

js
const text = 'A😀'

text.length        // 3
[...text].length   // 2，按码点迭代
text.at(1)         // 高代理项，不是完整 emoji

组合字符、肤色、ZWJ emoji 等还可能由多个码点构成一个字素簇。按用户可见字符切分时使用 Intl.Segmenter，不要只依赖 split('') 或展开语法。

String API ​

创建与静态方法 ​

  • String(value)：转换为字符串；不推荐 new String() 包装对象。
  • String.fromCharCode()：从 UTF-16 码元创建字符串。
  • String.fromCodePoint()：从 Unicode 码点创建字符串。
  • String.raw()：获取模板字面量的原始转义文本。
js
String.fromCodePoint(0x1F600) // '😀'
String.raw`a\nb`              // 'a\\nb'
1
2

访问、查询与比较 ​

API作用
at(index)按码元访问，支持负索引
charAt(index)按码元访问，越界返回空字符串
charCodeAt(index)返回 UTF-16 码元值
codePointAt(index)返回起始位置的 Unicode 码点
includes(search, position?)是否包含子串
startsWith(search, position?)是否以子串开始
endsWith(search, endPosition?)是否以子串结束
indexOf(search, position?)首次出现位置
lastIndexOf(search, position?)最后出现位置
localeCompare(other, locales?, options?)本地化比较

面向用户的排序优先使用复用的 Intl.Collator，而不是在大数组比较函数中反复创建本地化配置。

截取、组合与填充 ​

  • slice(start?, end?)：支持负索引，推荐作为通用截取 API。
  • substring(start?, end?)：负值按 0 处理，并可能交换起止位置。
  • concat(...strings)：连接字符串；模板字面量和 + 通常更直观。
  • repeat(count)：重复字符串。
  • padStart(targetLength, fillString?)、padEnd()：填充到目标码元长度。
  • split(separator?, limit?)：按字符串或正则拆分。

已弃用的 substr() 不应出现在新代码中。

大小写、空白和 Unicode ​

  • toLowerCase()、toUpperCase()
  • toLocaleLowerCase()、toLocaleUpperCase()
  • trim()、trimStart()、trimEnd()；trimLeft()、trimRight() 是别名
  • normalize(form?)：Unicode 规范化，支持 NFC、NFD、NFKC、NFKD
  • isWellFormed()：判断是否含孤立代理项
  • toWellFormed()：用替换字符处理孤立代理项
js
const composed = 'é'
const decomposed = 'e\u0301'

composed === decomposed                 // false
composed === decomposed.normalize('NFC') // true

  • toString()、valueOf()
  • [Symbol.iterator]()：按 Unicode 码点迭代
  • 实例属性：length

已弃用 HTML 包装方法 ​

anchor()、big()、blink()、bold()、fixed()、fontcolor()、fontsize()、italics()、link()、small()、strike()、sub()、sup() 已弃用。HTML 应通过 DOM API 或模板生成，并进行上下文安全处理。

RegExp ​

创建与转义 ​

js
const literal = /user-(\d+)/i
const dynamic = new RegExp(`^${RegExp.escape(userInput)}$`, 'u')
1
2
  • 正则字面量适合静态模式。
  • RegExp(pattern, flags?) 适合动态模式。
  • RegExp.escape(string) 将普通文本转义为可安全嵌入正则的模式片段。

不要只手写替换少数特殊字符；边界字符和转义序列比常见元字符更复杂。

标志 ​

标志属性含义
dhasIndices返回匹配及捕获组索引
gglobal全局匹配，使用 lastIndex
iignoreCase忽略大小写
mmultiline^、$ 按行工作
sdotAll. 匹配换行符
uunicodeUnicode 模式和码点语义
vunicodeSetsUnicode 集合模式与集合运算
ysticky只从 lastIndex 精确位置匹配

flags 返回规范顺序的完整标志字符串，source 返回模式文本。

实例 API ​

  • 可写状态：lastIndex
  • 属性：dotAll、flags、global、hasIndices、ignoreCase、multiline、source、sticky、unicode、unicodeSets
  • 方法：exec()、test()、toString()
  • 协议方法：[Symbol.match]()、[Symbol.matchAll]()、[Symbol.replace]()、[Symbol.search]()、[Symbol.split]()
  • 已弃用：compile()

String 的匹配 API 会通过这些 Symbol 协议调用模式对象，因此自定义对象也能参与匹配协议。

RegExp.$1 到 RegExp.$9、RegExp.input、RegExp.lastMatch 等静态匹配状态属于非标准遗留扩展，不应在新代码中使用。

捕获组与反向引用 ​

js
const datePattern = /^(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})$/
const match = datePattern.exec('2026-07-18')

match.groups.year // '2026'

3
4
  • (...)：编号捕获组
  • (?<name>...)：命名捕获组
  • (?:...)：非捕获组
  • \1、\k<name>：反向引用
  • (?=...)、(?!...)：前瞻
  • (?<=...)、(?<!...)：后顾

不需要结果时使用非捕获组，避免无意义的捕获数据。

lastIndex 与状态 ​

带 g 或 y 的正则会修改 lastIndex。复用同一个实例进行 test() 可能出现交替结果。

js
const pattern = /a/g

pattern.test('a') // true，lastIndex = 1
pattern.test('a') // false，lastIndex 重置
1
2
3
4

共享正则前应明确状态管理，或为每次独立匹配创建新实例。

性能与安全 ​

嵌套量词、重叠分支和缺少边界的模式可能产生灾难性回溯。对不可信长文本：

  • 限制输入长度。
  • 避免 (a+)+ 一类嵌套量词。
  • 使用明确锚点和互斥分支。
  • 测试接近失败路径的输入，而不只测试成功样例。
  • 正则不适合解析任意嵌套语法或完整 HTML。

JSON ​

JSON 支持对象、数组、字符串、有限 Number、布尔值和 null。它不保留原型、方法、Symbol、BigInt、undefined、循环引用以及 Map/Set 语义。

JSON API ​

  • JSON.parse(text, reviver?)
  • JSON.stringify(value, replacer?, space?)
  • JSON.rawJSON(text)
  • JSON.isRawJSON(value)

parse 与 reviver ​

js
const value = JSON.parse(
  '{"createdAt":"2026-07-18T00:00:00.000Z"}',
  (key, current) =>
    key === 'createdAt' ? new Date(current) : current
)

reviver 按从叶子到根的顺序调用。返回 undefined 会删除对应属性；根值也会经过 reviver。

较新的实现会向原始值的 reviver 提供包含 source 的上下文参数，可用于在 Number 已发生精度损失前读取原始文本。使用前检查兼容性。

stringify 与 replacer ​

js
const json = JSON.stringify(
  { id: 1, password: 'secret', tags: new Set(['a', 'b']) },
  (key, value) => {
    if (key === 'password') return undefined
    if (value instanceof Set) return [...value]
    return value
  },
  2
)

  • replacer 函数可以转换或排除值。
  • replacer 数组只保留列出的字符串或数字属性键。
  • space 控制缩进，最多使用 10 个字符或 10 个空格。
  • 对象属性值为 undefined、函数或 Symbol 时会被忽略。
  • 数组中的这些值会序列化为 null。
  • NaN、Infinity 和 -Infinity 序列化为 null。
  • BigInt 默认抛出 TypeError。

对象可以通过 toJSON(key) 自定义序列化结果，Date 就使用该机制输出 ISO 字符串。

rawJSON ​

JSON.rawJSON(text) 创建一个特殊值，使其内部合法 JSON 文本在外层 stringify() 时作为原始 JSON 插入，而不是再次作为字符串转义。

js
const precise = JSON.rawJSON('12345678901234567890')
JSON.stringify({ value: precise })
// '{"value":12345678901234567890}'

JSON.isRawJSON(precise) // true

传入文本必须表示一个 JSON 原始值。原始插入不会自动让 JavaScript Number 获得更高精度；解析端仍需采用合适策略。

安全边界 ​

  • JSON.parse() 不执行文本中的 JavaScript，比 eval() 安全，但解析后的数据仍然不可信。
  • 在使用前校验结构、类型、长度和业务约束。
  • 不要把未知对象直接合并到安全敏感配置，尤其要处理 __proto__、constructor 等键。
  • JSON 不是加密、签名或权限边界。

常见错误 ​

  • 用 length 当作用户可见字符数量。
  • 用 split('') 拆分 emoji 或组合字符。
  • 动态拼接正则却不使用 RegExp.escape()。
  • 复用带 g/y 的正则但忽略 lastIndex。
  • 用复杂正则解析嵌套语言。
  • 认为 JSON 能无损保存所有 JavaScript 值。
  • 用 JSON.parse(JSON.stringify(value)) 充当通用深复制。
  • 解析 JSON 后不做运行时校验。
