大文件上传、下载与断点续传 ​

文件一旦大到无法在一次请求、一次页面会话或一份浏览器内存中稳定完成，问题就不再是“给 FormData 增加一个字段”。前端需要和服务端共同定义分片、幂等、校验、恢复和过期语义，还要区分上传进度、服务端确认进度与文件最终可用状态。

本文使用一个 5 GiB 视频素材上传案例贯穿方案。用户可能使用不稳定网络，暂停或刷新页面后需要继续上传；上传完成后，有权限的用户还需要下载同一个不可变文件版本。示例只展开前端依赖的接口契约，不讨论对象存储、数据库和服务端合并实现。

完整链路如下：

text
选择文件并确认约束
  -> 建立上传会话
  -> 切分并校验缺失分片
  -> 有限并发上传
  -> 服务端确认分片
  -> 完成校验并生成文件版本
  -> 获取短时下载入口
  -> 浏览器按文件版本下载或恢复

问题场景与失败定位 ​

最直接的上传和下载实现会把整个文件重新读入内存：

ts

  const bytes = await file.arrayBuffer()
  await fetch('/api/uploads', {
    method: 'POST',
    body: bytes
  })
}

async function downloadAsBlob(url: string) {
  const response = await fetch(url)
  const blob = await response.blob()
  const objectUrl = URL.createObjectURL(blob)

  const anchor = document.createElement('a')
  anchor.href = objectUrl
  anchor.download = 'video.mp4'
  anchor.click()
  URL.revokeObjectURL(objectUrl)
}

它们在小文件中可以工作，但放到 5 GiB 场景会同时触发多类问题：

现象优先检查常见原因
请求开始前页面已经卡住Memory、PerformancearrayBuffer() 复制整个文件，哈希在主线程执行
固定时间后失败状态码、网关日志请求体或超时超过网关限制
网络抖动后从零开始已确认分片与重试记录协议只有一个不可恢复请求
进度到 100% 后仍等待上传响应与完成接口只统计浏览器发送字节，没有服务端校验和完成阶段
刷新后找不到任务本地恢复记录、上传会话页面只保存了内存状态
下载时内存快速上升Response、Blob、Heap先把完整响应缓存为 Blob 再触发下载
续传后文件损坏分片边界、摘要、文件版本重传覆盖错误、拼接顺序错误或混用了两个版本

案例约束 ​

先写清约束，才能决定是否需要分片：

约束案例取值
单文件大小常见 2～5 GiB，上限 10 GiB
普通请求限制网关请求体上限 100 MiB，60 秒超时
运行环境当前两个主要版本的桌面 Chrome、Edge 和 Safari
恢复要求暂停后可继续；刷新后重新选择同一文件可恢复
上传会话24 小时有效，过期后重新初始化
内存预算上传模块额外占用尽量低于 128 MiB
安全要求服务端重新授权、校验大小与内容，完成扫描前不可下载

本文处理的是浏览器已有文件的传输，不重复技术方案、评审与决策记录中的服务端异步导出任务，也不展开文件预览、打印和格式转换。

一、按规模选择传输方式 ​

分片会增加协议、请求数和清理成本，不应成为所有文件的默认方案：

方式适用场景优点主要代价
单次 FormData 或 PUT文件明显低于请求体和超时上限实现最短，事务边界清楚失败后通常从零重传
业务文件服务分片已有统一鉴权、审计和文件服务契约可按业务控制前后端共同维护协议
存储服务原生分片直传大流量，应用服务不应转发字节减少应用服务器带宽签名、CORS、过期和完成流程更复杂
tus 等标准续传协议新系统且服务端可以接入标准协议少自定义恢复语义，客户端生态成熟需要协议服务和现有鉴权集成

案例已有文件服务，并且它能够保证分片幂等和最终校验，因此采用显式分片契约。若是新系统，应先评估 tus 或存储服务的原生 Multipart 能力，不要仅为了练习而发明另一套私有协议。

案例选择 16 MiB 分片、最多 3 个并发请求。5 GiB 文件约产生 320 个分片，单次失败最多重传 16 MiB；同时读取三个分片时，摘要缓冲区约占 48 MiB，连同网络和页面开销仍在预算内。这些数值是当前约束下的起点，不是通用常量。

三、识别文件与校验分片 ​

刷新页面后，浏览器通常不能自动重新获得用户选择的 File。基线方案要求用户重新选择文件，再用本地指纹确认它是否对应原上传会话。

1. 快速指纹只用于匹配 ​

读取文件头尾样本和元数据，可以避免在上传前完整扫描 5 GiB 文件：

ts
const SAMPLE_SIZE = 64 * 1024

function arrayBufferToBase64(buffer: ArrayBuffer): string {
  let binary = ''
  for (const byte of new Uint8Array(buffer)) {
    binary += String.fromCharCode(byte)
  }
  return btoa(binary)
}

export async function sha256Base64(blob: Blob): Promise<string> {
  const bytes = await blob.arrayBuffer()
  const digest = await crypto.subtle.digest('SHA-256', bytes)
  return arrayBufferToBase64(digest)
}

export async function createFileFingerprint(file: File): Promise<string> {
  const metadata = JSON.stringify({
    name: file.name,
    size: file.size,
    type: file.type,
    lastModified: file.lastModified
  })
  const first = file.slice(0, Math.min(SAMPLE_SIZE, file.size))
  const last = file.slice(Math.max(0, file.size - SAMPLE_SIZE))

  return sha256Base64(new Blob([metadata, first, last]))
}

2. 分片摘要控制内存上限 ​

Blob.slice() 创建的是文件范围视图，不会先复制完整文件。只有计算当前分片摘要时才读取这一段：

ts
export type UploadPart = {
  partNumber: number
  start: number
  end: number
  blob: Blob
}

export function createMissingParts(
  file: File,
  partSize: number,
  uploadedParts: UploadedPart[]
): UploadPart[] {
  if (!Number.isInteger(partSize) || partSize <= 0) {
    throw new RangeError('partSize must be a positive integer')
  }

  const confirmed = new Set(uploadedParts.map((part) => part.partNumber))
  const count = Math.ceil(file.size / partSize)
  const result: UploadPart[] = []

  for (let index = 0; index < count; index += 1) {
    const partNumber = index + 1
    if (confirmed.has(partNumber)) continue

    const start = index * partSize
    const end = Math.min(file.size, start + partSize)
    result.push({
      partNumber,
      start,
      end,
      blob: file.slice(start, end)
    })
  }

  return result
}

四、上传一个分片并报告进度 ​

Fetch 目前没有覆盖主要目标浏览器的统一上传进度事件。示例只在分片 PUT 中使用 XMLHttpRequest，其他 JSON 接口继续使用 Fetch：

ts
export class UploadHttpError extends Error {
  constructor(
    public readonly status: number,
    message: string,
    public readonly retryAfterMs?: number
  ) {
    super(message)
  }
}

function parseRetryAfter(value: string | null): number | undefined {
  if (!value) return undefined

  const seconds = Number(value)
  if (Number.isFinite(seconds)) return Math.max(0, seconds * 1000)

  const time = Date.parse(value)
  return Number.isNaN(time) ? undefined : Math.max(0, time - Date.now())
}

function abortReason(signal: AbortSignal): Error {
  return signal.reason instanceof Error
    ? signal.reason
    : new DOMException('Aborted', 'AbortError')
}

export function uploadPart(
  uploadId: string,
  fileSize: number,
  part: UploadPart,
  digest: string,
  signal: AbortSignal,
  onProgress: (loaded: number) => void
): Promise<UploadedPart> {
  return new Promise((resolve, reject) => {
    if (signal.aborted) {
      reject(abortReason(signal))
      return
    }

    const xhr = new XMLHttpRequest()
    const url = `/api/uploads/${encodeURIComponent(uploadId)}`
      + `/parts/${part.partNumber}`
    const stop = () => xhr.abort()
    const cleanup = () => signal.removeEventListener('abort', stop)

    xhr.open('PUT', url)
    xhr.withCredentials = true
    xhr.setRequestHeader(
      'Content-Range',
      `bytes ${part.start}-${part.end - 1}/${fileSize}`
    )
    xhr.setRequestHeader('Content-Digest', `sha-256=:${digest}:`)
    xhr.upload.onprogress = (event) => onProgress(event.loaded)

    xhr.onload = () => {
      cleanup()

      if (xhr.status < 200 || xhr.status >= 300) {
        reject(new UploadHttpError(
          xhr.status,
          `upload part failed: ${xhr.status}`,
          parseRetryAfter(xhr.getResponseHeader('retry-after'))
        ))
        return
      }

      const etag = xhr.getResponseHeader('etag')
      if (!etag) {
        reject(new UploadHttpError(502, 'upload response has no ETag'))
        return
      }

      resolve({
        partNumber: part.partNumber,
        size: part.end - part.start,
        digest,
        etag
      })
    }

    xhr.onerror = () => {
      cleanup()
      reject(new TypeError('upload network error'))
    }
    xhr.onabort = () => {
      cleanup()
      reject(abortReason(signal))
    }

    signal.addEventListener('abort', stop, { once: true })
    xhr.send(part.blob)
  })
}

五、有限并发、重试与整体进度 ​

1. 只重试可恢复错误 ​

网络错误、408、425、429 和部分 5xx 可以有限重试；401、403、409、413 和 415 需要重新登录、修正契约或更换文件，不能自动循环：

ts
function isRetryable(error: unknown): boolean {
  if (error instanceof TypeError) return true
  if (!(error instanceof UploadHttpError)) return false
  return [408, 425, 429, 500, 502, 503, 504].includes(error.status)
}

function wait(ms: number, signal: AbortSignal): Promise<void> {
  return new Promise((resolve, reject) => {
    if (signal.aborted) {
      reject(abortReason(signal))
      return
    }

    const timer = window.setTimeout(done, ms)
    const stop = () => {
      clearTimeout(timer)
      signal.removeEventListener('abort', stop)
      reject(abortReason(signal))
    }
    function done() {
      signal.removeEventListener('abort', stop)
      resolve()
    }

    signal.addEventListener('abort', stop, { once: true })
  })
}

export async function withRetry<T>(
  operation: () => Promise<T>,
  signal: AbortSignal,
  maxAttempts = 4
): Promise<T> {
  for (let attempt = 1; attempt <= maxAttempts; attempt += 1) {
    try {
      return await operation()
    } catch (error) {
      if (signal.aborted) throw abortReason(signal)
      if (!isRetryable(error) || attempt === maxAttempts) throw error

      const retryAfter = error instanceof UploadHttpError
        ? error.retryAfterMs
        : undefined
      const backoff = Math.min(1000 * 2 ** (attempt - 1), 8000)
      await wait(retryAfter ?? backoff + Math.random() * 250, signal)
    }
  }

  throw new Error('unreachable retry state')
}

重试安全依赖协议幂等，而不是前端“禁止重复点击”。同一个 uploadId + partNumber 再次提交相同摘要必须得到同一结果；若内容不同，服务端应返回冲突，避免静默覆盖。

2. 使用有界工作池 ​

上传编排只启动固定数量的消费者，不为数百个分片同时创建读取和网络任务。三个并发不一定比两个快；带宽占满后继续增加并发，只会增加内存、重试风暴和服务端压力。移动网络和低内存设备可以由服务端下调 maxConcurrency，前端还应设置自己的硬上限。

六、恢复记录与完整上传入口 ​

恢复记录只保存不敏感的小型元数据，不保存文件内容、签名 URL 和登录凭证。案例一次只允许一个活动文件，因此使用 localStorage；多任务队列应迁移到 IndexedDB。

ts
type ResumeRecord = {
  fingerprint: string
  fileSize: number
  lastModified: number
  idempotencyKey: string
  uploadId: string | null
  expiresAt: string | null
}

const RESUME_PREFIX = 'large-upload:'

function readResumeRecord(fingerprint: string): ResumeRecord | null {
  try {
    const raw = localStorage.getItem(RESUME_PREFIX + fingerprint)
    const record = raw ? JSON.parse(raw) as Partial<ResumeRecord> : null
    return record?.fingerprint === fingerprint
      && typeof record.idempotencyKey === 'string'
      && typeof record.fileSize === 'number'
      && typeof record.lastModified === 'number'
      ? record as ResumeRecord
      : null
  } catch {
    return null
  }
}

function writeResumeRecord(record: ResumeRecord): boolean {
  try {
    const key = RESUME_PREFIX + record.fingerprint
    localStorage.setItem(key, JSON.stringify(record))
    return true
  } catch {
    return false
  }
}

function removeResumeRecord(fingerprint: string) {
  try {
    localStorage.removeItem(RESUME_PREFIX + fingerprint)
  } catch {}
}

1. JSON 接口层 ​

创建会话前先持久化幂等键。即使第一次响应丢失，重新请求也会返回同一个会话：

ts
async function requestJson<T>(
  url: string,
  init: RequestInit,
  signal: AbortSignal
): Promise<T> {
  const headers = new Headers(init.headers)
  if (init.body && !headers.has('content-type')) {
    headers.set('content-type', 'application/json')
  }

  const response = await fetch(url, {
    ...init,
    headers,
    signal,
    credentials: 'include'
  })

  if (!response.ok) {
    throw new UploadHttpError(
      response.status,
      `request failed: ${response.status}`,
      parseRetryAfter(response.headers.get('retry-after'))
    )
  }

  return response.json() as Promise<T>
}

function createUpload(
  file: File,
  idempotencyKey: string,
  signal: AbortSignal
): Promise<UploadSession> {
  return requestJson('/api/uploads', {
    method: 'POST',
    headers: { 'Idempotency-Key': idempotencyKey },
    body: JSON.stringify({
      fileName: file.name,
      fileSize: file.size,
      mediaType: file.type || 'application/octet-stream',

}

ts
async function prepareSession(
  file: File,
  fingerprint: string,
  signal: AbortSignal
): Promise<UploadSession> {
  let record = readResumeRecord(fingerprint)

  if (record
    && (record.fileSize !== file.size
      || record.lastModified !== file.lastModified)) {
    removeResumeRecord(fingerprint)
    record = null
  }

  if (record?.uploadId) {
    try {
      return await getUpload(record.uploadId, signal)
    } catch (error) {
      if (!(error instanceof UploadHttpError)
        || ![404, 410].includes(error.status)) {
        throw error
      }
      removeResumeRecord(fingerprint)
      record = null
    }
  }

  const idempotencyKey = record?.idempotencyKey ?? crypto.randomUUID()
  const pending: ResumeRecord = {
    fingerprint,
    fileSize: file.size,
    lastModified: file.lastModified,
    idempotencyKey,
    uploadId: null,
    expiresAt: null
  }
  if (!writeResumeRecord(pending)) {
    throw new Error('resume storage is unavailable')
  }

  const session = await withRetry(
    () => createUpload(file, idempotencyKey, signal),
    signal
  )
  const stored = writeResumeRecord({
    ...pending,
    uploadId: session.uploadId,
    expiresAt: session.expiresAt
  })
  if (!stored) throw new Error('cannot persist upload session')
  return session
}

export async function uploadFile(
  file: File,
  signal: AbortSignal,
  onProgress: (progress: UploadProgress) => void
): Promise<UploadResult> {
  if (file.size === 0) throw new Error('empty file is not allowed')

  const fingerprint = await createFileFingerprint(file)
  if (signal.aborted) throw abortReason(signal)
  const session = await prepareSession(file, fingerprint, signal)

  if (session.state === 'completed' && session.file) {
    removeResumeRecord(fingerprint)
    return session.file
  }
  if (session.state === 'failed' || session.state === 'canceled') {
    throw new Error(session.failureReason ?? `upload is ${session.state}`)
  }

  const maxPartSize = 64 * 1024 * 1024
  if (session.partSize <= 0 || session.partSize > maxPartSize) {
    throw new Error('server returned an unsafe part size')
  }

  const completed = new Map(
    session.uploadedParts.map((part) => [part.partNumber, part])
  )
  const active = new Map<number, number>()
  const missing = createMissingParts(
    file,
    session.partSize,
    session.uploadedParts
  )
  const controller = new AbortController()
  const stop = () => controller.abort(abortReason(signal))

  if (signal.aborted) stop()
  signal.addEventListener('abort', stop, { once: true })

  function emitProgress() {
    const confirmedBytes = [...completed.values()]
      .reduce((total, part) => total + part.size, 0)
    const activeBytes = [...active.values()]
      .reduce((total, loaded) => total + loaded, 0)
    onProgress({ confirmedBytes, activeBytes, totalBytes: file.size })
  }

  try {
    emitProgress()
    if (!Number.isInteger(session.maxConcurrency)
      || session.maxConcurrency < 1) {
      throw new Error('server returned an invalid concurrency')
    }
    const concurrency = Math.min(session.maxConcurrency, 3)

    let cursor = 0
    async function uploadNext() {
      while (cursor < missing.length) {
        const part = missing[cursor]
        cursor += 1
        const digest = await sha256Base64(part.blob)
        if (controller.signal.aborted) throw abortReason(controller.signal)

        const result = await withRetry(async () => {
          active.set(part.partNumber, 0)
          emitProgress()
          try {
            return await uploadPart(
              session.uploadId,
              file.size,
              part,
              digest,
              controller.signal,
              (loaded) => {
                active.set(part.partNumber, loaded)
                emitProgress()
              }
            )
          } catch (error) {
            active.delete(part.partNumber)
            emitProgress()
            throw error
          }
        }, controller.signal)

        active.delete(part.partNumber)
        completed.set(part.partNumber, result)
        emitProgress()
      }
    }

    const workers = Array.from(
      { length: Math.min(concurrency, missing.length) },
      uploadNext
    )
    await Promise.all(workers)
  } catch (error) {
    controller.abort(error)
    throw error
  } finally {
    signal.removeEventListener('abort', stop)
  }

  const parts = [...completed.values()]
    .sort((left, right) => left.partNumber - right.partNumber)
  let finalSession = await withRetry(
    () => completeUpload(session.uploadId, parts, signal),
    signal
  )

  while (finalSession.state === 'completing') {
    await wait(2000, signal)
    finalSession = await withRetry(
      () => getUpload(session.uploadId, signal),
      signal
    )
  }

  if (finalSession.state !== 'completed' || !finalSession.file) {
    throw new Error(
      finalSession.failureReason ?? `upload is ${finalSession.state}`
    )
  }

  removeResumeRecord(fingerprint)
  return finalSession.file
}

一次尝试失败时，activeBytes 会回退，再从零计算该分片；这比制造一个永不回退的虚假进度更准确。界面可以同时展示“已确认 62%”和“当前请求 8 MiB / 16 MiB”，不要把两者加总后直接称为服务端完成比例。

工作池中一个分片最终失败时，内部 Controller 会停止其他活动请求。下一次调用 uploadFile() 会重新查询服务端，已成功但前端来不及记录的分片也不会重复计入。

案例把恢复能力作为验收条件，因此 writeResumeRecord() 失败会停止启动。若某个产品允许降级为单页面上传，也必须明确提示“刷新后无法恢复”，不能静默降低承诺。

const input = document.querySelector<HTMLInputElement>('#file')!
const progress = document.querySelector<HTMLProgressElement>('#progress')!
const pauseButton = document.querySelector<HTMLButtonElement>('#pause')!
const resumeButton = document.querySelector<HTMLButtonElement>('#resume')!
const status = document.querySelector<HTMLOutputElement>('#status')!

let selectedFile: File | null = null
let controller: AbortController | null = null

async function start() {
  if (!selectedFile) return

  controller = new AbortController()
  pauseButton.disabled = false
  resumeButton.disabled = true
  status.value = '正在上传'

  try {
    const result = await uploadFile(
      selectedFile,
      controller.signal,
      ({ confirmedBytes, totalBytes }) => {
        progress.value = confirmedBytes / totalBytes
        status.value = confirmedBytes === totalBytes
          ? '分片已确认，正在校验'
          : '正在上传'
      }
    )
    status.value = `上传完成，文件版本 ${result.version}`
  } catch (error) {
    const paused = error instanceof DOMException && error.name === 'AbortError'
    const unauthenticated = error instanceof UploadHttpError
      && error.status === 401
    const recoverable = paused || isRetryable(error)
    if (paused) status.value = '已暂停，可继续上传'
    else if (unauthenticated) status.value = '登录已失效，请重新登录后继续'
    else if (recoverable) status.value = '暂时失败，可以继续上传'
    else status.value = '文件或会话不可恢复，请按错误提示处理'
    resumeButton.disabled = !recoverable
  } finally {
    pauseButton.disabled = true
  }
}

刷新页面后 selectedFile 会丢失，这是浏览器安全边界。用户重新选择同一文件后，指纹定位本地记录，服务端状态决定从哪些分片继续。File System Access API 可以在受控环境中保存文件句柄，但仍需重新确认权限，不能作为跨浏览器基线。

七、暂停、取消与后台边界 ​

动作前端行为服务端行为
暂停Abort 活动请求，保留恢复记录保留已确认分片直到会话过期
继续重新查询会话，只上传缺失分片返回已确认清单
取消Abort 后调用 DELETE，删除本地记录标记会话取消并异步清理临时分片
页面崩溃或关闭无法保证发送清理请求依靠会话过期清理
完成结果未知使用同一清单重试完成请求或查询状态幂等返回同一文件版本

不要依赖 beforeunload 完成取消或保存，它可能不触发，也不能可靠等待异步请求。Service Worker 可能被浏览器终止，Background Sync 也不是多 GiB 文件持续上传的通用保障。Web 页应承诺“重新打开后可恢复”，而不是“关闭页面后一定继续上传”。

多标签页同时操作同一会话时，服务端幂等仍是最后防线；选主和页面间协调属于多标签页通信与状态同步，本文不提前展开。

八、大文件下载与 Range 恢复 ​

1. 优先交给浏览器下载管理器 ​

普通大文件下载不应先 fetch() 再 blob()。接口重新检查权限后返回短时 URL、过期时间、文件版本、大小和 ETag，页面把 URL 渲染为普通链接，由服务端响应决定文件名和下载行为。

下载响应至少明确：

http
Content-Disposition: attachment; filename*=UTF-8''training-video.mp4
Content-Length: 5368709120
Accept-Ranges: bytes
ETag: "file-version-42"
1
2
3
4

浏览器可以直接把响应流交给下载管理器，避免页面持有完整 Blob。跨域链接上的 download 属性不一定生效，可靠文件名应由 Content-Disposition 提供。

2. Range 必须绑定同一文件版本 ​

恢复到 100 MiB 后，客户端或下载管理器可以发送：

http
Range: bytes=104857600-
If-Range: "file-version-42"
1
2

资源仍是同一版本时，服务端返回：

http
HTTP/1.1 206 Partial Content
Content-Range: bytes 104857600-5368709119/5368709120
ETag: "file-version-42"
1
2
3

如果版本已变化，服务端应忽略 Range 并返回新的完整 200 响应，不能把两个版本拼在一起；范围超出文件长度则返回 416。短时 URL 过期后，需要为同一不可变文件版本重新获取下载凭证，再按服务能力决定恢复还是重新下载。

浏览器下载管理器是否自动跨过期 URL 恢复，需要在目标浏览器和 CDN 上实际验证。只有客户端解密、逐块校验或写入指定文件等明确需求，才考虑 Fetch Stream 配合 File System Access API 的自定义下载器；它的兼容性、权限和恢复状态成本明显更高。

九、安全、资源与生命周期 ​

前端限制只能改善体验，文件安全必须由服务端执行：

风险必须执行的边界
伪造文件名和 MIME文件名只作元数据，服务端检查大小、魔数和允许类型
用他人的 uploadId 上传或完成每个分片、查询、完成和取消请求都重新授权
分片覆盖或乱序校验编号、范围、摘要和文件总大小
上传恶意内容完成后进入隔离和扫描，通过前不可预览或下载
签名地址泄露最小权限、短时有效，不写入长期存储和日志
跨用户秒传泄露文件存在去重不能根据客户端指纹直接暴露命中结果
Cookie 请求被伪造使用项目统一的 SameSite 与 CSRF 防护
临时分片无限增长服务端按会话过期清理，并监控未完成体积

客户端提供的 SHA-256 只能发现传输错误，恶意客户端可以同时伪造内容和摘要。服务端必须独立验证最终对象，并以自己的扫描与授权结果决定文件是否可用。

文件选择后不要把 Blob、ArrayBuffer 和分片数组长期挂在全局状态中。上传完成、取消或切换文件时释放引用；预览产生的对象 URL 由文件预览、导出与打印专题负责，并应及时 URL.revokeObjectURL()。

十、测试、故障实验与监控 ​

1. 先测试分片边界 ​

使用 createMissingParts() 验证以下已填写用例：

文件大小分片大小已确认编号期望缺失范围 [编号, start, end)
10 B4 B[][1,0,4] [2,4,8] [3,8,10]
10 B4 B[2][1,0,4] [3,8,10]

0 B4 B[]入口直接拒绝空文件

还要覆盖服务端返回非法分片大小和已确认清单越界。客户端测试通过后，接口契约测试必须验证重复 PUT、摘要冲突和重复 complete。

2. 注入真实失败 ​

故障预期结果
某分片上传一半断网只重试该分片，确认进度允许回退
返回 429 和 Retry-After等待指定时间，不形成并发重试风暴
返回 401 或 403停止全部请求，不自动重放
同一编号提交不同摘要服务端返回 409，前端进入不可自动恢复错误
初始化响应丢失相同幂等键恢复同一会话
刷新后重新选择同名不同文件指纹不匹配，不复用旧会话
会话已过期删除本地记录并建立新会话
complete 响应丢失重试或查询后得到同一文件版本
下载中权限被撤销新下载凭证被拒绝，旧入口按服务端策略失效
Range 对应的 ETag 已变化返回完整新版本，不拼接旧字节

性能验证使用代表性文件和设备记录：摘要耗时、主线程长任务、峰值堆内存、并发数、平均吞吐、分片重试率和完整上传耗时。只用 1 MiB 测试文件无法暴露长会话中的内存和恢复问题，也不需要在普通 CI 中真的保存 10 GiB 文件；容量环境可以使用可控的大文件和故障代理单独验证。

3. 线上指标 ​

指标作用
初始化成功率与耗时发现鉴权、限流和文件规则问题
分片确认吞吐与重试率区分网络波动和服务端异常
暂停后恢复成功率验证恢复协议是否真正可用
摘要冲突和完成失败率发现边界、覆盖和存储问题
会话过期与取消比例调整有效期和交互提示
峰值内存与长任务验证分片和并发预算
下载凭证失败与 206 比例发现权限、过期和 Range 行为

日志使用 uploadId、文件版本和分片编号关联阶段，但不记录原始文件名、签名 URL、用户本地路径和文件内容摘要全集。

十一、方案选择 ​

场景优先方案
小文件且请求限制充足单次 FormData 或 PUT，不引入分片
数百 MiB 到数 GiB、需要暂停恢复有限并发分片 + 幂等会话 + 服务端状态恢复
大流量且应用服务带宽昂贵服务端授权后直传存储服务
新系统且续传需求标准评估 tus，减少私有协议
浏览器端生成大导出文件小数据才本地生成；大数据改用服务端异步任务
普通大文件下载短时链接 + 浏览器下载管理器
客户端解密或逐块验证下载评估 Stream + File System Access 的受控方案

以下情况需要重新评审分片大小、并发或协议：

  • P95 分片重试成本过高，或大量请求卡在网关超时附近。
  • 移动设备峰值内存超过预算，摘要产生明显长任务。
  • 未完成分片占用持续增长，当前过期策略无法回收。
  • 自定义协议开始复制标准续传协议已经解决的能力。
  • 下载凭证频繁过期，用户无法可靠恢复同一文件版本。

总结 ​

大文件传输的核心不是把文件切成数组，而是让每一步都有稳定身份、幂等结果和可恢复边界：

text
小文件保持单请求
  -> 大文件建立有期限的会话
  -> 文件指纹只定位候选会话
  -> 分片摘要和服务端状态确认真实进度
  -> 有限并发控制内存与带宽
  -> 只重试幂等且可恢复的错误
  -> 暂停保留、取消清理、关闭后允许恢复
  -> 下载绑定不可变版本和 Range 条件
  -> 用故障实验验证，而不是只看进度条

常见误区正确处理
所有文件都分片先比较文件规模、超时和失败成本
上传进度 100% 就算完成等待分片确认、最终校验和文件提交
指纹相同就直接秒传指纹只做本地匹配，服务端独立授权与校验
并发越高越快根据带宽、内存和失败率设置上限
网络错误统一无限重试仅重试幂等的暂时故障，并遵守退避和限流
页面关闭后继续上传承诺重新打开可恢复，不依赖后台长期存活
